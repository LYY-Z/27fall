# VR 相对位姿与坐标标定

## 0. 先看清这一步在做什么

人的手握着 VR 手柄，机器人有自己的手腕 TCP。程序先读取手柄位置和朝向，生成“希望机器人手腕去哪里、朝哪里”的目标；后面的 IK 和执行器才负责动作。手和手腕的绝对位置、初始朝向都不需要相同。相对控制让机器人从自己的起点跟随手柄变化，也允许位置缩放，所以不能称为两个物体在房间中绝对同步。

本章先学坐标和相对目标，再把目标装成 SE(3)，最后对照源码。数值均为教学设定；源码事实见[文件地图](../02_源码阅读与运行/01_源码版本与文件地图.md)，运行与性能证据另查记录。先修见[坐标基础](../../../01_通用基础/03_坐标_运动学与动力学/01_坐标点向量与主动被动变换.md)。

## 1. 四个坐标系与唯一的矩阵记号

坐标系是一组固定在某个参照物上的三根方向轴和一个原点。

| 坐标系 | 固定在哪里 | 本章主要用来描述什么 |
|---|---|---|
| W | VR 房间/追踪空间 | 手柄的位置、朝向和位移 |
| H | 手柄本体 | 手柄自身的 x、y、z 方向 |
| B | 机械臂基座 | 手腕位置、朝向、目标和误差 |
| E | 手腕/TCP | 工具自身的 x、y、z 方向 |

统一定义 \(R_{AB}\)：**把按 B 轴描述的方向向量换成按 A 轴描述**，即
\[
v^A=R_{AB}v^B.
\]
读 \(R_{WH}\) 就是“手柄 H 的轴相对房间 W 的朝向”；同一矩阵也能把手柄轴下的方向转换到房间轴下。旧资料的 \(R_{A\leftarrow B}\) 与 \(R_{AB}\) 等价，本项目教学正文统一使用后者。

\(p_H^W\) 表示手柄原点在房间中的位置，不是手柄局部坐标。\(p_E^B\) 表示 TCP 原点在基座中的位置。它们的数字可能都长得像三维数组，但必须连着物体和参考系一起读。

### 1.1 为什么旋转矩阵的三列就是三根轴

把 B 的单位 x 向量 \([1,0,0]^T\) 左乘 \(R_{AB}\)，结果正好取出第一列。所以第一列是 B 的 +x 在 A 里怎么写；第二、三列同理。合法旋转矩阵满足
\[
R^TR=I,\qquad\det R=+1,\qquad R^{-1}=R^T.
\]
列的长度为 1、相互垂直，且保持右手方向。长度改变会引入缩放；不垂直会引入剪切；行列式 -1 会引入反射。

### 1.2 一组始终不换假设的 90° 例子

本章后续都假设轴对齐关系为
\[
C=R_{BW}=R_z(90^\circ)=
\begin{bmatrix}0&-1&0\\1&0&0\\0&0&1\end{bmatrix}.
\]
三列依次说明：W 的 +x 在 B 里是 +y，W 的 +y 在 B 里是 -x，W 的 +z 在 B 里仍是 +z。因此
\[
C[0.10,0,0]^T=[0,0.10,0]^T\ {\rm m}.
\]
这里改写的是同一段位移的坐标数字，物体没有因为做矩阵乘法而真的转动。

这个 C 是**教学假设**。真实 C 要来自明确的轴约定、安装关系或标定。已知三个 W 轴在 B 中的方向，就按列放入；只有两根可靠的不共线方向时，可先正交化，再用叉乘确定右手第三轴。带噪声的多组方向对应可用旋转拟合，并检查正交性、行列式和剩余误差。单条方向只能约束部分旋转，不能唯一确定三维 C。

纯软件重定义轴与测得两个物理坐标系的旋转也要区分。若 W 的物理追踪方向会随重定位改变，固定转换矩阵仍然存在，也不证明房间到基座的物理标定仍有效。原点偏移对绝对点转换重要，但相对位移中会抵消。

## 2. 初始化与激活：分别记录两个锚点

程序初始化可以加载模型、设置关节初值、准备通信和滤波；**一次相对操作的参考应在实际使能时捕获**，不能把程序启动时间和按下开始时间默认当成同一时刻。

按下 grip/控制键时，保存
\[
(p_{H0}^W,R_{WH0}),\qquad(p_{E0}^B,R_{BE0}).
\]
前一对是手柄起点，后一对是机器人当前 TCP 起点。E0 的轴相对 B 完全可以是倾斜的；“有 TCP 坐标系”不表示 \(R_{BE0}=I\)。

刚按下时，手柄位置差为零、旋转差为单位阵，所以 TCP 目标等于它自己的当时位姿。这使目标连续，但不单凭公式保证通信或执行器没有瞬变。松开后清参考，再按下重新捕获，允许人把手收回来而从机器人新的起点继续操作。

### 2.1 相对位置只做同参考系下的相减

\[
\Delta p_W=p_H^W-p_{H0}^W,\qquad
p_d^B=p_{E0}^B+sC\Delta p_W.
\]
相减发生在 W；C 改写位移方向；s 缩放距离；最后加到 B 中的机器人起点。不要直接把手柄房间坐标加到机器人基座坐标。

沿用第 1.2 节的 C：手柄从 \([0.4,0.2,1.0]^T\) m 到 \([0.5,0.2,1.0]^T\) m，机器人起点为 \([0.3,0,0.4]^T\) m，s=0.5：
\[
\Delta p_W=[0.1,0,0]^T,\quad
sC\Delta p_W=[0,0.05,0]^T,\quad
p_d^B=[0.3,0.05,0.4]^T\ {\rm m}.
\]
机器人目标移动 5 cm。两端的原点可以相距很远，不妨碍计算。

## 3. 朝向跟随：先声明增量在哪组轴下

### 3.1 世界增量左乘，局部增量右乘

手柄当前朝向与参考朝向都写在 W：
\[
\Delta R_W=R_{WH}R_{WH0}^T,\qquad
R_{WH}=\Delta R_W R_{WH0}.
\]
它是按固定世界轴描述的转动。换成基座轴下的同一转动，再施加到机器人起点：
\[
\Delta R_B=C\Delta R_WC^T,\qquad
R_d=\Delta R_B R_{BE0}.
\]
从右到左理解共轭：先把 B 的向量换回 W，在 W 中转，再换回 B。因此它改变旋转轴的表达，角度保持不变。

另一个同样正确的定义是手柄起点局部轴增量：
\[
\Delta R_{H0}=R_{WH0}^TR_{WH},\qquad
R_{WH}=R_{WH0}\Delta R_{H0}.
\]
若设计要求将局部手柄动作对应到 TCP 起点局部轴，需要另声明 \(C_{E0H0}\)，再用
\[
R_d=R_{BE0}(C_{E0H0}\Delta R_{H0}C_{E0H0}^T).
\]
这个局部映射不是本章的世界轴 C。两种控制设计的基准不同，不能拿世界增量直接右乘，也不能仅凭名字把两种 C 当成同一矩阵。

### 3.2 非同向初始腕：左右乘真的不同

设 \(R_{BE0}=R_x(90^\circ)\)，手柄多绕世界 z 转 90°。本章 C 也绕 z，因此 \(\Delta R_B=R_z(90^\circ)\)。世界增量目标为
\[
R_z(90^\circ)R_x(90^\circ)=
\begin{bmatrix}0&0&1\\1&0&0\\0&1&0\end{bmatrix}.
\]
若误改成右乘，则
\[
R_x(90^\circ)R_z(90^\circ)=
\begin{bmatrix}0&-1&0\\0&0&-1\\1&0&0\end{bmatrix}.
\]
第一列分别是 \([0,1,0]^T\) 和 \([0,0,1]^T\)，手腕自己的 x 轴最终朝向都不同。右乘描述绕起始 TCP 自身轴转，左乘描述绕固定 B 轴转。

只绕同一 z 轴的 30°→50° 例子可得到 20° 差，但容易掩盖旋转不能交换的事实。三维姿态不能普遍逐项相减欧拉角。

### 3.3 四元数、欧拉角和轴角各在记什么

矩阵、单位四元数、欧拉角都是朝向的编码。每次都要说明“谁相对谁”，并注明主动/被动、列/行向量和乘法约定。本文用列向量；绕固定 z 的主动旋转为 \(R_z(\theta)\)。

- 单位四元数有 4 个数字，却只有 3 个旋转自由度。wxyz 与 xyzw 是存储顺序，不是两种姿态；转换时重排。q 与 -q 表示同一旋转。
- 若使用欧拉角，必须声明顺序及内禀/外禀。例如本文可约定 \(R=R_z(yaw)R_y(pitch)R_x(roll)\)，在列向量下先作用右侧的 x 旋转。其他库的字符串约定要另查。
- 轴角向量 \(\phi=\theta n\) 有 3 维：长度为弧度角，方向为单位轴。它不是 roll、pitch、yaw 三个独立角。

位置缩放 s 只乘位移。将 s 乘到 R 会破坏旋转矩阵，将 s 任意乘到姿态角也会改变原本的跟随设计。

## 4. SE(3)：把位置和朝向装进一张 4×4 表

\[
T_{AB}=
\begin{bmatrix}R_{AB}&p_B^A\\0&1\end{bmatrix}.
\]
左上 3×3 是旋转，右上 3×1 是 B 原点在 A 的位置，最后一行是 \([0,0,0,1]\)。这个矩阵把 B 中的点变成 A 中的点：
\[
T_{AB}\begin{bmatrix}x^B\\1\end{bmatrix}
=\begin{bmatrix}R_{AB}x^B+p_B^A\\1\end{bmatrix}.
\]
点的 w=1，让平移生效；方向的 w=0，只受旋转：
\[
T_{AB}\begin{bmatrix}v^B\\0\end{bmatrix}
=\begin{bmatrix}R_{AB}v^B\\0\end{bmatrix}.
\]
w 是齐次分量，不是第四个空间方向。

### 4.1 最后一行必要，但不能单独保证刚体变换

SE(3) 必须同时满足 \(R^TR=I,\det R=1\) 和最后一行固定。任意 4×4 矩阵不都是 SE(3)。例如 \(\operatorname{diag}(2,1,1,1)\) 最后一行也正确，但它把 x 放大两倍；带非正交左上块的矩阵也可能剪切。因此“最后一行保证没有缩放剪切”是错误解释。

若截图式公式写成 \([R,p]\) 两个块，只是略写；完整尺寸是上半 3×4、下半 1×4。不能把右上平移写成最后一行，不能把 \(p\) 当成角度，不能因 4×4 外形正确就认定合法。

### 4.2 组合与逆：中间坐标系必须接得上

\[
T_{AC}=T_{AB}T_{BC}
=\begin{bmatrix}
R_{AB}R_{BC}&R_{AB}p_C^B+p_B^A\\0&1
\end{bmatrix},
\quad
T_{AB}^{-1}=
\begin{bmatrix}R_{AB}^T&-R_{AB}^Tp_B^A\\0&1\end{bmatrix}.
\]
逆变换的平移不是简单 -p，还要换轴。无匹配中间坐标系的两个绝对位姿不能凭尺寸相同直接相乘并声称是遥操目标。

例如 \(T_{AB}=[R_z(90^\circ),(1,0,0)^T]\)，\(T_{BC}=[I,(0.2,0,0)^T]\)，则 C 原点在 A 为 \((1,0.2,0)^T\)，因为第二段位移先经过 R 转轴，再加第一段平移。

### 4.3 同一组数字：手柄起点、当前、腕起点、腕目标

继续使用 C=\(R_z(90^\circ)\)、s=0.5。手柄起点朝向为 I，当前绕 W 的 z 转 90°；腕起点朝向为 \(R_x(90^\circ)\)：
\[
T_{WH0}=
\begin{bmatrix}1&0&0&0.4\\0&1&0&0.2\\0&0&1&1.0\\0&0&0&1\end{bmatrix},
\quad
T_{WH}=
\begin{bmatrix}0&-1&0&0.5\\1&0&0&0.2\\0&0&1&1.0\\0&0&0&1\end{bmatrix}.
\]
\[
T_{BE0}=
\begin{bmatrix}1&0&0&0.3\\0&0&-1&0\\0&1&0&0.4\\0&0&0&1\end{bmatrix}.
\]
第 2.1 节得到 \(p_d^B=[0.3,0.05,0.4]^T\)。第 3.2 节得到 \(R_d=R_z(90^\circ)R_x(90^\circ)\)，所以
\[
T_{BE_d}=
\begin{bmatrix}0&0&1&0.3\\1&0&0&0.05\\0&1&0&0.4\\0&0&0&1\end{bmatrix}.
\]
读第一列：目标 E 的 x 轴在 B 中朝 +y；读右上：目标原点在 B 中是 \((0.3,0.05,0.4)\) m。位置和朝向被放在一张表里，没有相加。

还要区别“手柄原点位移”与“整个刚体变换的平移块”：
\[
T_{WH}T_{WH0}^{-1}
=\begin{bmatrix}\Delta R_W&p_H^W-\Delta R_Wp_{H0}^W\\0&1\end{bmatrix}.
\]
本例右上是 \([0.7,-0.2,0]^T\)，并非 \([0.1,0,0]^T\)。它是把整个位姿从起点变到当前的世界刚体变换，绕世界原点旋转会移动起点。当前遥操设计分别使用“手柄原点的位置差”和“朝向差”，不能拿完整 SE(3) 乘积的平移块替代位置差。

## 5. 源码如何实现这些步骤

当前可读 Python 主脚本和 geometry.py 的事实如下，其他版本须分别追踪：

1. 初始化模型和关节初值；主类 RateLimiter 配置为 200 Hz。这不是激活参考，也不是实测周期。
2. 读取 XR 位置 xyz，输入四元数 xyzw 重排成 wxyz。
3. 位置乘固定 R_HEADSET_TO_WORLD，四元数用对应共轭改轴。源码矩阵为
\[
R_{WV}=\begin{bmatrix}0&0&-1\\-1&0&0\\0&1&0\end{bmatrix}.
\]
此处 V 专指 provider 的原始追踪轴，W 是源码转换后的轴。矩阵列读出 +xV→-yW、+yV→+zW、+zV→-xW。它与教学 90° 的 C 不是同一矩阵，源码也没有单独的世界标定 C 变量。转换后轴是否和 MuJoCo 世界 M、基座 B 一致，必须查场景安装和 provider 约定。
4. 转换后做位置与四元数指数融合。类默认 filter_alpha=0.3，主入口显式传 0.5；主入口 scale_factor=1。
5. control_trigger>0.9 首次激活时记录当前 TCP 参考；处理手柄时保存其已转换、已滤波参考，并先返回零增量。
6. 后续位置差乘 scale_factor；quat_diff_as_angle_axis 计算 \(\Delta\eta=\eta_{now}\eta_{ref}^{-1}\) 并转成轴角。这里 \(\eta\) 专指姿态四元数，避免与关节 q 混淆。
7. position 模式保持 TCP 参考朝向；pose 模式 apply_delta_pose 把旋转增量左乘 TCP 参考四元数。松开清参考，下次重建；滤波历史是另一份状态，不等于同时清空。
8. 得到目标后进入[MuJoCo/Mink 与求解](02_MuJoCoMink任务约束与求解.md)。

源码角轴转换中有对 w<0 的四元数改符号处理；**这不能替代滤波前相邻四元数的半球对齐**。当前融合段未显式做该对齐，q/-q 可能相消；归一化也不能把零向量救成合法姿态。SLERP、半球修正是可讨论的改进，不能说当前活动代码已使用。

## 6. 从生成目标转到机器人跟踪

手柄相对起点转了多少用于设目标；当前机器人离目标还差多少用于纠错。以 B 中当前 R 与目标 \(R_d\) 为例：
\[
e_p=p_d^B-p_E^B,\qquad
e_R=\operatorname{Log}(R_dR^T)^\vee.
\]
Log 是旋转群对数，vee 将反对称矩阵转成三维轴角向量；不是逐格普通对数。向量方向是补转轴，长度是补转弧度。若改用 \(R^TR_d\)，得到局部轴表达，后续角速度雅可比也要跟着换轴。

六维任务和误差到速度的单位推导见下一章。目标得到后仍可能不可达、受限或跟踪滞后；不应将目标矩阵当成编码器反馈。

## 7. 复习与排查

| 现象或疑问 | 先核对 |
|---|---|
| 一按键目标跳变 | 两个参考捕获时刻、参考/当前是否同样滤波、旧参考是否清除 |
| 向前变成向左 | provider 原始轴、转换矩阵列、M/B 安装、是否误用转置 |
| 手柄不转但 TCP 初始倾斜 | R_BE0 是真实起始朝向，不能强置 I |
| 一次旋转方向错误 | 世界/局部增量定义、左右乘、四元数顺序 |
| 位姿看似合法但拉伸 | R 正交性和 det；最后一行不足以保证 SE(3) |
| 两端动作滞后 | XR 样本年龄、滤波、IK 周期、执行器反馈 |

纸笔验收：重算第 4.3 节四个位姿，再把手柄当前朝向改为起点、位置保持移动，确认位置目标变而朝向保持 \(R_{BE0}\)。口述时说清“输入样本→激活锚点→相对变化→换轴→目标”，再追[完整周期](../02_源码阅读与运行/02_一个周期的调用与数据流.md)。个人贡献只按[材料证据](../04_贡献_证据与材料映射/01_CV_PS表述与证据.md)说明。

English reference: “I capture controller and end-effector references when control is enabled. I map relative displacement into the robot base frame and apply a frame-consistent rotation increment to the initial wrist orientation. The resulting pose is a target; IK and actuator feedback determine the actual motion.”
