# P6 逐步实验手册

## 1. 做实验前先知道它证明什么

这些普通电脑实验都使用本地合成数据和假设备，不连接真实 OpenHarmony 服务、M-DDS/M-Robots 或硬件。它们适合练习“输入怎样经过检查，状态为什么接受/拒绝”，不能作为历史项目性能或实际设备动作的证据。

本轮只审阅实验文档与源码，没有运行脚本、编译 C++ 或写入实验输出。下文数字结果是按代码逐步手算的预期。真正执行后，要另存实际日志并比较差异。

完整命令与依赖说明在 [P6 普通电脑教学实验](../../../03_代码实验/02_项目实验/P6/README.md)；逐个函数的说明在 [逐函数阅读指南](../../../03_代码实验/02_项目实验/P6/逐函数阅读指南.md)。

## 3. 实验一：设备能力、反馈和动作校验

代码使用字典保存一个合成设备 robot。注册序号为 1，能力为 move/stop，注册后 online=false。新鲜反馈序号 2、采样时间 9.5 s、当前时间 10.0 s，TTL 是 1.0 s：

- 反馈年龄 = 10.0 − 9.5 = 0.5 s，所以状态同步成功。
- 动作 a1 的创建时间 9.8 s，当前时间 10.0 s，动作年龄 = 0.2 s，小于 max_age=0.5 s。
- move 能力存在、反馈新鲜、value=0.5 在教学允许范围 [-1,1] 内，因此第一次返回 executed（模拟效果）。
- 同一个 a1 再请求，返回 duplicate，不再次记一次模拟效果。
- 新 ID a2 请求不存在的 fly 能力，返回 unsupported capability。
- 新 ID a3 的 issued_at=8.0 s，当前年龄 2.0 s，超过 0.5 s，返回过期。
- 新 ID a4 的 value=2.0 超出教学范围，返回范围拒绝。

注意检查顺序：程序先查动作 ID 是否已经执行，再查能力、反馈年龄、请求年龄和值域。因此同 ID 重放可能先返回 duplicate；不同失败原因要看 reason 字段。

**练习：**将反馈采样时间改为 8.9 s、now 仍为 10 s，算出年龄 1.1 s；解释动作为何不应使用这份缓存。再把 now 改为 9.9 s，重新判断 1.0 s 的 TTL 边界。

## 4. 实验二：旧反馈、过期缓存和恢复

脚本按顺序回放四个反馈事件。每个时间单位是秒，反馈 TTL 为 1 s：

| 输入序号 | sample time | now | 年龄/顺序检查 | 反馈处理 | 随后动作 |
|---:|---:|---:|---|---|---|
| 2 | 0.1 | 0.1 | 比注册序号 1 新，年龄 0 | 同步成功 | 使用刚同步的新状态，动作可接受 |
| 1 | 0.2 | 0.2 | 序号不大于已保存的 2 | 旧帧拒绝，不覆盖状态 | 上一份状态 sample=0.1，此刻年龄 0.1 s，仍新鲜，因此该动作仍可接受 |
| 3 | 0.2 | 2.0 | 序号更新，但年龄 1.8 s | 过期反馈拒绝 | 旧缓存年龄 1.9 s，也过期，动作拒绝 |
| 4 | 2.0 | 2.0 | 序号更新，年龄 0 | 同步成功 | 恢复后的新状态可供动作校验 |

这个例子刻意把两个概念分开：序号用于发现乱序/重复，采样时间用于判断信息年龄。旧帧被拒绝，不代表上一次缓存立刻失效；只要上一次缓存还在 TTL 内，它仍可能用于短暂决策。缓存年龄超过 TTL 后，才应拒绝依赖它的新动作。

此脚本模拟的是单进程、单次启动。设备重启后序号归零、时钟未同步、跨进程持久化和真实重连没有模拟。

## 5. 实验三：C++ 接口、所有权和异步任务

device_adapter.cpp 中：

1. DeviceAdapter 是统一接口，MockAdapter 修改内存状态，不访问设备。
2. unique_ptr 独占适配器；基类析构是 virtual，允许通过基类指针正确销毁派生对象。
3. SharedDevice 用 mutex 将一次 execute 与读取反馈保护在同一个临界区，避免命令与反馈快照交错。
4. dispatchOwned 把 shared_ptr<Device> 和 Command 值捕获进异步任务，任务持有它们的寿命，不借用调用者栈上的引用。
5. future.get 等异步任务完成并拿回 Execution；它不是超时，也不取消任务。

按代码顺序手算：

- a1(value=0.5)：accepted=true，状态序号从 0 到 1。
- 再提交相同 a1：accepted=false，序号仍为 1。
- a2(value=2.0)：超过 [-1,1]，accepted=false，序号仍为 1。
- 异步 a3(value=0.25)：future.get 等待它完成；成功后序号变 2。
- 最后 stop 把 Mock 值清为 0，序号变 3。

MockAdapter 只有 bool 返回值，失败原因比 Python 实验少。stop 只改变内存值，不证明电机真实停下；async 任务完成也不提供 deadline、取消或跨进程去重。

## 6. 怎样做对照和故障注入

每次只改变一个条件，并在记录中写明你预计改变哪个检查：

| 改动 | 预期观察 |
|---|---|
| 重复同一个 action_id | duplicate/accepted=false，不重复模拟效果 |
| 换一个未知 capability | 因能力不支持拒绝 |
| 把请求时间改早，使 age 超过 max_age | 因请求过期拒绝 |
| 把 value 改到区间外，或改成 NaN/无穷 | 数值检查或值域检查拒绝 |
| 把反馈序号倒退 | 旧序号拒绝，原缓存不应被覆盖 |
| 保持序号更新但 sample time 太旧 | 反馈仍因年龄过期而拒绝 |
| 让调用方局部变量被异步引用捕获并提前销毁 | 这是反例讨论；不要把教学代码改成存在悬空引用的运行程序 |

## 7. 记录表应写什么

每轮至少保留：

- 代码版本或 SHA、Python/g++ 版本、完整命令；
- device_id、action_id、capability、value 和单位；
- sequence、sample time、当前时间、反馈年龄；
- status/reason 或 accepted、状态序号和最终缓存值；
- 预期和实际是否一致；若不一致，指出具体函数/分支。

若真实设备测试另行获准并具备安全条件，还要分开记录协议写成功、设备 ACK、传感器读回和物理到位。不要用教学 CSV 填写实机成绩。
