# P1 四状态 LQR 仿真实验：从模型到曲线

本手册带你亲手完成一个离线 LQR 仿真：准备 Python 环境，建立 P1 项目使用的前后方向四状态模型，计算 LQR 增益，在电脑中让虚拟机器人运动，调整 \(Q/R_u\)，再查看位置、速度、倾角、力矩和饱和情况。

配套程序：[lqr_four_state_sim.py](../../../03_代码实验/02_项目实验/P1/lqr_four_state_sim.py)。依赖列表：[requirements-lqr.txt](../../../03_代码实验/02_项目实验/P1/requirements-lqr.txt)。先修原理：[四状态倒立摆与 LQR 分析](../01_原理与子系统/04_四状态倒立摆与LQR分析.md)。

> **先划清实验边界：**这是电脑中的单平面、直立附近的小角度模型。它没有连接 ROS、CAN、电机或机器人，也不是球形底盘的完整三维仿真。它的输入是模型定义的等效力矩 \(\tau\)，不是实机驱动消息里的轮子速度。程序读取的质量和惯量数值是当前源码配置的快照，未经独立称量或实验辨识；仿真曲线不能直接当作实机性能证据。

## 1. 做完后应该能回答什么？

做完基础实验后，你应该能用自己的话解释：

1. 状态 \(x,\dot x,\theta,\dot\theta\) 分别代表什么，单位是什么；
2. 质量、半径、质心高度和转动惯量怎样进入 \(A,B\)；
3. \(Q\) 如何表达“哪些状态偏差更不想看到”，\(R_u\) 如何表达“多大控制输入算贵”；
4. 软件怎样由 \(A,B,Q,R_u\) 求出 \(P,K\)，再用 \(u=-Ke\) 算力矩；
5. 力矩限幅、采样周期、传感器噪声和测量延迟如何改变结果；
6. 为什么“某个 \(Q/R_u\) 的模拟表现不错”不等于它已经适合实机。

## 2. 整体实验会做什么？

把电脑里的虚拟机器人想成每隔一小段时间重复做下面的事情：

~~~text
读取虚拟传感器状态
        ↓
和目标比较，得到误差 e
        ↓
LQR 计算一个等效控制力矩 τ = -K e
        ↓
按力矩上限裁剪命令（如果启用限幅）
        ↓
根据倒立摆模型更新位置、速度、倾角和倾角速度
        ↓
进入下一个采样周期
~~~

程序会自动做三个运动场景，并对五组 \(Q/R_u\) 设置分别仿真：

| 场景 | 开始状态与目标 | 观察重点 |
|---|---|---|
| **recover_initial_pitch** | 原地开始，身体有一个小的初始倾角，目标回到直立 | LQR 是否能把倾角和倾斜速度拉回去 |
| **move_to_position** | 从静止出发，目标位置为 0.20 m | 控制器怎样先移动、再减速并停下 |
| **move_and_recover_disturbance** | 同样移动到 0.20 m，中途再加入短暂的外部等效力矩 | 外力消失后能否恢复，以及是否触发限幅 |

程序会自动比较：源码候选 \(Q/R_u\)、倾角权重增大、倾角速度权重增大、输入代价增大和输入代价减小。它不会预先假定哪一组最好；要根据输出曲线和指标解释差异。

### 2.1 最后能看到什么？

这份实验的主要可视化结果是**时间曲线图**，旁边配有 CSV 数值表；它不会显示一个可转动的三维机器人模型，也没有机械臂或球体动画。具体会看到位置、线速度、机身倾角、倾角速度和等效力矩随时间如何变化，并可把不同 \(Q/R_u\) 的曲线叠在一起比较。CSV 保存每个采样时刻的状态和控制量，适合检查图上看不清的数值。

这对本实验的学习目标已经足够：要观察的是“模型状态如何响应控制输入”，不是外观动画。若以后需要看三维外观和机构运动，要另建包含几何、关节和接触的 MuJoCo/Gazebo 模型；那会增加建模工作，也引入碰撞、接触与执行器参数，不能把它误认为本实验默认包含的内容。当前脚本用 Matplotlib 保存 PNG 曲线和 CSV，不要求 MATLAB，也不要求 MuJoCo。

## 4. 仿真机器人是什么模型？

### 4.1 先把机器人缩成一个平面

想象只从侧面看机器人，只研究前后方向：一个球形底座在地面上滚动，机身像倒立摆一样立在上面。暂时不管左右运动、偏航、三只轮子的相互分配、手臂和真实电机内部细节。

状态向量固定为：

\[
z=\begin{bmatrix}x&\dot x&\theta&\dot\theta\end{bmatrix}^{\mathsf T}
\]

| 状态 | 白话含义 | 单位 |
|---|---|---|
| \(x\) | 球心/底座相对参考位置前后走了多远 | m |
| \(\dot x\) | 底座正向或反向走得多快 | m/s |
| \(\theta\) | 机身相对直立姿态前后歪了多少 | rad |
| \(\dot\theta\) | 机身倾角正在怎样变化 | rad/s |

程序里的控制输入是 \(\tau\)，也就是这个简化模型的**等效驱动力矩**，单位 N·m。它不是三只电机的轮速命令。

### 4.2 模型参数从哪里来？

程序复制当前源码配置中的这一组值：

| 参数 | 数值 | 单位 | 模型中的意思 |
|---|---:|---|---|
| \(m\) | 2.9 | kg | 源模型的滚动部分质量项 |
| \(\rho\) | 0.11 | m | 源模型中的球/滚动半径 |
| \(J_w\) | 0.014036 | kg·m² | 源模型中的轮转动惯量项 |
| \(M\) | 18.0214 | kg | 倒立摆机身质量项 |
| \(l\) | 0.3784 | m | 支撑参考点到机身质心的距离 |
| \(I\) | 4.1115 | kg·m² | 本次前后方向模型使用的机身 \(I_{xx}\) |
| \(g\) | 9.81 | m/s² | 重力加速度 |

这些数值来自 **model_params.yaml** 的配置快照，不代表已经称量或辨识确认。实验脚本把它们写成自己的只读常量，不会打开或改写原始 YAML。若后续查明参数不可靠，应替换为有依据的参数并记录来源。这里采用 Ixx 是为了与源 `model_x` 的数值一致；按常见 x 向前、y 向左、z 向上的机身定义，前后倾斜绕 y 轴，应核对相应 Iyy。原脚本命名与真实机身轴的对应尚未由 CAD/部署模型证明；本实验复现源候选模型，不替它作物理校准结论。

### 4.3 物理方程怎样变成 \(A,B\)？

先计算三个惯性组合：

\[
A_{11}=m+\frac{J_w}{\rho^2}+M,\qquad
A_{12}=Ml,\qquad
A_{22}=Ml^2+I
\]

再计算：

\[
\Delta=A_{11}A_{22}-A_{12}^2
\]

简化模型的两条耦合方程是：

\[
A_{11}\ddot{x}+A_{12}\ddot{\theta}=\frac{\tau}{\rho}
\]

\[
A_{12}\ddot{x}+A_{22}\ddot{\theta}=Mgl\theta
\]

它们同时解出底座的线加速度 \(\ddot{x}\) 和机身的角加速度 \(\ddot{\theta}\)。整理成状态形式：

\[
\dot z=A_cz+B_c\tau
\]

其中：

\[
A_c=\begin{bmatrix}
0&1&0&0\\
0&0&-\dfrac{M^2gl^2}{\Delta}&0\\
0&0&0&1\\
0&0&\dfrac{A_{11}Mgl}{\Delta}&0
\end{bmatrix},\qquad
B_c=\begin{bmatrix}
0\\
\dfrac{A_{22}}{\Delta\rho}\\
0\\
-\dfrac{A_{12}}{\Delta\rho}
\end{bmatrix}
\]

这个写法的意思是：给定当前状态和力矩后，\(A_c,B_c\) 告诉程序状态此刻变化得多快。**这里已经包含了力矩怎样影响平移和转动的加速度。**仿真更新时不能再把力矩额外除以惯量算一次加速度，否则会把动力学重复计算。

## 5. LQR 怎样进入这个仿真？

### 5.1 \(Q,R_u\) 是“扣分规则”

连续 LQR 使用下面的长期代价：

\[
J=\int_0^\infty \left(z^{\mathsf T}Qz+\tau^{\mathsf T}R_u\tau\right)dt
\]

- \(Q\)：状态偏差的扣分规则；
- \(R_u\)：控制力矩的扣分规则。

项目 LQR 参数文件里的候选值是：

\[
Q=\operatorname{diag}(200,25,800,8),\qquad R_u=0.5
\]

本实验先把它当作**起始候选**。它不是通过这次实验得出的唯一正确答案。

本教学程序会用这组 (Q,R_u) 重新计算未经手动缩放的 (K)。原项目离线分析脚本在求得 (K) 后还会对部分增益做人工缩放，所以这里用于学习“标准 LQR 的计算和权重影响”，不复刻原脚本最终写入配置的所有处理步骤。

注意球半径也常用 \(R\) 表示。本手册把控制代价写成 \(R_u\)，避免把“半径”和“LQR 输入代价”混为一谈。

### 5.2 电脑怎样算出反馈 \(K\)？

程序把 \(A_c,B_c,Q,R_u\) 交给连续 Riccati 方程求解器，得到矩阵 \(P\)，随后计算：

\[
K=R_u^{-1}B_c^{\mathsf T}P
\]

运行时反馈律是：

\[
\tau=-K(z-z_{\text{目标}})
\]

在固定目标位置 \(x^*\) 下，目标状态是 \([x^*,0,0,0]^{\mathsf T}\)。反馈中的四项分别利用位置误差、速度、倾角和倾斜速度。\(P\) 和 \(K\) 由求解器算；学习者主要调整 \(Q,R_u\)，看得到的 \(K\) 和运动曲线怎样变化。

### 5.3 连续模型和离散控制周期怎样接起来？

机器人控制不是连续无穷快地更新，而是每隔 \(\Delta t\) 计算一次。主实验默认：

\[
\Delta t=0.01\text{ s}=10\text{ ms},\qquad f=\frac1{\Delta t}=100\text{ Hz}
\]

这是本实验选定的模拟周期，与项目配置的 100 Hz 假设相对应；它不是实测实机周期。

主实验用**零阶保持**：在两个采样点之间，力矩命令保持不变。SciPy 的 **cont2discrete(..., method="zoh")** 把连续模型变成：

\[
z_{k+1}=A_dz_k+B_d\tau_k
\]

于是每个周期都按下面顺序更新：读取状态 → 算 \(\tau_k\) → 做限幅 → 用 \(A_d,B_d\) 算 \(z_{k+1}\)。

主模式使用连续 LQR 算出的 \(K\)，再按 100 Hz 采样执行。额外的 **--design discrete** 会先把模型离散，再解离散 Riccati 方程。连续/离散两种设计的代价定义不完全相同；直接使用同一组数值 \(Q,R_u\) 不代表两种设计的代价完全相等，所以先把离散模式当进阶对照。

## 7. 结果文件怎么读？

每次运行会生成：

| 文件 | 看什么 |
|---|---|
| **metadata.json** | 模型参数来源、矩阵、采样周期、LQR 设计方法、\(P/K\)、软件版本和假设 |
| **summary.csv** | 每个 \(Q/R_u\) 案例与运动场景的指标汇总 |
| **recover_initial_pitch__*.csv** | 初始倾斜恢复场景的逐周期状态和控制输入 |
| **move_to_position__*.csv** | 位置目标场景的逐周期状态和控制输入 |
| **move_and_recover_disturbance__*.csv** | 带合成扰动的场景数据 |
| **\*__comparison.png** | 多种 \(Q/R_u\) 设置的状态和力矩曲线比较图 |

CSV 中既有真实模型状态，也有控制器看到的测量状态。噪声或延迟实验里，两者会不同。**tau_raw_nm** 是限幅前控制要求，**tau_applied_nm** 是实际送入模型的限幅后命令，**tau_disturbance_nm** 是另加的外部扰动。

**summary.csv** 里的主要指标：

| 指标 | 白话解释 | 趋势怎么理解 |
|---|---|---|
| **max_abs_pitch_deg** | 最大身体倾角 | 太大可能表示控制不稳或控制太慢 |
| **final_position_error_m** | 最后离目标还差多少 | 越接近 0 越好，但不能单独代表平衡好 |
| **position_rmse_m** | 整段时间平均位置误差大小 | 同一目标下越小通常越贴近目标 |
| **peak_abs_raw_torque_nm** | 控制器曾要求的最大力矩 | 过大说明动作要求激进 |
| **peak_abs_applied_torque_nm** | 限幅后实际送入模型的最大力矩 | 不会超过本次教学限幅 |
| **saturation_fraction** | 多少比例的控制周期发生力矩饱和 | 长时间饱和说明当前动作要求超过设定能力 |
| **control_effort_nm2s** | 力矩平方随时间累加的控制用量指标 | 越小越省控制，但不能以牺牲稳定为代价 |
| **settling_time_s** | 位置、速度、倾角和倾斜速度都进入小误差范围并保持所需时间 | 空值表示本次仿真时长内没有满足设定范围 |
| **sampled_closed_loop_stable_without_saturation** | 不考虑限幅时，离散闭环线性矩阵是否稳定 | 是模型局部的数学检查，不代表含限幅/延迟后一定稳定 |

程序采用的“稳定”误差范围是：位置误差不超过 0.01 m、速度误差不超过 0.02 m/s、倾角不超过 1°、倾斜速度不超过 2°/s，并且剩余仿真区间都保持在范围内。它是便于比较的教学定义，不是实机验收标准。

## 8. 按顺序完成实验，不要一次改很多参数

### 实验 A：先读懂基准结果

1. 运行第 6 节命令。
2. 打开 **metadata.json**，确认状态顺序、模型参数、\(Q,R_u\)、dt 和设计方式。
3. 先看 **recover_initial_pitch__comparison.png**：身体倾角是否回到接近 0°？力矩有没有超过 ±5 N·m？
4. 再看 **move_to_position__comparison.png**：位置是否接近 0.20 m？速度是否在终点附近减下来？
5. 最后看带扰动的图：扰动出现和消失时，角度、位置和力矩分别有什么变化？
6. 打开对应 CSV，对照某一时刻手算 \(\tau=-Ke\)：乘法结果应和 **tau_raw_nm** 同方向、同数量级，限幅后则看 **tau_applied_nm**。

先不要追求“曲线好看”。第一目标是能解释每条曲线代表谁、单位是什么、为什么会变化。

### 实验 B：提高倾角权重

程序的 **pitch_weight_x4** 只把 \(q_\theta\) 乘以 4，其余不变。把它和基准曲线比较，观察最大倾角、位置误差、峰值力矩和饱和比例。

预测时可以说“模型更不愿意倾斜，因此它可能采取不同的加速/制动动作”；不要预先断言一定更快或一定更稳，最后以曲线为准。因为状态耦合，改一项权重可能改变多个状态的表现。

### 实验 C：提高倾斜速度权重

**pitch_rate_weight_x4** 只把 \(q_{\dot\theta}\) 乘以 4。观察身体正在快速倾斜时，控制力矩是否更早改变方向，最大倾角有没有变化，控制用量有没有增加。

这能帮助你理解为什么 LQR 的状态里不仅有角度，也要有角度变化速度：同样是 0.05 rad 倾角，“正在停住”和“还在快速向前倒”不是同一个状态。

### 实验 D：增加或减少输入代价

比较 **input_cost_x4** 和 **input_cost_x0p25**：

- \(R_u\) 增大：更不愿用大力矩；观察动作是否更柔和、是否变慢、位置误差是否变大；
- \(R_u\) 减小：更愿用力矩；观察是否更快、是否更容易触发限幅或出现较大峰值。

### 实验 E：看力矩限幅的重要性

先用默认 ±5 N·m 限幅，再在新目录关闭限幅：

~~~powershell
.\.venv-lqr\Scripts\python.exe .\lqr_four_state_sim.py --out-dir 'F:\27fall\申请材料\01_项目学习\05_实验与学习记录\02_记录与数据\运行结果\LAB-P1-LQR-02-no-limit' --design continuous --dt 0.01 --no-saturation
~~~

再对比限幅和无限幅结果。限幅数值是教学设定，不是 P1 电机能力数据。若限幅后效果明显变差，说明线性 LQR 计算出的动作有一部分超出了假设可用范围；标准 LQR 本身没有自动处理硬件饱和约束。

### 实验 F：改变控制周期

分别以 50、100、200 Hz 运行，也就是：

| 频率 | 命令中的 dt |
|---:|---:|
| 50 Hz | **--dt 0.02** |
| 100 Hz | **--dt 0.01** |
| 200 Hz | **--dt 0.005** |

每个频率都使用新的输出目录。观察采样变慢后，闭环离散特征值和运动曲线是否变化。连续 LQR 的 \(K\) 在不同采样周期下不一定同样适合；**metadata.json** 中的采样闭环特征值专门用来辅助检查。

### 实验 G：加入测量噪声和一拍延迟

先用 **--noise-scale 1** 加入脚本定义的合成测量噪声；再试 **--measurement-delay-steps 1**，代表控制器使用上一周期的整条测量数据（包括当时那份噪声），不是拿旧状态再临时生成一份新噪声。100 Hz 时一拍是 0.01 秒。

~~~powershell
.\.venv-lqr\Scripts\python.exe .\lqr_four_state_sim.py --out-dir 'F:\27fall\申请材料\01_项目学习\05_实验与学习记录\02_记录与数据\运行结果\LAB-P1-LQR-03-noise-delay' --design continuous --dt 0.01 --noise-scale 1 --measurement-delay-steps 1
~~~

噪声标准差是为了练习设定的：位置 0.001 m、速度 0.01 m/s、倾角 0.1°、角速度 1°/s；它们不是 IMU 或编码器的实测噪声。随机种子固定时，同一配置可以重复得到相同的噪声序列。比较不同权重时程序使用相同噪声序列，尽量避免“换了一种随机噪声”影响结论。

### 实验 H：连续 LQR 和离散 LQR

主实验 **--design continuous** 对应项目分析脚本的设计路线；额外运行：

~~~powershell
.\.venv-lqr\Scripts\python.exe .\lqr_four_state_sim.py --out-dir 'F:\27fall\申请材料\01_项目学习\05_实验与学习记录\02_记录与数据\运行结果\LAB-P1-LQR-04-discrete' --design discrete --dt 0.01
~~~

离散模式先按 0.01 秒采样周期离散模型，再用离散 Riccati 求 \(K\)。这适合学习“控制器确实每隔固定周期运行”的情况。由于连续与离散代价的单位和积分/求和方式不同，同一组 \(Q,R_u\) 数值不保证代表完全同一偏好；比较时要记录设计方法，不能只说哪个 \(K\) 数值大。

<a id="lab-one-step"></a>
### 实验 I：从一行 CSV 验收模型、控制和积分顺序

先在无噪声、无延迟的基准场景选一个非末尾采样行。用 `metadata.json` 中同一案例的 K 与该行 `x_true_m`、速度、`theta_true_rad`、角速度构造状态，减去该场景参考，再手算 \(-Ke\)，与 `tau_raw_nm` 比较。按教学力矩上限裁剪后应对应 `tau_applied_nm`；若有扰动，模型输入还要加 `tau_disturbance_nm`。最后用元数据中的离散矩阵 \(A_d,B_d\) 计算下一状态，与 CSV 的下一行比较。

这条验收顺序是“先读当前状态 → 算本周期输入 → 更新下一状态”，不是先拿下一行状态回算上一行输入。CSV 最后一行用于保存最终状态，其测量和控制字段为 NaN，因为最后状态之后没有再施加一个新周期控制；它不等于节点接收了 NaN 传感器。该实验程序的记录契约与实际 ROS 故障检查要分别理解。

如果求解器不能得到合适的 K，先检查 \(Q\) 对称半正定、\(R_u\) 正定、矩阵形状与单位，再检查系统的不稳定方向能否被输入控制（可稳定化）以及代价能否识别需要稳定的状态（可检测性）。不能用“把权重调得更大”代替模型与求解条件的检查。连续理想闭环看 \(A_c-B_cK\) 的特征值实部是否为负；采样实现看 \(A_d-B_dK\) 的特征值模是否小于 1。加入饱和和延迟后，这两个线性检查也不能单独保证整条轨迹稳定。

## 10. 常见现象和排查顺序

| 现象 | 先检查什么 |
|---|---|
| Riccati 求解失败 | \(A,B\) 是否正确、参数是否有效、不稳定方向是否能被输入控制、\(Q/R_u\) 是否有错误形状或非正值 |
| 力矩一直顶在上限 | 查看 **tau_raw_nm** 与 **tau_applied_nm**；确认限幅是教学设定，不要直接把 \(Q/R_u\) 继续调大 |
| 初始小倾角反而越倒越大 | 检查输入符号、角度正方向、\(B\) 的符号、状态排列是否与 \(K\) 一致 |
| 位置到不了目标 | 看仿真是否提前超出小角度范围、是否长期饱和、是否达到 5 秒时长、速度是否仍未降到零 |
| 改 \(Q/R_u\) 后不同图看起来差不多 | 先核对 metadata 和 K 是否变化；再看纵轴尺度、运行时长和输入是否触发限幅 |
| 离散模式和连续模式的 K 差很多 | 先确认设计方法和采样周期；两者求解的 Riccati 方程不同，不能按 \(K\) 数值直接判优 |
| 噪声/延迟模式更差 | 这是要观察的现象；较迟的反馈会让控制器依据旧状态动作，不代表 LQR 公式算错 |
| 倾角超过模型角度上限 | 程序会停止该条轨迹并标记 **outside_small_angle_model_range**；这只表示线性小角度模型不再适合解释该段，不等同于真实机器人的摔倒判断 |

## 11. 怎样判断“这一组 Q/R 更好”？

不能只挑一张看起来最平滑的图。对同一目标和初始状态，至少同时考虑：

1. 最大倾角是否在模型适用范围内；
2. 最后位置、速度和倾角误差是否够小；
3. 有没有长期处于力矩限幅；
4. 到目标的时间和超调是否能接受；
5. 控制用量是否合理；
6. 加入采样变慢、噪声或延迟后，表现是否突然恶化。

不存在脱离任务的“最好 \(Q/R_u\)”。如果任务是保持直立，倾角和角速度可能更重要；如果任务是准确到位，位置和速度误差的重要性会上升。提高一种重要性，常常要以更多控制动作或其他误差为代价。

## 12. 仿真结论能说到哪里？

这套模型适合做：

- 理解 P1 四状态模型的状态耦合；
- 学习连续/离散 LQR 和 \(Q/R_u\) 的调节影响；
- 比较无饱和与有饱和、不同周期和扰动条件；
- 为后续同模型 PID 对照提供可复现的基线。

它不能单独证明：

- AIRS 三轮球体的完整三维平衡能力；
- 双臂动作下的完整动力学；
- 实机电机速度环或力矩环的带宽；
- 实际控制周期、总延迟或真实电机力矩上限；
- 实机一定比 PID 更稳、更快或更省电。

若之后要用它指导 PID，下一步应在**同一组 \(A,B\)、同一目标、同一初态、同一限幅和同一扰动**下，实现位置外环—姿态内环的串级 PD/PID，再比较倾角峰值、到位时间、超调、饱和比例和控制用量。现有 **balance_compare.py** 中的直接状态 PD 使用另一组合成参数，不应把它的数字直接当作本手册同条件对照。
