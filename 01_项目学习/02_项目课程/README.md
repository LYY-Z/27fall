## 每个项目都按这六步学习

1. **看总览**：读项目 README、项目结构与完整数据链，先说清机器/平台由什么组成。
2. **认输入和输出**：读端到端流程、一个周期的数据流。为每个信号写出来源、单位、坐标/参考系、时间戳和消费者。
3. **学主题章节**：先用图和实际物体建立直觉，再看公式；每个公式都问“变量对应什么、值从哪里来、算完交给谁”。
4. **回到源码**：对照源码地图确认哪个文件/函数/分支实际执行。区分配置、默认值、教学模型和硬件接口。
5. **做实验或故障推理**：只运行明确标注安全的教学实验；真实硬件与危险副作用要按对应操作手册执行。
6. **用问题归档复习**：先口述一条完整因果链，再用总汇查易混点，最后做面试/白板问答和证据核对。

## 统一阅读方法：每个知识点回答六个问题

- **物体/模块**：现实中是哪一个部件或软件模块？
- **量与单位**：输入是什么单位，输出是什么单位？
- **参考系与正方向**：坐标原点、轴方向、符号约定是什么？
- **计算原因**：公式每一项为什么存在？它从哪个几何/物理/软件关系来？
- **调用位置**：代码在哪更新、计算、缓存、发送？它是否真的位于活动路径？
- **证据边界**：静态代码、教学算例、仿真输出和硬件实测分别能证明什么？

### 按 P1 原理章节的讲解深度学习

读者不需要先会背公式。每个重要知识点按下面的顺序展开，某一步不成立时先停在那一步补基础：

1. **先画实际对象。**指出哪个物体、连杆、轮子、传感器或软件模块正在发生变化；明确目标由谁提出。
2. **给量贴标签。**每个符号首次出现时写出真实含义、单位、参考坐标系/轴向、来源和消费者；矩阵另写行列形状。
3. **说明为什么要算。**先说工程问题，再说明所用的几何、物理或软件关系。公式不是装饰，也不能只给最终结果。
4. **把中间步骤写出来。**从标量/二维关系开始，展示求导、投影、矩阵乘法或状态更新的关键过程，解释每次变形用了什么规则。
5. **从头代一个完整数字例。**包括中间量、单位、正负号和最终解释；标清这是实际参数、配置值还是纯教学数值。
6. **连回项目数据流。**指出真实输入来自哪里、代码由谁调用、结果发给谁；区分设定值、估计值、控制意图、设备命令和实测反馈。
7. **说明失败在哪里。**给出至少一个可观察信号或日志字段，解释故障会改变哪一个中间量、最终会表现成什么。
8. **闭卷复述再做练习。**练习题检查概念、手算、代码/调用和结果判断；答案写出推理过程，不只给一个词。

同一章先回答“这是什么、为什么需要”，再回答“怎么算”；跨坐标系时先固定原点和轴向；谈控制量时说清它作用于谁、进入什么接口。初看符号绕时，先回到图、变量表和具体例子，不要一次同时追三条坐标变换链。

## 资料之间怎样分工

- **项目 README / 项目全貌**负责导航和完整系统图。
- **原理与子系统**负责把单个机制讲透，包括直觉、公式、单位、数值例子、源码落点和失败条件。
- **源码阅读与运行**负责版本、调用顺序、线程/回调时序和执行入口。
- **实验与故障**负责可复现步骤、观测量和失败诊断。
- **历次问题归纳**负责按主题收拢反复疑惑并标出回到哪章，不重复粘贴聊天记录。
- **面试训练**负责把已理解的内容压缩成可验证、不过度夸大的口述。

## 共同的事实边界

“代码里有函数”不等于“该函数在当前主路径被调用”；“模型能计算”不等于“模型参数已标定”；“消息已发布/命令已排队”不等于“设备已执行”；“配置频率”不等于“实测周期”；教学模型和手算不等于原机数据；项目材料中的存在也不单独证明个人贡献。每个项目的源码版本和证据边界以各自 README、源码地图和实验记录为准。

## 复习时怎么用

一轮复习只选一个项目：先不看文档，用纸写“输入 → 处理 → 输出 → 反馈”，给每个箭头补上单位/时间/坐标系；卡住时去主题章读解释，之后回到源码地图核对调用，最后用问题归档自测。不要靠反复重读整篇长文判断掌握；能独立讲清因果和边界才算通过。
