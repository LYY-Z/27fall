# 05 从“请求”到“完成”：策略、回执、幂等与重试

前四章已经解释对象、线程和协议。本章进一步判断一次动作到底完成到了哪一步。当前ExecCommand的共同入口主要检查空ID、空cmd和命令表；下面完整策略合同属于教学与设计要求，不能一律称为源码已实现。

## 1. 一次动作需要说清哪些内容

教学请求可以表示为：

```json
{
  "action_id": "a-101",
  "device_id": "robot-A",
  "operation": "move",
  "value": 0.2,
  "unit": "m",
  "deadline": "约定时间基准上的截止时刻"
}
```

operation决定动作意义，value与unit共同定义目标，device_id确定对象，action_id关联这一次请求，deadline表示还可以等多久。这里只演示请求语义；当前地锁的input并没有证明包含并验证以上所有字段。

策略判断应依次回答：设备和操作是否存在；模式与权限是否允许；参数和单位是否有效；反馈是否新鲜；截止时间是否还能满足；当前设备是否处于可执行状态。支持move能力和“现在允许move”不同。

## 2. 成功必须带阶段

| 阶段 | 可说明什么 | 尚不能说明什么 |
|---|---|---|
| accepted | 软件接受了请求 | 消息已经发给硬件 |
| queued | 工作入队 | worker已开始 |
| sent | 发送接口处理了数据 | 设备理解或执行 |
| device_ack | 设备按协议应答 | 机械已经到位，除非协议明确规定 |
| running | 有执行进行中的反馈 | 已完成目标 |
| completed | 指定完成条件成立 | 以后永远无故障 |
| failed/unknown | 有失败证据或结果未知 | unknown不等于明确未执行 |

这些名称是教学合同。当前函数返回码未必有这么多状态，但复述时仍要明确其实际证明范围。

## 3. 用地锁说明写成功与动作完成

地锁Up调用WriteLockCommand，写服务成功后，处理器把currentStatus更新为controlValue并上报，再返回`{"result":"success"}`。

这个链证明“写路径返回成功并更新软件状态”。它没有独立证明地锁机械已升起。随后读寄存器，或读取协议定义的到位位/限位开关，才可能提供完成证据。

将字段拆成desired_state、reported_state和command_stage，会比共用一个currentStatus更不易误读。这个拆分是建议；不要把新字段写成原版已有成员。

## 4. 为什么超时不一定意味着没执行

```text
软件发送a-101 → 设备执行了动作 → 回执丢失
                   ↓
软件等待超时，但设备可能已动
```

此时若简单重新发送“向前再走0.2m”，设备可能累计走0.4m。超时描述的是本方没有及时取得结果，不自动描述设备是否执行。

应先定义结果查询和命令关联机制。如果无法确认，就应报告UNKNOWN并采取适合硬件的安全策略；不能把缺回包一律当成“未执行，放心重试”。

## 5. 幂等是什么：看副作用而非消息次数

同一个请求重复到达，若最终效果与一次请求相同，就具有相应幂等语义。

- `set_target_position=0.2m`重复设置同一绝对目标，可能设计为幂等。
- `advance_by=0.2m`每次累加，通常不能直接重复。
- 即使“开泵”不重复改变开关状态，“再浇20秒”也可能延长时间，必须看具体设备语义。

软件保存action_id及结果，可在重复ID到达时返回既有结果。若重复ID携带不同参数，应拒绝或明确处理，不能误认为同一请求。

## 6. 内存去重为何不能保证跨重启恰好一次

设设备执行成功后，进程在保存“完成记录”前崩溃；重启后记录丢失。软件不知道该动作已经执行，重试可能再次产生副作用。

仅在执行前写记录也有另一问题：写完记录后设备尚未执行，进程就崩溃；如果把记录当完成，动作会被漏掉。需要区分PREPARED、SENT、ACKED、COMPLETED等状态，并结合设备侧ID、持久记录和恢复查询。

这说明“同进程去重演示”“可靠投递”和“端到端恰好一次动作”是不同保证。P4的防重复分析也不能自动提供P6硬件动作幂等。

## 7. 把停止和人工覆盖纳入同一合同

stop到底是设速度0、断使能、保持位置还是制动，取决于设备。人工停止后，应说明新动作是否仍可入队、旧任务如何取消、恢复是否需要重新使能，以及当前操作可否被中止。

取消排队任务与停止正在运动的设备不同。将取消标志置true，不意味着CAN/Modbus设备已经收到停止命令。

## 8. 一次请求的纸笔推演

教学设当前时刻10.0s，状态采样9.8s，允许年龄0.15s。年龄0.2s，先拒绝依赖该状态的运动请求，即使设备能力包含move。若重新取得9.95s反馈，则年龄0.05s，可以继续检查参数、模式与deadline。

接下来在10.1s发送a-101、10.12s收到协议ACK、10.5s收到到位反馈。若完成条件确为这份到位反馈，端到端完成延迟是0.5s；不能用ACK延迟0.12s代替。

英文：*I associate results with the request and distinguish acceptance, protocol acknowledgement and physical completion. A timeout may leave the outcome unknown, so retries need explicit side-effect and recovery semantics.*
