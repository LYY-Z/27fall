# P6 综合推理、白板与源码追问

本页补充原25道主问，不重编号。每个场景按“中文理解→纸笔中间量→英语口述→源码追问”练；英文用客观源码/教学事实，个人经历句只按贡献证据填写。不要把参考答案当成自己已经完成的实验。

如果公式一眼看不懂，先不要硬算：把每个符号旁边写上“它代表什么、单位是什么、是谁给的”，用箭头画出数据变化，再用一个很小的数字手算。完成中文因果说明后，再练英文表达。综合主线可返回[项目白话总览](../00_项目全貌与学习路线/03_P6一次设备动作怎样走过软件平台.md)。

## 使用顺序

1. 用中文回答主问，画输入→计算→输出；写形状、单位、时刻。
2. 对照数字与原源码，指出假设和启用分支。
3. 用英语说45—90秒，回答第二层追问。
4. 记录卡住的是基础、项目、证据还是表达；下次只补对应环节。

## 场景1：能力与在线不同

**Interviewer:** Why not mark a device usable immediately after registration?

### 先用中文把因果与中间量讲清

注册说明接口能力，不说明当前连通/反馈新鲜。教学register默认online false，新序号且age≤1s才sync；源BaseInit设置默认online也不自动证明健康，两个实现分开。

### Candidate：英语参考

Registration describes what a device can do. Usability additionally depends on fresh synchronized state and the connection contract. I distinguish the source’s default online flag from demonstrated communication health.

**Follow-up:** What happens after sequence reset?

中文追问答案：单boot逻辑会拒旧序号；真实系统需session/boot版本，并明确重注册/同步策略。

验收：能指出上述结论的源函数或教学假设；没有运行数据时，只说手算/静态所见，不补性能数字。

## 场景2：命令路由

**Interviewer:** How is a generic command executed by a specific device?

### 先用中文把因果与中间量讲清

源ExecCommand校空、设备级handler优先再mapfallback，提交HIGH任务到线程池；适配器处理设备/Modbus细节。抽象接口解决替换性，不能掩盖协议尺度、线程安全与设备结果。

### Candidate：英语参考

The generic layer validates and routes a command, and the device handler implements protocol-specific behavior. I trace handler precedence, task submission and feedback rather than assume that an abstract interface makes every device interchangeable.

**Follow-up:** How do you avoid a technology-list answer?

中文追问答案：说明请求schema→具体handler→排队→协议→反馈及每处失败，不只报C++/线程池名称。

验收：能指出上述结论的源函数或教学假设；没有运行数据时，只说手算/静态所见，不补性能数字。

## 场景3：future并不等于非阻塞接口

**Interviewer:** Is ExecCommand nonblocking because it uses a thread pool?

### 先用中文把因果与中间量讲清

任务在worker异步执行，但调用方future.get同步等待且无deadline。若加wait_for后返回，worker仍可能运行；源按引用捕获的参数寿命要改，不可只增加超时。新教学dispatchOwned按值Command/sharedowner且mutex保护，仍无取消。

### Candidate：英语参考

Worker execution is asynchronous, but future.get makes the caller wait. A timeout does not cancel the worker. If the caller returns early, referenced data may no longer be alive, so ownership and cancellation semantics must be redesigned together.

**Follow-up:** Does shared_ptr make the adapter thread safe?

中文追问答案：只管寿命，mutable状态仍需mutex或其他同步；教学两者分别展示。

验收：能指出上述结论的源函数或教学假设；没有运行数据时，只说手算/静态所见，不补性能数字。

## 场景4：Modbus ACK

**Interviewer:** Does a successful write mean the mechanism reached its target?

### 先用中文把因果与中间量讲清

0x03从地址0读17个寄存器，GroundLock代码读取 allData[7] 并注释为寄存器地址 0x0006；要先核对底层返回数组的布局，不能直接把地址写成数组下标。0x06写单寄存器成功不等于机械运动完成；命令、后续读回、状态序号和采样时间需分别关联。

### Candidate：英语参考

A protocol acknowledgment and physical completion are different events. I need subsequent fresh device feedback, matched to the command, before reporting that the target has been reached.

**Follow-up:** What fields belong in an action result?

中文追问答案：accepted/executing/completed/failed阶段、ID、device、timestamp、seq、reason与实际状态。

## 场景5：去重边界

**Interviewer:** Why is an in-memory action ID set not exactly-once?

### 先用中文把因果与中间量讲清

重启丢集合，设备可能已动作而上层未记录；重复ID若不同payload还要冲突检查。教学仅单进程模拟效果，无persistent日志/M-DDS/真实ACK，不升级成分布式执行保证。

### Candidate：英语参考

An in-memory set prevents some repeated effects within one process, but it does not cover crashes or ambiguous device outcomes. Persistent identifiers, payload consistency and a recovery protocol are needed for stronger execution guarantees.

**Follow-up:** How would you test recovery later?

中文追问答案：在发送前/后、记录前/后故障注入并核对动作次数；此处是方法，不称已测。

## 场景6：关闭和贡献

**Interviewer:** What must be considered when releasing a device?

### 先用中文把因果与中间量讲清

源Release清状态、移调度、OnRelease、注销ReportManager，最后设备时关线程池；排队/进行中的任务必须与对象寿命、资源关闭一致。当前M-DDS/M-Robots历史源缺，不用标准相似模块冒充。

### Candidate：英语参考

Release must coordinate queued work, running callbacks and device resources. A joined scheduler alone does not prove that every callback is safe. I separate the available source from missing platform-specific modules and state my own contribution only where records support it.

**Follow-up:** Which documents would substantiate your role?

中文追问答案：实际commit/模块改动、设计决策、交付记录；候选CV/PS语句不是独立实机证据。

验收：能指出上述结论的源函数或教学假设；没有运行数据时，只说手算/静态所见，不补性能数字。

## 场景7：在线标志和真实通信

**Interviewer:** The framework reports a device as online. What does that prove?

### 先用中文把因果与中间量讲清

先找谁写 online、依据什么事件、最后一次有效读数何时到达。当前 BaseDeviceHandler::Init 在 OnInit 成功后设置 online；ReportProperty 的路径也可能在上报前设置 online。因此要把 framework 标志、socket/协议连通、有效新鲜反馈分开。

### Candidate：英语参考

The online flag is a framework state, not necessarily proof of a fresh device response. In this snapshot, initialization and property reporting can set it. I would also inspect the last successful read or heartbeat and its timestamp.

**Follow-up:** What if the last measurement is old but the connection is still open?

中文追问答案：连接可能存活但状态已过期；由采样时间、序号和业务TTL决定状态是否可用。

## 场景8：地址、下标和寄存器表

**Interviewer:** How do you verify that the status register is decoded correctly?

### 先用中文把因果与中间量讲清

先记录起始地址、请求数量、返回 vector 长度、代码下标、设备寄存器表和已知测试值。当前 GroundLock 请求地址0、数量17，代码取下标7并注释地址0x0006。需查底层服务是否改变数组布局，或用已知状态做安全读回；不能只看一条注释。

### Candidate：英语参考

I would separate protocol addresses from zero-based array indices. The handler reads 17 registers from address zero and accesses index seven for the status described as address six, so I would verify the lower-level return layout against the device register map.

**Follow-up:** What symptom might an off-by-one mapping cause?

中文追问答案：界面可能显示相邻寄存器值，状态与物理地锁不一致；应以已知输入/寄存器回读定位。

验收：能指出上述结论的源函数或教学假设；没有运行数据时，只说手算/静态所见，不补性能数字。

## 场景9：关闭时的在途动作

**Interviewer:** A command is waiting on a future while its device is being released. What should you inspect?

### 先用中文把因果与中间量讲清

先画 Release、ExecCommand、worker 和 handler 的并发时序，再检查 threadPool_、handler 捕获对象、设备连接和 promise 的寿命。当前静态源码显示 Shutdown 可能令 worker 不再取队列中后续任务，因此不能假定等待方都拿到结果；具体并发是否会出现还要查上层生命周期锁与设备注销顺序。

### Candidate：英语参考

I would trace the caller, queued lambda, handler and device resource through shutdown. A worker join does not by itself guarantee that every pending promise receives a result. The lifecycle needs an explicit drain or cancellation policy before dependent state is destroyed.

**Follow-up:** Why is adding a timeout insufficient?

中文追问答案：超时只让调用方不再等，不会自动取消 worker；引用捕获的对象可能已失效，设备也可能仍在执行。

验收：能指出上述结论的源函数或教学假设；没有运行数据时，只说手算/静态所见，不补性能数字。
