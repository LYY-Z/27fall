# P2 端到端流程与面试地图

## 0. 读完后应能讲出的三条链

P2 涵盖 VR 手柄遥操、Leader/Follower 主从臂和二轮底盘。它们各自有入口、模型、时间与执行器；资料放在同一个目录不证明已由同一 launch 连成实机系统。本篇先完整走 VR，再走主从和底盘；专章提供逐数字推导，[疑惑覆盖索引](04_对话疑惑覆盖与复习索引.md)用于查漏。

| 链路 | 输入 | 主要计算 | 输出 |
|---|---|---|---|
| VR | 手柄位姿和使能键 | 相对动作→TCP目标→差分 IK | 仿真执行器/ROS关节目标 |
| 主从臂 | 电机反馈、Leader/上层关节参考 | Leader重力补偿、Follower参考映射 | MIT五字段电机命令 |
| 二轮底盘 | 车体速度目标、轮反馈 | 轮速分配、已配置的速度环、里程计 | 板端/电机命令与状态 |

阅读时把每条箭头说成“谁产生、哪个物体的什么量、单位、坐标、时间、谁消费”。模型计算、源码调用和实验结果分开陈述；个人工作须回到[贡献证据](../04_贡献_证据与材料映射/01_CV_PS表述与证据.md)。

## 1. 先只认一套坐标与记号

W 是 VR 房间/追踪空间，H 是手柄局部坐标，B 是机械臂基座，E 是 TCP。统一 \(R_{AB}\) 把 B 轴描述的向量变成 A 轴描述：
\[
v^A=R_{AB}v^B.
\]
旧记号 \(R_{A\leftarrow B}\) 等价。矩阵每列是 B 的一根轴在 A 中的方向，右上位置向量则是 B 原点在 A 中的位置。位置/位移 m、轴角 rad、关节角 rad、关节速度 rad/s、TCP线速度 m/s 与角速度 rad/s 要分清。

源码还有 provider 原始轴 V、转换后的轴 W、MuJoCo世界 M。W 与 M、B 是否一致必须按变换链核对，不能因变量名字叫 world 就合并。教学 C 固定为 \(R_{BW}\)；若讨论手柄局部轴到 TCP 局部轴，另记 \(C_{E0H0}\)，不复用同一个无下标 C。

## 2. 程序初始化和一次操作的开始是两件事

程序初始化加载模型、关节初值、任务、通信和滤波状态。随后读取 XR；控制键数值大于 0.9 的第一次激活，才捕获这次操作的手柄参考 \((p_{H0}^W,R_{WH0})\) 与 TCP 参考 \((p_{E0}^B,R_{BE0})\)。

手柄与 TCP 是两个物体，绝对位置不要求重合，局部轴初始不必同向。E0 朝向可以倾斜。起点分别保存，让零手柄增量对应零机器人目标增量。松开清参考，下次重新捕获；这也使人可以收回手再继续操作。

当前可读 Python 脚本先转换/滤波手柄数据，再记录手柄参考。输入四元数 xyzw 重排为 wxyz；默认 filter_alpha=0.3，主入口传 0.5，scale_factor=1。归一化不等于四元数半球对齐，不能声称已经采用 SLERP。

## 3. 手柄变化怎样成为 TCP 目标

### 3.1 位置与朝向分别计算

\[
\Delta p_W=p_H^W-p_{H0}^W,\quad
p_d^B=p_{E0}^B+sC\Delta p_W.
\]
旋转增量若按世界轴表示：
\[
\Delta R_W=R_{WH}R_{WH0}^T,\quad
R_d=(C\Delta R_WC^T)R_{BE0}.
\]
C 改写方向，s 只缩放位置；手柄转角不随位置比例改变。世界轴增量左乘；局部轴增量 \(R_{WH0}^TR_{WH}\) 必须与局部对应关系成套处理并右乘。不可交换两种定义。

### 3.2 连贯数值例：从手柄到目标矩阵

教学设 C=\(R_z(90^\circ)\)、s=0.5；手柄从 \([0.4,0.2,1.0]\) m 到 \([0.5,0.2,1.0]\) m，朝向从 I 到 \(R_z(90^\circ)\)。TCP起点为 \([0.3,0,0.4]\) m，朝向 \(R_x(90^\circ)\)。

位移为 \([0.1,0,0]\) m，换到 B 为 \([0,0.1,0]\)，缩放后目标位置 \([0.3,0.05,0.4]\) m。旋转增量在 B 中仍绕 z 转90°，所以
\[
R_d=R_z(90^\circ)R_x(90^\circ)
=\begin{bmatrix}0&0&1\\1&0&0\\0&1&0\end{bmatrix}.
\]
组合目标：
\[
T_d=
\begin{bmatrix}0&0&1&0.3\\1&0&0&0.05\\0&1&0&0.4\\0&0&0&1\end{bmatrix}.
\]
第一列表示目标TCP的+x朝基座+y；右上三格是目标位置。它只是希望值。

SE(3) 必须左上 R 正交且 det=1，同时最后一行为 [0,0,0,1]。点 w=1 受旋转和平移，方向 w=0 只转轴；任意4×4不是SE(3)，最后一行也不保证无缩放剪切。连乘要中间参考系匹配，逆变换平移为 -Rᵀp。完整四个位姿与组合推导在[坐标章第4节](../01_原理与子系统/01_VR相对位姿与坐标标定.md)。

### 3.3 真实轴转换从哪里来

源码 geometry.py 使用固定 R_HEADSET_TO_WORLD：
\[
\begin{bmatrix}0&0&-1\\-1&0&0\\0&1&0\end{bmatrix}.
\]
矩阵列说明原始 +xV→-yW、+yV→+zW、+zV→-xW。它是源码的轴重定义，与教学90°矩阵不同；物理房间到机器人基座是否已对齐、坐标重定位后的关系仍需标定证据。源码并没有单独声明教学 C。不能用教学轴对应替换项目真实矩阵的含义。

## 4. 目标与当前比较，才得到跟踪误差

手柄从起点转90°是设目标动作；机器人现在离该目标还差6°是跟踪误差。当前 TCP 位姿来自模型 FK 或真实编码器经模型计算。

先在同一 B 中比较：
\[
e_p=p_d-p,\quad e_R=\operatorname{Log}(R_dR^T)^\vee.
\]
Log/vee 产生三维轴角：向量方向是还要转的轴，长度是弧度，不是普通逐格对数，也不是欧拉角三个数普遍相减。

教学例当前位置 \([0.40,0.23,0.30]\) m、目标 \([0.40,0.25,0.30]\) m；当前 yaw=104°、目标=110°且只绕同一z轴。差为 [0,0.02,0] m 和 [0,0,0.10472] rad。分别乘 \(K_p=2/s,K_R=3/s\)：
\[
V_d=[0,0.04,0,0,0,0.31416]^T.
\]
上三项 m/s、下三项 rad/s，六种要求同时存在但单位不相加。每秒增益来自所选反馈律 \(v=e/T\)，不是几何位置自动变速度。

## 5. 模型怎样知道关节能造成哪些动作

模型文件保存连杆连接、关节固定原点/轴、TCP偏移；当前 q 给出各关节角。沿链乘固定安装变换与关节运动变换，得到每个轴心 O、轴向 a 和 TCP位置P。在同一参考系中，转动关节一列为
\[
J_i=\begin{bmatrix}a_i\times(P-O_i)\\a_i\end{bmatrix}.
\]
单杆 O=[0,0,0]、a=[0,0,1]、P=[0.30,0,0]，叉乘逐项为 [0,0.30,0]，所以该列 [0,0.30,0,0,0,1]。乘0.2 rad/s，TCP得到+y的0.06 m/s与绕+z的0.2 rad/s。

这些数来自几何与当前姿势，不需要实体先试转。七关节单TCP常为6×7；满行秩时有冗余，可以用不同关节组合完成同一瞬时任务。多臂完整列数看model.nv，不能把教学19×7当实际模型尺寸。[MuJoCo/Mink章第2–3节](../01_原理与子系统/02_MuJoCoMink任务约束与求解.md)给递推与二连杆算例。

MuJoCo 既能模拟物理，也能只做FK/Jacobian。MjModel存结构，MjData存状态；无窗口照常计算。mj_forward更新当前派生量、不积分时间；mj_step推进物理仿真。

## 6. Mink 如何决定一组关节小步

Mink 将有目标的 FrameTask 与 PostureTask 组织成QP，调用OSQP。所有任务共享同一组决策变量；残差在当前姿势附近线性化，平方和形成二次目标，实际传入的限制形成约束。任务权重控制偏好，硬速度/位置/碰撞边界要真实构造并传入。

2026-10-12 核验当前上游：内部QP求切空间Δq，solve_ik返回Δq/dt，应用再按dt积分。FrameTask 的局部SE(3) Log误差及任务J包含坐标和Jlog修正，不能拿世界几何J与任意误差拼接。历史Mink版本未锁定，上述核验不证明过去完全相同。详细来源见[MuJoCo/Mink章第5–6节](../01_原理与子系统/02_MuJoCoMink任务约束与求解.md)。

近奇异的小非零σ使伪逆1/σ变大；σ=0的Moore–Penrose伪逆系数定义为0，无法实现的方向留下残差。教学DLS统一惩罚+λ²||z||²，增益σ/(σ²+λ²)抑制弱方向，但不提供硬限速。全局damping与每任务LM可以并存，不能说软件永远只有一个阻尼来源。完整推导和手算见[奇异阻尼章](../01_原理与子系统/03_奇异阻尼限位与异常保持.md)。

源码Posture目标每步设当前q，抑制本步多余变化，不能称固定home。默认cost和lm_damping是配置事实；lm_damping不能直接当教学λ。

## 7. 求解后仍有执行和反馈

普通转动关节例 q=[0.1,0.2] rad、vel=[0.4,-0.2] rad/s、dt=.005 s，积分得 q_next=[.102,.199] rad。含四元数的配置需用库积分，nq与nv可能不同。

独立XarmIKSolver直接写qpos/ctrl并mj_forward，是运动学更新；主遥操只写ctrl，_update_ik随后mj_step，实际qpos由仿真动力学产生。主入口openarm/scene.xml的活动手臂执行器是position，另一个assets副本使用motor；ctrl不能全目录统一称为关节角。保存脚本主入口还有异常文本，当前意图路径不等于已成功运行。

dt默认5 ms是IK积分配置；仿真物理h取opt.timestep；XR帧间隔、墙钟周期、电机内环另算。未看到二者联动赋值就不能说mj_step也为5 ms。QP成功、Δq很小、ROS目标发布，都不等于TCP已到位；需位置/姿态残差和真实反馈。异常保持旧ctrl还可能持续出力。

实机可读编码器，再用MuJoCo只做几何，或改用KDL/Pinocchio；继续用Mink就依赖MuJoCo模型。位置驱动接积分后的q_next，速度驱动接qdot，力矩驱动要另加控制律/动力学算tau。实际编码器回流、驱动模式和通信超时需独立证据。

## 8. 主从机械臂走另一条链

人推动Leader，编码器反馈经motor_to_joint成为qL。URDF经KDL tree选start/end chain，按活动关节顺序填q，JntToGravity给g(q)。在 \(M\ddot q+C\dot q+g=\tau\) 约定中g是电机应提供的支撑项，重力外力广义矩为-g；不要又无条件反号。

所读unilateral_step中Leader手臂effort=ratio×gravity，ratio=[1,1,1,1,1,1,.8]；MIT的pos/vel/kp/kd为0，torque填映射后的effort。该函数计算Coriolis与摩擦，但手臂混合赋值被注释，夹爪另有摩擦输出。分支与设备范围必须说清。

Follower读参考，经joint_to_motor发送pos、vel、Kp、Kd、零前馈。理想MIT关系为tau=Kp位置差+Kd速度差+tau_ff，所以torque字段0不等于总力矩0。关节到电机的方向、偏置、传动比与力矩换算需协议证据。

相同结构可用初始化相对角映射；不同结构需另设计FK/IK，不能当已实现。主从关节跟踪也不自动证明从臂接触力传回主臂。完整URDF/KDL、二连杆重力和MIT算例见[主从章](../01_原理与子系统/04_KDL重力补偿与主从跟踪.md)。

## 9. 差速底盘独立完成轮动闭环

标准模型 \(v_r=v+\omega L/2,v_l=v-\omega L/2\)，再除r得轮角速。编码器计数按每圈计数、传动比和dt换成反馈，与轮目标比较形成速度环。里程计由反馈轮角增量求
\[
\Delta s=r(\Delta\varphi_r+\Delta\varphi_l)/2,\quad
\Delta\psi=r(\Delta\varphi_r-\Delta\varphi_l)/L,
\]
再按当前/中点航向积分。s=rθ来自弧长和纯滚动；打滑、尺度与时间误差会漂移。

本地板端H723/EZ_RTOS副本的pid_calc被注释，speed_send直接给参考；不能称板端PID已启用。ROS2/CAN桥接要核对单位、ID、时间和下游模式，msg_to_Host不能自动称发布ROS2 odom。host_online边界和未赋值发送缓冲是静态风险。完整计算与证据范围见[底盘章](../01_原理与子系统/05_差速PID里程计与ROS2CAN.md)。

## 10. 面试复述与学习验收

中文主线：“VR按使能时分别记录手柄和TCP参考，换轴后的相对变化生成TCP目标。模型从当前关节状态算位姿和雅可比，Mink按任务、偏好和实际约束求小步，再积分形成关节参考。仿真执行器或硬件驱动跟踪后，读取新状态重算。我区分源码配置、当前库API、历史环境与实机证据。主从臂重力补偿和底盘轮速控制各有独立入口。”

English reference: “The VR path maps controller motion relative to activation into a TCP pose target. A robot model computes the current pose and Jacobian, and Mink solves a differential IK update. The application integrates the returned velocity into a joint reference, which the actuator must then track. I verify model frames, limits, feedback and timing separately from solver success.”

纸笔验收：不看资料写四个坐标系、四个位姿；完成一次目标生成、一列叉乘、一次阻尼解和一次速度积分。源码验收：指出真正活动分支、XML路径、求解器返回值与失败处理。证据验收：说出哪些结论仍缺安装版本、协议、日志和个人贡献材料。
