# 环境、工程和运行入口：只描述当前课程仓库

## 1. 课程源码有哪些环境

指定仓库并非单一工程：

|内容|文件/环境|用途|
|---|---|---|
|第五课运动学|MATLAB 脚本和 PlatformIO 嵌入式目录|绘制/求解五连杆 FK、IK|
|第六课 PID 平衡|ESP32/Arduino 风格 PlatformIO 工程|传感器、轮式平衡与腿目标|
|第八课 LQR|MATLAB wheel_control.m|建立连续模型并调用 lqr|
|第九课变腿高部署|PlatformIO/ESP32 工程 + MATLAB 拟合脚本|轮平衡代码、系数拟合示例|
|第十课 VMC|MATLAB 符号推导文件|推导雅可比的草稿|
|第十一课 VMC 实现|ESP32/Arduino 风格 PlatformIO 工程|IMU 任务、TWAI/CAN 腿控制和轮接口|

课程里包含 ESP32 的 FreeRTOS 任务 API；这不等于 STM32/Keil/HAL/FDCAN 工程。主控制和通信文件应按各课自己的版本阅读。

## 2. 入口文件怎么找

第六、九、十一课可先读各自 src/main.cpp 的 setup() 与 loop()，再分别跳到 robot.cpp、Kinematics.cpp、MPU6050.cpp、CAN 通信文件。第八课从 wheel_control.m 开始，按 A/B、Q/R、lqr 调用顺序读。第五课从 MATLAB 正反运动学函数开始。

第十一课创建 IMUTask 并固定到 ESP32 核心，主 loop 另行运行。代码没有明显为 IMUTask 设置固定 delay；不能从任务名推断它的真实采样率。实际周期要用运行时戳测量。

## 3. 软件包和硬件边界

MATLAB 第八课需要 MATLAB 控制系统工具箱中的连续 LQR 函数；第五课动画脚本依赖 MATLAB 绘图。PlatformIO 工程依赖 ESP32 Arduino 框架以及仓库中的库和配置。具体板卡、版本、串口和电机接线必须从 platformio.ini、板卡说明和实物配置确认。

轮毂电机函数在预编译 libSF_Motor.a 中，当前头文件只给出 sendMotorTargets 声明。腿部通信代码能看到 MIT 字段和 TWAI/CAN 路径，但真实电机协议效果仍要结合硬件手册和测试记录确认。

## 4. 本次工作范围

本次仅进行源码阅读和文档重整，不编译、不上传固件、不启动电机、不连接硬件。本文的运行环境说明不构成“已成功编译或运行”的声明。
