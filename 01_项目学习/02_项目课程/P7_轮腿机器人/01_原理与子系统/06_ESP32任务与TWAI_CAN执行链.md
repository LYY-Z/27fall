# 第十一课主循环、IMU任务与 CAN 命令链

> 本章针对第十一课源码。它是 ESP32/Arduino 工程，使用 ESP32 FreeRTOS API 创建 IMU 任务，并通过 TWAI/CAN 文件通信。

## 1. 上电准备

main.cpp 的 setup 依次初始化 I2C、串口、MPU6050，创建 IMU 任务，再初始化 CAN、PPM 和电机接口，等待后使能电机。具体延时是启动流程的一部分，不是控制频率的证明。

Open_thread_function 使用 xTaskCreatePinnedToCore 创建 IMUTask。它循环读取 IMU 并更新姿态/陀螺变量。源码中这个 while 循环没有明显的 delay 或阻塞等待，因此不能从配置推断固定 IMU 采样频率；需在运行时测量，且应留意任务占用 CPU 的影响。本文不运行固件。

## 2. loop 的顺序会造成什么

第十一课主 loop 的代码顺序是：

1. wheel_control：用当前缓存的 pitch、gyro、轮速、位移和上一轮几何点生成轮目标；
2. CAN_Control：接收 CAN 状态，并按发送节拍向关节电机发命令；
3. remote_switch：更新遥控开关状态；
4. calRightVMC、calLeftVMC：由当前腿几何和目标计算新的关节力矩；
5. snake_case：更新动作状态；
6. sendMotorTargets：把轮目标交给轮毂电机库；
7. storeFilteredPPMData、mapPPMToRobotControl：滤波并转换遥控量。

这说明代码的顺序不是“本帧所有传感器先更新，再所有控制计算，再全部输出”。例如 CAN_Control 在该处接收消息，但它发送时读到的腿 torque 字段是在后面的 VMC 函数更新的，所以这些新力矩通常要到下一次 CAN_Control 才被装入发送结构。wheel_control 也使用此前算出的腿点。遥控映射放在尾部，所以本轮新遥控值通常在后续循环参与控制。

## 3. IMU 数据链

IMUTask 调用 mpu6050.update() 更新传感器数据，再读取 roll、pitch、yaw 和 gyroX/Y/Z。MPU6050 的原始加速度/角速度与软件融合得到的角度是不同层次的数据。gyroZ 有一个小死区，gyroY 使用低通滤波。

源码一处 gyroX 滤波调用传入 gyroY 作为 previousValue，和变量名不一致，需当作待核的实现问题。滤波公式和传感器单位应追踪 MPU6050.cpp，不能凭变量名补出未实现的功能。

## 4. CAN 关节数据和 MIT 命令

CAN_Control 先调 recCANMessage()，接收线程/驱动解析出的状态后写到 devicesState。CAN_comm.cpp 将编码后的 pos、vel、tor 字段按结构中设置的范围解码为浮点数。腿部几何和 VMC 使用这些关节状态。

发送时，代码把四个关节 torque 字段填入 MIT 结构，pos、vel、kp、kd 置零，再以设备 ID 发送。配置声明 torque 范围，但协议字段缩放、驱动器内部闭环和实机力矩校准仍要结合通信实现及电机手册确认。

## 5. 轮子命令链的边界

main.cpp 调用 Motor.h 中的 sendMotorTargets(motor1Target,motor2Target)。这个函数实现在预编译的 libSF_Motor.a 中，仓库头文件只暴露接口。robot.cpp 中轮目标限制到 ±3，但本目录不能仅凭接口声明确认数值单位和底层电机控制模式。

因此准确说法是“控制程序生成并传递两个轮电机目标值”。若要说 rad/s、rpm 或转矩，需获得库实现、配置和电机反馈标定。

## 6. 周期与任务

CAN_Control 以 millis() 和 SEND_INTERVAL=1 的条件限制发送间隔，注释意图约为 1 ms；这只是调度条件，不是测得的 1 kHz。主 loop 的计算、CAN 收发、IMU 并发、串口打印和系统任务都会影响实际周期。IMUTask 没有明确周期等待，也不能称为固定频率传感器任务。

若要报告实际周期，需在相同运行版本上记录连续时间戳，统计平均值、最大值和抖动；源码阅读不能替代实测。

## 7. 安全和证据边界

当前所见内容不能自动证明具备完整失联看门狗、跌倒停机、接触力传感器或离地恢复状态机。若讨论这些，应标为需要补充的安全设计，而不是仓库已实现。

## 8. 汇报用一句话

该课程版本在 ESP32 主循环中更新轮平衡目标和腿部 VMC 力矩，IMU 由单独任务读取，关节数据通过 TWAI/CAN 收发，轮目标交给预编译的轮电机库。由于命令写入顺序和底层库边界，我会进一步核对数据新鲜度、执行周期和电机单位，再判断闭环性能。

## 历次疑惑归纳：控制任务的反馈怎样到 ESP32 电机接口

全项目回顾见 [P7 历次问题归纳](../05_中英文面试/05_历次问题归纳与新源码视频完整讲解.md)。

- **IMU 任务、控制循环和 CAN 发送是分开的阶段。**任务周期配置说明预期调度节拍，实际控制间隔还受计算、抢占、总线和等待影响；频率结论需要时间戳。
- **TWAI/CAN 发送的是协议字段，不是抽象的“物理力”。**要确认轮毂目标单位、关节 torque 字段比例、符号、限幅和电机模式；未标定协议值不能称为 N·m。
- **编码器/IMU反馈必须回到同一周期闭环。**若反馈过期、缺失或时间不同步，状态估计会错误；单次发送成功不能证明电机到达目标。
- **模型、课程控制和硬件库分层表述。**预编译电机库可证明调用接口存在，但无法仅凭公开头文件推断内部控制律和硬件性能。
