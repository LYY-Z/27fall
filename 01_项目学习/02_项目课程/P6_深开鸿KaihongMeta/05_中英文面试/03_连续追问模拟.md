# P6 连续追问模拟

训练方式：先不看答案口述，再看下面参考。每轮约10分钟，记录哪一步从理解变成背词。

**初学者练法：**第一遍只用中文讲清楚因果，不要求马上说出所有术语；卡住时停下来画对象、箭头和信号单位。第二遍再回答英文追问。先按动作单从校验、排队、协议发送到设备反馈讲过程。函数返回、网络确认、设备ACK和动作完成是不同事实；按源码证据回答。先用[项目白话总览](../00_项目全貌与学习路线/03_P6一次设备动作怎样走过软件平台.md)把主线复述一遍。

## Round 1

**Interviewer:** What problem does the device platform solve?

**Candidate:** The platform provides common capability, command and feedback interfaces across devices. Hardware details remain in adapters, while units, freshness and errors must still be visible to callers.

**Interviewer, deeper:** Which differences should not be hidden by an abstraction?

**回答依据：** 统一设备能力、命令和反馈接口，让上层少依赖具体协议；设备差异不能全隐藏，单位时效错误仍需上层知道。 追问需要回模型、源调用或实验条件；不要自动添加个人性能数字。

## Round 2

**Interviewer:** Why separate an interface from its implementation?

**Candidate:** The caller depends on a contract, while a concrete adapter implements it. This supports substitution and mocks, provided inputs, outputs, errors and lifecycle behavior are explicit.

**Interviewer, deeper:** How could an implementation violate the contract?

**回答依据：** 调用者依赖契约，具体设备类实现；便于替换和Mock，契约要输入输出错误与生命周期明确。 追问需要回模型、源调用或实验条件；不要自动添加个人性能数字。

## Round 3

**Interviewer:** What is RAII?

**Candidate:** RAII ties resource lifetime to object lifetime. Unique ownership and scoped locks simplify cleanup. Threads still need a deliberate stop-and-join policy before dependent state disappears.

**Interviewer, deeper:** Can a destructor safely wait forever?

**回答依据：** 资源绑定对象生命期，构造获取析构释放；unique_ptr唯一拥有、lock_guard作用域锁；线程仍需stop/join设计。 追问需要回模型、源调用或实验条件；不要自动添加个人性能数字。

## Round 4

**Interviewer:** How does ExecCommand work in the available source?

**Candidate:** It validates and looks up the handler, submits a high-priority task, captures the result or exception through a promise, and waits on the future. The caller is therefore still synchronously waiting for completion.

**Interviewer, deeper:** Where would you add a deadline?

**回答依据：** 检查命令、查设备/通用处理器、提交HIGH任务、处理器捕异常、promise给结果、future.get等待。要知道等待是同步的。 追问需要回模型、源调用或实验条件；不要自动添加个人性能数字。

## Round 5

**Interviewer:** Why can asynchronous submission still block the caller?

**Candidate:** The work runs on another thread, but future.get waits for the result. Asynchronous execution does not imply a nonblocking caller, especially without a timeout.

**Interviewer, deeper:** What should happen when the handler never returns?

**回答依据：** 提交异步只是任务另线程跑，随后future.get仍阻塞到结果；没有超时则设备卡住可挂等待。 追问需要回模型、源调用或实验条件；不要自动添加个人性能数字。

## Round 6

**Interviewer:** What is the risk of capturing references in a queued task?

**Candidate:** The current wait keeps local variables alive until completion. If a timeout lets the function return while the task still holds references, those references can dangle. A deadline requires redesigning task-state ownership.

**Interviewer, deeper:** Would adding wait_for alone solve the problem?

**回答依据：** 当前函数等待任务使局部仍活着；若加入超时返回而lambda还用引用，会悬空。参数值或共享任务状态需重新设计。 追问需要回模型、源调用或实验条件；不要自动添加个人性能数字。

## Round 7

**Interviewer:** Does a mutex guarantee valid shared state?

**Candidate:** A mutex protects concurrent access, but it does not establish freshness, semantic consistency or trust. Sequence numbers, timestamps and state versions address different problems.

**Interviewer, deeper:** Can a locked read still return an obsolete value?

**回答依据：** 互斥保证同一时刻不冲突，不保证读数新、语义一致或来源可信；需要序号时间戳版本。 追问需要回模型、源调用或实验条件；不要自动添加个人性能数字。

## Round 8

**Interviewer:** What does command idempotency mean?

**Candidate:** Retries with the same action identifier should not repeat the physical effect. A new identifier can represent a new action even if the value is unchanged. The result history needs a defined persistence policy.

**Interviewer, deeper:** Can you guarantee exactly-once execution after a crash?

**回答依据：** 同动作ID重试不重复物理作用，需保存结果；不是同value永远不再执行，新的ID可新动作。 追问需要回模型、源调用或实验条件；不要自动添加个人性能数字。

## Round 9

**Interviewer:** How would you substantiate the M-DDS or M-Robots claim?

**Candidate:** The named implementations have not been located in the current snapshot. I would retrieve the historical repository, commit, module paths and my changes instead of treating smart-farm code as equivalent evidence.

**Interviewer, deeper:** How would you explain that gap during an interview?

**回答依据：** 现有查找未定位对应实现，不能用smart_farm代替；需历史仓库提交、模块路径、消息IDL/日志及本人变更。 追问需要回模型、源调用或实验条件；不要自动添加个人性能数字。

## Round 10

**Interviewer:** Does the online flag set during initialization prove that the device is reachable?

**Candidate:** No. In this snapshot, BaseDeviceHandler can set the framework flag after OnInit succeeds, and property reporting can also affect it. I would check for a recent successful read or heartbeat with a timestamp.

**Interviewer, deeper:** What if the connection is open but the last measurement is stale?

**回答依据：** 连接状态和反馈新鲜度是两种状态；在线不自动证明最近数据可用于决策。

## Round 11

**Interviewer:** The ground-lock handler returns success after writing a register. Is the lock physically raised?

**Candidate:** Not necessarily. The handler updates a cached status after a successful write. I would verify a later register readback or position sensor before claiming physical completion.

**Interviewer, deeper:** How would you find an off-by-one register mapping?

**回答依据：** 对照起始地址、寄存器数量、返回数组布局、源码下标和设备寄存器表；当前源码取 allData[7]，注释说地址 0x0006。

## Round 12

**Interviewer:** A feedback frame has a newer sequence number. Is it necessarily fresh?

**Candidate:** No. Sequence order helps reject duplicates and out-of-order frames, while a sample timestamp tells me how old the measurement is. I need both checks.

**Interviewer, deeper:** Could an old frame be rejected while an action is still accepted?

**回答依据：** 可以。如果旧帧未覆盖缓存，而上一份缓存尚在 TTL 内，动作仍可能使用上一份有效状态；缓存过期后才拒绝。

## Round 13

**Interviewer:** What happens to queued tasks when this thread pool shuts down?

**Candidate:** I would not assume they are all drained. The worker loops check the shutdown flag, so pending work may remain unprocessed. I would inspect how pending promises are completed or cancelled and how waiting callers exit.

**Interviewer, deeper:** Does joining every worker prove that every command has a result?

**回答依据：** 不能。join 证明线程退出，不自动证明队列任务完成或每个 future 获得结果。

## Round 14

**Interviewer:** Does changing a polling interval immediately move the next scheduled run?

**Candidate:** The source does not necessarily do that. The interval is accepted in seconds and stored in milliseconds; the device-level setter updates the interval but leaves the current nextRunTime in place.

**Interviewer, deeper:** What timing fields would you log?

**回答依据：** 计划触发时刻、实际提交、worker开始/结束、跳过原因和下个计划时刻。

## Round 15

**Interviewer:** Can a high-priority command interrupt a polling task that is already inside a device read?

**Candidate:** No such preemption is shown. The source can remove pending long tasks or skip a long task before it starts, but a task already executing its handler or device I/O is not forcibly interrupted by the priority label.

**Interviewer, deeper:** What would you log to tell a cancelled poll from a slow poll?

**回答依据：** task ID/type、入队时刻、worker取出时刻、handler开始/结束、取消/跳过原因、设备请求时间。不要把“任务没上报”直接等同于“设备无响应”。

## Round 16

**Interviewer:** What happens to a cancellation record when a pending polling task is removed?

**Candidate:** In this snapshot, `ClearPendingLongTasks` sets the flag and pops the task, but does not erase the matching entry from `taskCancelFlags_`. The task no longer reaches the worker cleanup path. I would track the map size and clear count to see whether this causes persistent growth in a long-running process.

**Interviewer, deeper:** Would you call it a confirmed memory leak based on source inspection alone?

**回答依据：** 先称静态内存保留/增长风险；运行记录显示长期单调增长，且排除线程池对象重建与其他清理后，才据证据定性。

## Contribution challenge

**Interviewer:** Which part did you personally implement, and what evidence supports that?

**Candidate template:** My own contribution was [verified module and decision]. The available source supports [specific function or interface]. A separate teaching experiment helps me understand the principle, but I do not use it as evidence of historical deployment.

## Evidence challenge

**Interviewer:** Did the available version actually run on the robot?

**Candidate:** The source snapshot and the deployed version must be matched using a commit, configuration and execution record. I would distinguish what I can trace in this snapshot from what I can substantiate with my own project records.

## 复盘答案标准

每问记录：公式/单位是否正确，能否指出函数，个人动作是否明确，验证是否有数据，限制是否诚实，英文是否可理解。不会则明确不知道的部分并解释已知部分。下次优先补一项，不改写成“已掌握”。
