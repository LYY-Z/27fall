## CV/PS 项目主张怎样落到整机流程

面试时按简历中的实际表述逐项说明“输入是什么、代码在哪、输出去哪、有什么验证”：

| CV/PS 主张 | 可说明的项目实现 | 面试时的准确边界 |
|---|---|---|
| IMU 与轮速用于球形底盘动态平衡 | IMU 姿态/角速度回调、轮反馈滤波、fk 与位置/速度计算 | 轮速积分位置会漂移；当前路径没有全局定位校正 |
| 级联 PID | X/Y 位置环产生 Roll/Pitch 参考，Roll/Pitch/Yaw 内环形成控制量 | 当前检查的 C++ 周期走 PID；具体实机表现须以实际部署与日志为准 |
| LQR 模型分析 | linear_model 连续四状态模型、lqr_params 中的 Q/R、连续 LQR 候选 K 和 PID 形式系数转换 | 离线分析和增益参照；不是已证明的在线 LQR 部署。脚本的手工缩放也要说明 |
| URDF/Pinocchio CoM 重力前馈 | 双臂关节状态 → 模型 CoM → /com_pos → 底盘 Roll/Pitch 前馈 | 该底盘路径消费 CoM 位置；速度/加速度前馈不是同一事实 |
| ROS 到 CAN、命令新鲜度与跌倒恢复 | 控制器 ROS 发布、驱动取最新缓存命令、CAN 参数发送；倾角分支 reset | 最新队列减少积压不等于有年龄 watchdog；fall reset 也不独立证明发零或电机停机 |
| 固定双臂轨迹下维持平衡 | 项目材料描述的任务条件和定性结果 | 可讲观察到的任务结果；没有误差/电流日志时不报提升百分比、延迟或稳定裕度 |

CV 当前用语提到 command freshness。回答追问时要区分：源码中可见的 queue size 1 和驱动取最新缓存，有助于不处理积压命令；当前检查路径未证明按时间戳丢弃过期命令或自动安全停机。若本人另有实机 freshness 逻辑和记录，应指出对应版本、代码和日志；否则不要把“队列最新”升级成“有完整 watchdog”。
