# P4 术语与三种长度口述

## 使用边界

这是可练习的参考答案，不替用户确认个人职责。只有本人确实完成的动作才能用I implemented/I designed。现存团队/平台代码用the implementation；新教学用a separate learning experiment。结果数值需日志，没有则解释验证方法。

## 常用术语：先用中文讲动作，再说英文词

|中文|英文|先在脑中想成什么|
|---|---|---|
|滞回|hysteresis|湿度落在中间区间时泵保持原状态，避免读数抖动就开关|
|量化校准|quantization calibration|用代表性图片检查模型换成整数表示后输出是否还可信|
|结构化事件|structured event|把类别、分数、框、地点和时间装进有固定字段的数据|
|非极大值抑制|non-maximum suppression|多个框指向同一病斑时保留较可信的那个|
|规则快速路径|rule-based fast path|简单明确的条件满足时直接走短流程，不必问更复杂模块|
|人工覆盖|manual override|人在手动模式下明确接管自动动作|
|执行回执|execution acknowledgement|设备返回它收到了或处理了命令；是否真的完成还要看定义|
|边缘推理|edge inference|在靠近摄像头的设备上运行模型，而不是把图都送到云端|
|V4L2缓冲区|V4L2 capture buffer|摄像头与程序轮流使用的一块帧内存；取出已填好的帧，处理后归还给驱动|
|长宽比补边|letterbox|保持图像比例缩小，再补边到模型尺寸；框坐标还原时要扣掉补边|
|吞吐率|throughput / FPS|每秒处理多少帧；不等同于一帧从拍摄到设备动作的等待时间|
|端到端延迟|end-to-end latency|从明确起点到明确终点的总等待时间，必须说清计时边界|
|TCP分帧|TCP message framing|从连续字节中恢复一条条应用消息；TCP的send/recv边界不是消息边界|
|事件队列|event queue|暂存等待Agent处理的事件；有限队列满时要说明丢弃、背压或优先级策略|
|向量检索|vector retrieval|把文字转成向量后按语义相似度找相关知识；可用不等于每次命中都正确|
|幂等命令|idempotent command|同一命令重复到达时，不会重复产生额外物理效果|
|设备确认|device acknowledgement|设备对命令接收/处理的反馈；还要区分软件确认与实际水流证据|

口述时用一条完整事件讲这些词：相机看见病斑→形成带时间的事件→服务给建议→设备返回执行状态。总览见[P4白话总览](../00_项目全貌与学习路线/03_P4端到端数据与执行链.md)。

避免把“模型算得快”“Agent生成了动作”“服务器写了executed日志”直接说成“泵已经可靠浇水”。按证据逐级讲：检测结果→策略建议→命令派发→设备接收→电气输出→流量/水分变化。更多面试练习见[Q26–Q36](02_原理实现与验证问答.md#p4-q26)。

公式读法与澄清句见[技术英语](../../../04_面试训练/01_技术英语/01_术语单位公式与矩阵读法.md)。

## 30秒：先让面试官听懂问题

This smart-gardening system connects local irrigation control, edge visual detection and a server-side decision workflow. The design separates fast local actuator behavior from richer remote interpretation and user interaction.

中文主线：系统是什么→要解决什么→关键方法。实际速度因人而异，30秒是训练目标，需自己计时。

## 90秒：加入方法和实现边界

This smart-gardening system connects local irrigation control, edge visual detection and a server-side decision workflow. The design separates fast local actuator behavior from richer remote interpretation and user interaction.

The local moisture controller uses different start and stop thresholds to avoid rapid switching. The vision path converts YOLO outputs into structured observations. The graph workflow combines deterministic rules with model-assisted decisions and limits the available commands.

My contribution should identify the exact module and decision I made. Neither a successful model export nor a server broadcast alone proves accuracy, execution or end-to-end reliability.

中文主线：问题→数据链→方法理由→一个实现点→证据边界。讲到复杂术语后留一句直觉解释，不一次报完技术栈。

## 3分钟：模型、实现、验证与反思

This smart-gardening system connects local irrigation control, edge visual detection and a server-side decision workflow. The design separates fast local actuator behavior from richer remote interpretation and user interaction.

The local moisture controller uses different start and stop thresholds to avoid rapid switching. The vision path converts YOLO outputs into structured observations. The graph workflow combines deterministic rules with model-assisted decisions and limits the available commands.

The source includes RKNN INT8 conversion for RK3588, active-low pump GPIO control, and a LangGraph rule fast path. I distinguish an execution summary from a hardware acknowledgement, and model deployment from proof of training ownership.

I would assess irrigation switching, stale-data rejection, detection quality, event-to-command latency and verified actuator outcomes. Sensor scaling, calibration data and timestamps must be recorded before interpreting a result.

My contribution should identify the exact module and decision I made. Neither a successful model export nor a server broadcast alone proves accuracy, execution or end-to-end reliability.

中文主线：模型输入输出/假设→一个实际函数链→一个已能解释的限制→怎样量化→个人贡献。不要将教材里的“会做”变成历史“做过”。

## 在口述中插入自己的贡献

确认职责后用：“My responsibility was [specific module]. I chose [method] because [reason]. I checked it using [actual data and metric]. The main limitation was [observed limitation].”

方括号必须用本人事实替换。没有记录则说：“I can explain the design, but I do not have a verified measurement for that performance claim.”
