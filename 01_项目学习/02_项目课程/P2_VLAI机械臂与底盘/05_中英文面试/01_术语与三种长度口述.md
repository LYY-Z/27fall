## 常用术语：先用中文讲动作，再说英文词

|中文|英文|先在脑中想成什么|
|---|---|---|
|遥操作|teleoperation|人动控制器，机器人按映射后的目标跟着动|
|相对位姿|relative pose|从按键那一刻开始，手柄后来移动了多少|
|坐标对齐|frame alignment|把手柄坐标里的方向换成机器人听得懂的方向|
|末端目标|end-effector target|希望机械臂手掌/工具尖端去到的位置和朝向|
|微分逆运动学|differential inverse kinematics|每个控制小步求关节速度，让手端往目标靠近一点|
|任务权重|task weights|多个目标冲突时，告诉求解器哪个目标更重要|
|阻尼最小二乘|damped least squares|在优化中惩罚大动作，接受一些末端误差；不等于硬速度上限|
|关节限位|joint limits|每个关节允许转动的范围|
|重力补偿|gravity compensation|电机先承担一部分手臂自重，操作者不必一直硬托住|
|主从机械臂|leader-follower arms|人拖动主臂，控制器把参考传给跟随臂|
|里程计|odometry|用轮子转动估计车走了多少，打滑时会偏|
|目标保持|target holding|没有新目标时仍维持已经选定的位置/姿态|

## 90秒：加入方法和实现边界

This project includes VR-based arm teleoperation, leader-follower control and a two-wheel base. The main idea is to convert human motion into consistent robot targets, solve the arm motion locally and execute it through a defined motor interface. The source versions for these subsystems need to be distinguished.

VR control is relative to the pose captured at activation. Translation is aligned and scaled, while the relative rotation updates the initial end-effector orientation. In the simulation path, Mink forms frame and posture tasks, solves differential IK and integrates joint velocity. The leader-follower path is different: the leader uses URDF-based gravity torque to support manual motion, while the follower receives mapped position and velocity references.

## 3分钟：模型、实现、验证与反思

This project includes VR-based arm teleoperation, leader-follower control and a two-wheel base. The main idea is to convert human motion into consistent robot targets, solve the arm motion locally and execute it through a defined motor interface. The source versions for these subsystems need to be distinguished.

VR control is relative to the pose captured at activation. Translation is aligned and scaled, while the relative rotation updates the initial end-effector orientation. In the simulation path, Mink forms frame and posture tasks, solves differential IK and integrates joint velocity. The leader-follower path is different: the leader uses URDF-based gravity torque to support manual motion, while the follower receives mapped position and velocity references.

The independent IK solver updates its configuration from current joints, sets a posture target, creates left and right SE3 targets and calls the QP backend. It returns the current state if solving raises an exception. I still need to check residual pose errors, because a small joint update can mean convergence or stagnation. In the C++ source, KDL computes gravity from a selected URDF chain. Leader and follower branches build different MIT command fields. Joint-to-motor conversion must account for signs and offsets. The local base board uses EZ_RTOS; its upstream PID calculation is commented out in the inspected path.

I would first check relative-pose continuity, coordinate axes, joint limits, solver status and feedback freshness. Near singular configurations, I would compare joint-rate magnitude with end-effector residual. Damping reduces amplification but does not replace collision or velocity constraints. For the base, I would separately validate body-to-wheel kinematics, measured odometry and the upper-level ROS bridge. A device command and a successful simulated target are not the same as confirmed hardware motion.

The installed historical Mink version and the complete base ROS2 deployment path are not established by this snapshot. The new relative-pose, damped-IK and gravity scripts are teaching examples rather than historical system evidence.

中文主线：模型输入输出/假设→一个实际函数链→一个已能解释的限制→怎样量化→个人贡献。不要将教材里的“会做”变成历史“做过”。

## 在口述中插入自己的贡献

确认职责后用：“My responsibility was [specific module]. I chose [method] because [reason]. I checked it using [actual data and metric]. The main limitation was [observed limitation].”

方括号必须用本人事实替换。没有记录则说：“I can explain the design, but I do not have a verified measurement for that performance claim.”
