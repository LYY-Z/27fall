## P4-Q02 滞回是什么？

**Question:** What is hysteresis in irrigation control?

**中文理解与答法：** 低于启动阈值开，高于停止阈值关，中间保持之前状态；源码56/65配置不等于所有土壤通用阈值。

**English reference:** Different start and stop thresholds prevent rapid switching near one boundary. Between the thresholds, the previous pump state is retained. The source values are configuration values, not universal soil thresholds.

## P4-Q26 V4L2 的缓冲区为什么要“取出再归还”？

**Question:** Why does a V4L2 capture loop dequeue and re-queue buffers?

**中文理解与答法：** 摄像头把一帧写进驱动管理的缓冲区。程序用 `DQBUF` 暂时拿到这块已填好的缓冲区，读取/处理完后用 `QBUF` 还回去，让摄像头继续复用。忘记归还，缓冲区会逐渐用完；拿着它处理很久，也可能让后续帧排队变旧。源码路径是申请并映射缓冲区、排队、等待、取帧、读数据、重新排队。这个生命周期描述的是驱动缓冲区所有权，不是“复制一张永远归程序所有的图片”。

**English reference:** The camera driver owns a pool of buffers. The application dequeues a completed frame, consumes it, and queues the buffer back so capture can continue. Holding buffers too long can reduce throughput or increase frame age.

**Follow-up:** What would you measure to detect a capture backlog? 记录采集时间、处理开始时间、缓冲区等待时间和实际帧率，并检查驱动队列是否持续积压。

## P4-Q27 resize 和 letterbox 有什么区别？

**Question:** How do direct resizing and letterboxing differ?

**中文理解与答法：** 直接resize把任意宽高的图拉成模型固定尺寸，简单但会改变物体形状；letterbox按同一比例缩放，再在空白处补边，保留形状但要记录缩放比例和边缘偏移，才能把检测框换回原图。当前核对的RK代码直接调用 `cv::resize` 到模型尺寸；letterbox是常见替代方案，不应误说成此源码正在使用。

**English reference:** Direct resizing maps the image to the model dimensions and may distort its aspect ratio. Letterboxing preserves the aspect ratio and adds padding, so post-processing must remove that padding when restoring box coordinates. The checked source uses direct resizing.

**Follow-up:** Why might boxes be wrong even when the class is correct? 预处理和坐标还原若使用了不同的缩放/补边规则，框的位置和大小会偏移。

## P4-Q28 FPS 高是否代表响应快？

**Question:** Does a high FPS guarantee low end-to-end latency?

**中文理解与答法：** 不保证。FPS表示单位时间处理多少帧；单帧延迟表示一帧从某个起点到终点用了多久。摄像头等待、图像转换、网络、排队、Agent处理和设备响应都可能让端到端延迟很高。源码中的推理计时区间只包住RKNN输入设置到输出读取，不等于拍摄至水泵反馈的时间。

**English reference:** No. FPS measures throughput, while latency measures the time for a particular observation to pass through a defined path. I would timestamp capture, preprocessing, inference, server receipt, decision, dispatch and device feedback separately.

**Follow-up:** Can a pipeline have high FPS and still react slowly? 可以；如果队列里处理的是旧帧，吞吐量高也可能伴随很大的数据年龄。

## P4-Q29 为什么服务端既有线程又有 asyncio？

**Question:** Why does the server combine threads and asyncio?

**中文理解与答法：** TCP接收使用阻塞式线程，而Agent/WebSocket侧使用asyncio事件循环。线程可独立等待网络数据；异步任务在等待网络时让出事件循环，继续处理其他任务。跨线程把事件送入asyncio队列要用线程安全调度。asyncio不是自动多核并行：CPU密集型推理或长同步函数仍可能阻塞事件循环。

**English reference:** The TCP side uses blocking I/O in threads, while the agent and WebSocket side use an asyncio loop. Cross-thread events must be scheduled safely. Async I/O improves concurrency for waiting tasks; it does not automatically parallelize CPU-bound work.

**Follow-up:** What happens when the bounded event queue is full? 当前桥接器会记录队列满并丢弃新事件；系统要监测丢弃、定义优先级或背压策略，不能假设所有事件都会处理。

## P4-Q31 去重是否保证命令只执行一次？

**Question:** Does event deduplication guarantee exactly-once actuator execution?

**中文理解与答法：** 不保证。当前内存去重可在一定时间窗内挡住同一事件再次进入图，但它不是持久事务，也没有覆盖网络重试、服务器重启、命令执行中断和设备端重复动作。事件去重是“少处理重复事件”；命令幂等是“重复收到同一命令也不重复产生效果”；二者还需要命令ID、设备确认、持久状态和恢复规则。

**English reference:** No. In-memory event deduplication reduces repeated graph processing within its scope and time window. Exactly-once physical effects require stronger command identifiers, durable state, device-side idempotency and acknowledgement/recovery semantics.

**Follow-up:** What if the device performed the action but its reply was lost? 重发前先依据关联ID查询或确认设备状态；若做不到，要采用安全的幂等动作或人工处理，不能盲目重复开泵。

## P4-Q32 设备时间戳和服务接收时间有什么不同？

**Question:** What is the difference between an observation timestamp and a server receive timestamp?

**中文理解与答法：** 采样时间回答“设备何时测到”；接收时间回答“服务器何时收到”。两者相差网络和排队延迟。设备时钟还可能没有同步。当前Hi3861事件时间戳为0，RK事件使用设备系统时间，而服务端存储快照时会写入服务器时间。因此不能把接收时间冒充采样时间，也不能未经时钟校正就直接相减。

**English reference:** A device timestamp marks when an observation was produced; a receive timestamp marks when the server received it. Clock synchronization and transport delay matter. A server receive time cannot replace a missing device capture time.

**Follow-up:** How would you reject stale observations across unsynchronized clocks? 优先测量并维护时钟偏差，或使用同设备单调时钟与接收侧延迟估计；若无法建立可靠年龄，就把新鲜度标成未知并禁止其触发高风险动作。

## P4-Q33 TCP两端的消息格式完全一样吗？

**Question:** Do both device links use the same TCP framing?

**中文理解与答法：** 不一样。RK视觉端给每个payload加4字节大端长度；一帧视觉数据又按类型、JSON长度、JSON、图像类型、图像长度、JPEG等分段发送。Hi3861传JSON字节流，服务端按JSON大括号边界拼接，没有使用同一种长度前缀。TCP本身只保证有序字节流，不定义应用消息边界。

**English reference:** No. The RK vision link uses length-prefixed payloads, while the Hi3861 JSON stream is reconstructed with a different parser. TCP itself provides bytes, not application-level messages, so each receiver must match its sender's framing exactly.

## 追问答案补全：P4-Q01–Q25

Q26–Q36 的追问答法已写在各题后；下面补齐 Q01–Q25 原先只留英文提示的部分。与设备安全有关的回答区分当前代码能证明的行为和建议的工程设计。

- **P4-Q01：Which behavior is actually implemented during disconnection?** 本地传感器阈值循环可独立于服务器处理，因此基础本地控制不应依赖云端LLM；远程链路断开时具体保持、超时关闭还是继续旧状态，要追踪设备回调、状态变量和watchdog。没有明确证据就不能声称断网必然安全关泵。
- **P4-Q02：What happens at exactly the threshold?** 若条件是严格 `<56` 才开启、严格 `>65` 才关闭，则恰好等于56或65都不满足转换条件，泵状态保持不变。核对源码比较符号；边界的行为不是“差不多”。
- **P4-Q03：Would a wider dead band always be better?** 不会。更宽可减少阈值附近频繁开关，但会容许更大的湿度变化、延迟响应；阈值要根据传感噪声、土壤、植物需水和最短开关时间实验确定。
- **P4-Q04：How would you represent a persistent manual stop?** 用明确的模式/锁存状态，例如 `MANUAL_OFF`，优先级高于语音、自动规则和Agent建议；只有显式人工解除后才能回自动。不能把一次性的 off 命令当成永久禁止，除非状态机确实这样保存。
- **P4-Q05：What state should the pin have during boot?** 由于继电器是低有效，启动时应先把输出配置到高电平的关闭态，再启用自动控制；还需检查芯片复位期间引脚浮空、外部上拉和继电器上电默认状态，避免程序初始化前误吸合。
- **P4-Q06：How would you collect calibration data?** 在多种土壤、湿度和供电条件下记录ADC原始码，同时用称重/烘干等参考方法得到含水量标签；重复采样并保留设备、温度和传感器位置。训练/阈值标定数据与最终评估数据分开。
- **P4-Q07：How would a color-order error affect detection?** 模型若按RGB训练、输入却是BGR，三个通道语义错位，颜色特征会系统性改变，类别分数和框质量可能变差。需固定颜色转换并用已知图像逐像素核验。
- **P4-Q08：What could cause a false negative?** 光照/遮挡/模糊、输入尺寸或颜色顺序错误、letterbox逆变换错误、置信阈值过高、类别索引映射错、量化误差、模型分布不匹配或帧过旧都可能漏检。先从原始帧、模型输入和后处理逐层排查。
- **P4-Q09：How would you evaluate the confidence threshold?** 在带标注且未用于校准/训练的代表性数据上扫阈值，画precision-recall曲线并按误报与漏报成本选点；分设备、场景和类别统计。单独挑几张成功图不能证明阈值合适。
- **P4-Q10：What is intersection over union?** 两个框的IoU是交集面积除以并集面积，范围0到1；越大重叠越多。NMS通常在同类别候选之间用它判断是否重复，但阈值、类别处理和框坐标必须一致。
- **P4-Q11：Why can outliers make calibration difficult?** 极端像素/激活会扩大量化范围，使大多数常见值只占很少的整数级，分辨率变差；若直接裁掉又可能让真实极端输入饱和。应检查分布、代表性和精度影响，不能只为数字好看删异常样本。
- **P4-Q12：How would you check accuracy after quantization?** 同一独立测试集、同一预处理和后处理下比较FP32与INT8的precision/recall、mAP或任务指标，查看按类别和场景的差异；同时测板端延迟、内存和功耗，记录模型/工具版本。
- **P4-Q13：Which measurements would you collect on the board?** 记录预处理、推理、后处理和端到端延迟的分布，实际FPS、队列积压/丢帧、CPU/NPU负载、内存峰值、温度、功耗及准确性。平均FPS无法描述尾延迟和老帧问题。
- **P4-Q14：What training records would support such a claim?** 数据集版本/来源、标签与划分、训练配置、随机种子、训练日志、权重/checkpoint、验证指标和复现实验记录。只存在 `best.onnx` 或部署文件，不能证明谁训练了模型。
- **P4-Q15：Which fields must be mandatory?** 至少要有schema版本、唯一事件ID、设备/相机ID、检测发生时间或明确的时间未知标志、图像尺寸、类别、置信度、原图坐标框和数据来源；缺失字段应拒绝或标注未知，不能静默填一个看似可信的默认值。
- **P4-Q16：How would you handle unsynchronized devices?** 优先同步时钟并记录时钟偏差；同设备内部用单调时钟量间隔，服务端另记接收时间。无法校准时，不把两端绝对时间直接相减，且将事件新鲜度标为未知并限制自动执行。
- **P4-Q17：Can a single recv call return a complete frame reliably?** 不能。TCP只提供有序字节流，一帧可能拆进多次 `recv`，多个帧也可能合并在一次返回；接收器必须按长度/状态机循环收齐，并处理超长、断连和超时。
- **P4-Q18：What would happen if the receiver expected a different order?** 它会把字段错位解释，导致长度错误、JSON/图像错配、阻塞等待或内存越界风险。用协议文档和两端实际 `send/recv` 顺序逐字段核对，再测试碎片和合并读取。
- **P4-Q19：Which node actually selects the next branch?** LangGraph 的条件边/路由函数根据共享 State 决定下一个节点；节点负责更新状态或生成结果。要追踪图的编译入口、条件函数和分支目标，不能把“有多个节点”理解为它们全部都会执行。
- **P4-Q20：How would you resolve contradictory rules?** 先定义优先级和互斥条件，例如安全/人工停止优先于自动浇水，传感器无效时禁止自动动作；用规则表和状态转换测试覆盖冲突。不要让节点顺序偶然决定安全优先级。
- **P4-Q21：What if the proposal conflicts with a manual stop?** 人工停止必须作为执行门中的硬拒绝条件，Agent建议只能作为非授权提议；记录拒绝原因，且不能因置信度高或规则快速路径而绕过停止锁存。
- **P4-Q22：Does in-memory deduplication survive a restart?** 不会。进程重启后内存集合清空，重发事件可能重复触发；需持久化事件/命令ID和处理状态，并为动作设计幂等键与过期策略。即便持久化也要考虑并发原子性。
- **P4-Q23：Can an acknowledged command still fail physically?** 可以。ACK可能只确认网络接收或软件接受；GPIO可能未改变，继电器/泵可能损坏、断水或堵塞。要分级记录设备状态和电流/流量等物理反馈。
- **P4-Q24：How would you prevent a stale snapshot from triggering an action?** 保存源时间、接收时间、序列号和最大年龄；决策时重查新鲜度、设备在线/模式和最新人工状态，过期就拒绝并请求新观测。消息到达服务器不代表观测仍适合控制。
- **P4-Q25：Which metric would you prioritize for irrigation reliability?** 先定义“可靠”：例如误浇水率、缺水漏浇率、成功执行率和故障安全关闭率；同时报告响应时延、耗水量和每次开关次数。具体优先级取决于误浇与漏浇的代价，不能只报检测准确率。
