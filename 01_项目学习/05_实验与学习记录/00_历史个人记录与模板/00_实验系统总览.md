# 实验与记录系统总览

实验不是为了“做出一张好看的曲线”，而是为了回答一个明确问题：

~~~text
某个算法或工程机制是否真的改善了机器人表现？
如果改善，改善了什么？
如果没有改善，最早异常出现在哪里？
~~~

没有硬件时，可以用 NumPy、仿真、离线数据和故障注入完成绝大多数理解训练；有硬件时，再验证执行器、总线、接触和安全边界。

---

## 1. 零基础先理解“实验是什么”

实验不是随便运行一次程序，而是一个可比较的过程。

~~~text
提出问题
→ 固定条件
→ 改变一个主要变量
→ 记录输入和输出
→ 计算指标
→ 与基线比较
→ 解释结果和局限
~~~

例如问题是“低通滤波是否改善云台角速度估计”：

- 基线：不加低通滤波；
- 改变量：只改变滤波截止频率；
- 保持：同一段原始 IMU 数据、同一控制器和同一采样周期；
- 观察：噪声标准差、相位延迟、姿态跟踪误差；
- 结论：噪声是否下降，以及延迟是否增加。

如果同时改了滤波器、PID 增益和控制周期，就无法知道结果到底由谁造成。

---

## 2. 每个实验必须有六个核心元素

| 元素 | 需要回答的问题 | 示例 |
|---|---|---|
| 问题 | 这次要证明什么？ | 腿长变化时姿态是否仍稳定 |
| 输入 | 程序真正收到什么？ | IMU、关节角、速度参考 |
| 处理 | 算法按什么顺序运行？ | 滤波 → 状态估计 → VMC |
| 输出 | 算法真正产生什么？ | 足端力、关节力矩、姿态 |
| 指标 | 用什么判断变好？ | RMSE、峰值、延迟、失败率 |
| 结论 | 结果支持到什么程度？ | 某参数减少误差但增大力矩 |

## 3. 输入、输出和指标的区别

### 3.1 输入

输入是实验开始前或运行时提供给算法的数据，例如：

~~~text
状态：位置、速度、姿态、关节角
参考：目标位置、目标速度、目标姿态
参数：增益、阻尼、限幅、预测步长
环境：障碍、接触、负载、网络延迟
~~~

### 3.2 输出

输出是算法计算出的中间量或执行命令，例如：

~~~text
滤波后的状态
规划路径
局部轨迹
轮速目标
关节力矩
CAN 帧
保护状态
~~~

### 3.3 指标

指标把一段曲线变成可以比较的数字：

~~~text
均方根误差 RMSE
最大绝对误差
稳态误差
上升时间
超调量
控制输出峰值
周期抖动
P95/P99 延迟
失败率
恢复时间
~~~

指标必须先定义。比如“延迟”要说明是采样到控制、控制到发送，还是从传感器时间戳到执行反馈。

## 4. 推荐的五级执行顺序

### 第 1 级：手算

用很小的数字验证公式。例：

~~~text
目标速度 = 1.0
反馈速度 = 0.8
比例增益 = 0.5
比例输出 = 0.5 × (1.0 - 0.8) = 0.1
~~~

### 第 2 级：离线最小代码

先不接 ROS、CAN 或硬件，只用固定数组验证算法输入和输出。这样能把数学问题和接口问题分开。

### 第 3 级：仿真

加入动力学、噪声、限幅、延迟和环境约束。仿真结果必须说明模型假设。

### 第 4 级：故障注入

主动加入：

~~~text
噪声
延迟
丢帧
时间戳停止
坐标轴错误
单位错误
执行器饱和
状态切换
~~~

观察最早异常信号，而不是只看最终是否失败。

### 第 5 级：低风险实机

满足以下条件再上实机：

~~~text
最小代码已经通过
单位和方向已经确认
输出有硬限幅
有急停或断电方案
测试速度和幅度从小开始
有人观察并能立即停止
~~~

## 5. 一个完整记录范例：轮速闭环

### 5.1 问题

验证轮速反馈是否比固定 PWM 更能抵抗负载变化。

### 5.2 条件

~~~text
参考速度：10 rad/s
初始反馈：8 rad/s
控制周期：待测
输出上限：待测
负载：轻载、中载
对照组：固定 PWM
实验组：速度 PID
~~~

### 5.3 运行流程

~~~text
读取目标速度
→ 读取轮速反馈
→ 计算误差
→ 计算 PID 输出
→ 执行输出限幅
→ 记录目标、反馈、原始输出、实际输出
→ 施加相同负载
→ 比较两组曲线
~~~

### 5.4 应记录的字段

~~~text
timestamp
target_speed
measured_speed
error
pid_output_raw
output_after_limit
current_or_power
feedback_age
mode
fault_code
~~~

### 5.5 如何计算 RMSE

假设一共有 N 个采样点：

~~~text
e_i = target_i - measured_i
RMSE = sqrt((e_1² + e_2² + ... + e_N²) / N)
~~~

RMSE 越小表示整体跟踪误差通常越小，但它不能单独说明没有超调或尖峰，所以还要记录最大误差和稳态误差。

### 5.6 结果怎样写

不要只写“PID 效果更好”。应写成：

~~~text
在相同参考和负载下，PID 组的 RMSE 为待测值，
固定 PWM 组的 RMSE 为待测值；PID 组在负载变化后
恢复到稳态的时间为待测值。结论仅适用于本实验的速度范围、
控制周期和输出限制。
~~~

## 6. 故障注入怎么记录

一个故障实验至少回答四件事：

1. 我主动改变了什么；
2. 正常系统原本会怎样；
3. 最早异常信号是什么；
4. 保护和恢复是否符合预期。

### 例：反馈时间戳停止更新

~~~text
注入：数值仍在发布，但时间戳固定
正常：状态年龄随时间增加
最早异常：age 超过阈值
保护：停止使用旧反馈，限制输出或停车
恢复：收到连续新鲜反馈后重新使能
~~~

不要只记录“系统停了”。“为什么停、哪一层发现、多久触发、怎样恢复”才是工程证据。

## 7. 没有数据时的规范

不能把学习参数或假设结果写成真实测量：

~~~text
指标：端到端延迟
定义：消息采样时间到执行反馈时间的差值
测量：记录采样、解析、控制、发送、执行和反馈时间
统计：平均值、中位数、P95、P99、最大值
当前状态：尚未测量
~~~

可以使用演示数字帮助学习，但要在记录中标明“示例”。真实项目数字必须来自日志、示波器、总线记录或可复现实验。

## 8. 七项目实验入口

| 项目 | 首组实验 | 要回答的问题 |
|---|---|---|
| P1 | 单轴平衡、三轮分配、质心前馈 | 控制器为什么能稳定，双臂扰动如何影响它 |
| P2 | 位姿映射、阻尼 IK、主从补偿 | 末端目标怎样变成连续关节运动 |
| P3 | 轮速、云台、发射和功率限制 | 多执行器怎样在总线和功率约束下协同 |
| P4 | 检测质量、INT8、端云边和本地保护 | 感知结果怎样安全转成设备动作 |
| P5 | 定位、Hybrid-A*、TEB 和跟踪 | 导航问题来自定位、规划还是执行 |
| P6 | CAN 解析、任务周期、掉线恢复 | 平台层怎样保证状态可靠和命令安全 |
| P7 | FK、Jacobian、VMC 和轮腿协调 | 腿长与接触变化时怎样保持稳定 |

## 9. 最终实验包

每个项目完成后，建议形成：

~~~text
01_实验记录.md
02_参数表.md
03_原始数据或数据生成脚本
04_关键曲线
05_故障前后对照表
06_中文 2 分钟口述
07_英文简短口述
08_结论与未解决问题
~~~

一个实验包不要求每次成功，但必须可以让另一个人理解：

~~~text
你测了什么
你怎样测的
你观察到了什么
你能确定什么
你还不能确定什么
下一步如何验证
~~~

## 10. 最终检查表

提交或用于面试前逐项检查：

- 是否说明实验问题和基线；
- 是否只改变一个主要变量；
- 是否记录原始输入和最终输出；
- 是否记录时间戳、周期和状态年龄；
- 是否定义误差和延迟的计算方式；
- 是否区分仿真、离线、实机和待测；
- 是否记录异常现象和排查顺序；
- 是否解释结论的适用范围；
- 是否能够把曲线讲回机器人任务；
- 是否能回答如果结果相反，下一步怎么办。
