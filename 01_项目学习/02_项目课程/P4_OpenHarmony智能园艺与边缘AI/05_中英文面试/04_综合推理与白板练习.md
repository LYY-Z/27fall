# P4 综合推理、白板与源码追问

本页补充原25道主问，不重编号。每个场景按“中文理解→纸笔中间量→英语口述→源码追问”练；英文用客观源码/教学事实，个人经历句只按贡献证据填写。不要把参考答案当成自己已经完成的实验。

如果公式一眼看不懂，先不要硬算：把每个符号旁边写上“它代表什么、单位是什么、是谁给的”，用箭头画出数据变化，再用一个很小的数字手算。完成中文因果说明后，再练英文表达。综合主线可返回[项目白话总览](../00_项目全貌与学习路线/03_P4端到端数据与执行链.md)。

## 使用顺序

1. 用中文回答主问，画输入→计算→输出；写形状、单位、时刻。
2. 对照数字与原源码，指出假设和启用分支。
3. 用英语说45—90秒，回答第二层追问。
4. 记录卡住的是基础、项目、证据还是表达；下次只补对应环节。

## 场景1：ADC不是直接湿度

**Interviewer:** What does the moisture percentage represent?

### 先用中文把因果与中间量讲清

源h=−.05*ADC+147.52，转int16并clip0…100。ADC1800→57.52→57，属于软件映射；未校准不能称体积含水率。泵GPIO低有效，逻辑on与电平0必须区分。

### Candidate：英语参考

The value is a software-scaled sensor reading, not a calibrated volumetric water content. I trace the conversion and the active-low output before interpreting a pump command.

**Follow-up:** How could calibration change the thresholds?

中文追问答案：用实际土壤/传感器采样建立映射和不确定性，56/65在原scale内解释，不能直接跨设备沿用。

验收：能指出上述结论的源函数或教学假设；没有运行数据时，只说手算/静态所见，不补性能数字。

## 场景2：滞回状态记忆

**Interviewer:** Why keep a previous pump state?

### 先用中文把因果与中间量讲清

低于56开、高于65关，中间保持。55/60/64/66/60→on/on/on/off/off；相等时严格不触发。manual模式与voice等输入优先级从源实际调用读，新教学增加invalid/stale off不能升级源事实。

### Candidate：英语参考

Hysteresis uses memory between two thresholds. It prevents the pump from toggling around a single noisy boundary. I separately trace manual and voice behavior because those paths can override automatic operation.

**Follow-up:** Why is one threshold prone to chatter?

中文追问答案：噪声每次跨同一个阈值使状态反复切换；双门槛形成保持带。

验收：能指出上述结论的源函数或教学假设；没有运行数据时，只说手算/静态所见，不补性能数字。

## 场景3：视觉链与量化

**Interviewer:** Does converting a detector prove that you trained it?

### 先用中文把因果与中间量讲清

不证明；RK输入640、INT8均值0/std255描述转换/推理，训练数据、权重、训练日志与作者另查。框还需逆letterbox回原图，事件可信度与时效独立。

### Candidate：英语参考

Model conversion, inference integration and training are different contributions. I can explain the RKNN input and quantization settings in the available source, but training ownership needs separate evidence such as datasets and training records.

**Follow-up:** What would you compare after INT8 conversion?

中文追问答案：同数据下浮点/量化输出、精度指标、时延与内存，不能编造未测数字。

验收：能指出上述结论的源函数或教学假设；没有运行数据时，只说手算/静态所见，不补性能数字。

## 场景4：timestamp和消息边界

**Interviewer:** Why can a high-confidence detection still be unusable?

### 先用中文把因果与中间量讲清

now10/sample8/maxage1→age2，过期，即使confidence.99也拒绝。源传感timestamp0并非真实新采样证明，RK事件字段location/time/bbox需适配到教学schema。TCP是字节流，长度字段/read循环决定帧边界，单次recv不保证整条。

### Candidate：英语参考

Confidence does not encode freshness. I need a valid acquisition time, schema and coordinate convention before using a detection for an action. TCP framing also needs explicit message boundaries because a receive call is not a message boundary.

**Follow-up:** Can a filtering algorithm repair a wrong clock?

中文追问答案：不能；先时钟同步/时间适配，滤波参数不解决timestamp语义。

验收：能指出上述结论的源函数或教学假设；没有运行数据时，只说手算/静态所见，不补性能数字。

## 场景5：Agent执行语义

**Interviewer:** Does an agent summary mean the pump has acted?

### 先用中文把因果与中间量讲清

否。proposal、policy通过、发送、接收ACK、设备反馈是多阶段。源六节点有规则快路，eventid:scope60s去重在analysis前写记录，不等于执行成功只一次；摘要不是硬件ACK。

### Candidate：英语参考

An agent can propose or summarize an action without proving physical execution. I distinguish policy approval, message transmission, acknowledgment and device feedback. Event deduplication before analysis does not provide persistent exactly-once actuation.

**Follow-up:** What is the missing evidence for physical completion?

中文追问答案：动作ID关联设备反馈、实际泵状态/流量及时间，不是仅字符串“已执行”。

验收：能指出上述结论的源函数或教学假设；没有运行数据时，只说手算/静态所见，不补性能数字。

## 场景6：综合闭环

**Interviewer:** Explain local control versus edge reasoning.

### 先用中文把因果与中间量讲清

Hi3861传感与泵本地状态机，RK摄像/YOLO事件，规则/LangGraph建议与策略，消息接口返回本地，反馈确认。网络丢失时是否仍执行安全本地行为必须按实码查；教学无网络回放不能替代。

### Candidate：英语参考

Local sensing and pump control form one loop, while edge vision and reasoning provide additional information and proposals. I describe the interface between them and verify mode, freshness and device feedback before treating a proposal as an executed action.

**Follow-up:** Which part belongs in a robotics interview versus CS?

中文追问答案：机器人重传感/动作/闭环，CS重schema/协议/状态机/量化/幂等；同事实不同解释重点。

验收：能指出上述结论的源函数或教学假设；没有运行数据时，只说手算/静态所见，不补性能数字。

## 场景7：从检测到水泵反馈，接口是否真的闭合？

**Interviewer:** The server logged an irrigation action as executed. How would you verify the claim?

### 先用中文把因果与中间量讲清

先不要把`executed`当作水泵已动作。逐步查：检测/传感事件何时采样，服务器何时收到，Agent是否通过策略，命令是否入队和发出，设备解析了什么动作字符串，设备是否回报状态，是否有GPIO/电流/流量证据。静态快照中服务器发`start/stop`，设备解析`water_on/water_off`，须先核对适配；动作日志在派发之前写入。故当前材料支持“发现接口风险”，不支持“实机已经失败”或“水泵已成功运行”。

### Candidate：英语参考

I would trace the action from the original observation to the physical actuator. In the reviewed snapshot, the server and device use different action names, and the action log is written before dispatch. I would call this a static integration risk, then verify the protocol adapter, device acknowledgement and physical pump feedback before claiming successful watering.

**Follow-up:** Would a `watering=true` report prove that water flowed?

中文追问答案：它是设备软件上报的逻辑泵状态，不是流量测量。还要说明数据关联ID和时间；要确认出水需流量/压力/泵电流等独立物理证据。

验收：把建议、命令、设备确认、逻辑状态和物理水流分开；静态观察与实机结果分开；不替项目补写未证实的适配器。
