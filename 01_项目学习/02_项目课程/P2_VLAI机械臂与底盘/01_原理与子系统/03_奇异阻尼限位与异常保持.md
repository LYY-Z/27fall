# P2 奇异、阻尼、QP 与关节限制

## 本章要回答什么

VR 手柄给出 TCP（工具中心点，也就是手腕末端）的目标。逆运动学要决定多个关节怎样配合。多数时候有一组解能让 TCP 朝目标走；但有些姿势会让某个方向特别难动。普通反算可能因此要求关节转得极快。阻尼会压低这类过大的关节命令；QP 可以把任务和明确的限制一起交给求解器。

先记住四件不同的事：

| 名称 | 用普通话说 | 它不能代替什么 |
|---|---|---|
| 雅可比 `J` | 当前姿势下，关节转动怎样影响 TCP | 不会自己决定安全限制 |
| 阻尼 λ | 求解时偏好较小、较稳的关节动作 | 不保证速度、角度或碰撞限制 |
| QP | 在多个目标和明确限制之间找一组较合适的关节动作 | 只会遵守实际交给它的限制 |
| 时间步 Δt | 这一轮动作实际持续多久 | 不能单独说明程序实测运行频率 |

建议顺序：先读第 1 节弄清输入输出，再看第 2–4 节理解奇异和阻尼，最后读第 5–7 节看 QP、周期和项目代码边界。雅可比怎样由机器人模型算出见 [MuJoCo、Mink 与雅可比](02_MuJoCoMink任务约束与求解.md)。相关教学程序入口在 [P2 代码实验说明](../../../03_代码实验/02_项目实验/P2/README.md)；本轮只整理文档，没有运行程序。

## 1. 求解器这一轮到底要算什么？

假设机械臂有几个转动关节。当前关节角写作 `q`，单位是 rad；每个关节这一刻的转速写作 `q_dot`，单位是 rad/s。TCP 的平移和旋转速度合在一起，记作 `v_TCP`，通常由三个线速度和三个角速度组成。

当前姿势对应一张影响表 `J(q)`：

\[
\underbrace{\mathbf v_{TCP}}_{\text{TCP 此刻怎样动}}
=
\underbrace{J(\mathbf q)}_{\text{当前姿势的影响表}}
\underbrace{\dot{\mathbf q}}_{\text{各关节此刻转多快}}.
\]

正向看，这个式子回答“关节这样转，手腕会怎样动？”逆运动学则反过来：给定想要的 TCP 速度 `v_TCP*`，找一组关节速度，让 `J q_dot` 尽可能接近目标。

注意三种量不要混在一起：

1. `q`：关节当前角度，单位 rad；
2. `q_dot`：关节当前速度，单位 rad/s，是求解器常见的输出；
3. Δq：本周期关节角变化，单位 rad。

它们通过周期时间连接：

\[
\Delta\mathbf q\approx\dot{\mathbf q}\Delta t,
\qquad
\mathbf q_{next}\approx\mathbf q+\Delta\mathbf q.
\]

比如某关节转速是 `0.2 rad/s`，本轮持续 `0.005 s`，这轮只改变 `0.001 rad`。求解器不是命令关节瞬间跳到最终角度，而是每轮给一个小动作，再用新状态重新计算。

## 2. “奇异”为什么会让反算变得很大？

先把复杂机械臂缩成一个方向上的简单关系：

\[
v=\sigma\dot q.
\]

这里 σ 表示关节速度变成 TCP 速度时的比例。

- 若 σ=1，想要 TCP 速度 1，只需关节速度 1。
- 若 σ=0.01，想要 TCP 速度 1，就得关节速度 `1/0.01=100`。
- 若 σ=0，这个关节动作完全不能产生该 TCP 方向的速度；无论怎么除都不能实现目标。

机械臂雅可比有很多行和列。SVD（奇异值分解）把它拆成若干组“关节组合方向 → TCP 运动方向”：

\[
J=U\Sigma V^{\mathsf T}.
\]

初学者先把它读成：`V` 给出不同的关节组合方向，`U` 给出相应的 TCP 方向，Σ 对角线上的奇异值 σ 表示每组方向的传递强弱。

- σ 大：这组关节组合容易造成该方向的 TCP 运动。
- σ 小：该 TCP 方向很弱，想要同样大的 TCP 速度，反算会要求很大的关节速度。
- σ 等于零：该瞬间确实无法靠关节速度产生那个方向的运动。

这就是“奇异附近速度放大”的来源。手臂伸直只是容易想象的例子：有些末端方向会变得难以产生。真实奇异要根据完整 `J(q)` 判断，不是看到手臂伸直就一定所有方向都不能动。

一个细节：TCP 任务同时含 m/s 和 rad/s。程序若给平移、旋转不同权重，SVD 和“哪个方向弱”的数值也会随尺度改变。因此奇异值要结合任务的坐标、单位和权重理解，不能脱离它们当作普适的物理量。

### 2.1 普通逆、伪逆、秩亏的条件分别是什么

方阵 J 只有满秩时才存在普通逆。七关节单 TCP 的 J 是 6×7，不能直接写 J⁻¹；若行满秩为 6，最小范数右逆可写为
\[
J^+=J^T(JJ^T)^{-1}.
\]
JJᵀ 此时为 6×6 且可逆；一旦秩小于 6，这个普通逆表达式失效。类似地，(JᵀJ)⁻¹Jᵀ 要求 J 列满秩，6×7 的 J 不满足。SVD 定义 J⁺=VΣ⁺Uᵀ，Σ⁺ 对非零奇异值取倒数、对零值取零，所以能定义秩亏情形的最小范数最小二乘解，但不能恢复已经丢失的运动方向。

若 J=diag(1,0)、目标 v=[0,1]，伪逆解为 qdot=[0,0]，预测 Jqdot=[0,0]，残差仍为 [0,1]。这个零方向与 diag(1,0.01) 的小非零方向完全不同：后者未截断的伪逆会给出 100。

### 2.2 任务尺度怎样改变奇异值的解释

SVD 中 U/V 的“单位方向”依赖采用的欧氏度量。把米改为毫米会放大平移行；把关节变量换单位或给关节不同代价，也会改变关节空间度量。可先定义任务归一化/权重 W 与关节尺度 S，分析有效矩阵 WJS⁻¹，而不是比较来自不同单位和权重设置的裸最小奇异值。物理秩不会因可逆尺度变换而改变，奇异值大小和条件数会改变。

## 3. 阻尼最小二乘：求解器为什么宁可少走一点？

### 3.1 先写出求解器在权衡什么

阻尼最小二乘（Damped Least Squares, DLS）的一种标准写法是：

\[
\min_{\dot{\mathbf q}}
\left(
\|J\dot{\mathbf q}-\mathbf v^*\|^2
+\lambda^2\|\dot{\mathbf q}\|^2
\right).
\]

两项分别问：

1. “关节动作合起来，造成的 TCP 速度离目标还差多少？”这是第一项。
2. “这一组关节速度本身有多大？”这是第二项。

求解器让总分尽可能小，所以它会在“TCP 跟得准”和“关节别一下转太快”之间折中。

### 3.2 全局正则与任务 LM：为什么可以同时存在？

如果有多个任务，常写成：

\[
\min_{\dot{\mathbf q}}
\left[
\sum_i\|W_i(J_i\dot{\mathbf q}-\mathbf b_i)\|^2
\right]
+\lambda^2\|\dot{\mathbf q}\|^2.
\]

方括号里每个任务各有一项，例如左手腕、右手腕、手臂姿势。方括号外的阻尼项只写一次，因为所有任务共用同一组决策变量 `q_dot`；它惩罚的是整组关节速度的大小。展开范数时，`q_dot` 的每个分量都会进入平方和：

\[
\|\dot{\mathbf q}\|^2=\dot q_1^2+\dot q_2^2+\cdots+\dot q_n^2.
\]

所以“一次全局项”管整组关节。但这只是上述简化目标的写法，不能推成“软件禁止每个任务有额外正则”。Mink 的任务 LM 与全局 damping 可以并存，PostureTask 又有自己有目标的误差项，三者来源不同。

2026-10-12 核验当前上游 main：任务加权误差为 \(b_i=-\alpha_iW_ie_i\)，加权误差雅可比为 \(A_i=W_iJ_i\)，任务 LM 系数为 \(\mu_i=\text{lm\_damping}_i\|b_i\|^2\)。总 Hessian 的这一部分为
\[
H=\sum_i A_i^TA_i+\left(d+\sum_i\mu_i\right)I,
\]
其中 d 是 solve_ik 的全局 damping；任务 LM 随各任务误差变化。全局项加一次，各任务 LM 相加，这是同一个 QP 的两种正则来源。见 [Task 源码](https://raw.githubusercontent.com/kevinzakka/mink/ae6759602593113ed7e5431ac7c65726ea27dc29/src/mink/tasks/task.py)和 [QP 汇总源码](https://raw.githubusercontent.com/kevinzakka/mink/ae6759602593113ed7e5431ac7c65726ea27dc29/src/mink/solve_ik.py)。当前项目的历史安装版本未锁定，此公式作为当前 API 核验，不能直接当历史内部实现。lm_damping=0.05 不能等同教学 λ=0.05。

### 3.3 从目标函数怎样得到阻尼公式？

为看清楚主线，先只保留一个任务。对 `q_dot` 求目标函数的最小值，也就是让导数为零。平方项求导后得到：

\[
2J^{\mathsf T}(J\dot{\mathbf q}-\mathbf v^*)+2\lambda^2\dot{\mathbf q}=0.
\]

两边都有因子 2，可以同时除以 2：

\[
J^{\mathsf T}(J\dot{\mathbf q}-\mathbf v^*)+\lambda^2\dot{\mathbf q}=0.
\]

把包含 `q_dot` 的项放在一起：

\[
(J^{\mathsf T}J+\lambda^2I)\dot{\mathbf q}=J^{\mathsf T}\mathbf v^*.
\]

这里 `I` 是单位矩阵，相当于给每个关节速度方向都加同样的惩罚。形式上可写为：

\[
\dot{\mathbf q}=(J^{\mathsf T}J+\lambda^2I)^{-1}J^{\mathsf T}\mathbf v^*.
\]

实际程序一般用线性方程求解器，不会真的手工构造矩阵逆。

### 3.4 为什么增益从 `1/σ` 变成 `σ/(σ²+λ²)`？

SVD 已经把复杂矩阵拆成互相独立的方向。只看其中一个方向，把该方向的雅可比比例记为 σ，目标 TCP 速度分量记为 `v`，关节速度分量记为 `q_dot`。带阻尼的矩阵方程在这个方向上就变成普通的一元方程：

\[
(\sigma^2+\lambda^2)\dot q=\sigma v.
\]

两边除以括号里的数：

\[
\dot q=\frac{\sigma}{\sigma^2+\lambda^2}v.
\]

因此，乘在目标速度 `v` 前面的比例就是 `σ/(σ²+λ²)`。如果没有阻尼，原关系是 `σ q_dot = v`，于是 `q_dot = v/σ`，比例就是 `1/σ`。

若 σ=0，普通除法没有定义；**Moore–Penrose 伪逆则把该奇异值的逆系数定义为 0，不是无穷大**。它留下无法实现的任务残差，并给出最小范数最小二乘解。数值伪逆还常把低于容差的奇异值截为零。真正的速度暴涨发生在“小而非零、仍参与求逆”的方向：此时系数为 1/σ。λ>0 的阻尼系数在 σ=0 也为零，而在 σ 接近零时平滑趋于零。矩阵 JᵀJ+λ²I 为正定，因而可逆。

### 3.5 为什么有人写 λ，有人写 λ²？

这是最容易把同一件事写乱的地方。若目标函数写成：

\[
\|J\dot q-v^*\|^2+\lambda^2\|\dot q\|^2,
\]

方程里对应 `+λ²I`，弱方向增益是 `σ/(σ²+λ²)`。若有人把目标函数写成 `+λ||q_dot||²`，则方程里对应 `+λI`，增益分母也应写 `σ²+λ`。只是参数命名方式不同；不能目标函数用 λ、推导却直接套 λ² 版本。

本课程统一使用“目标函数惩罚系数写 λ²”的约定。这样 λ 可以和奇异值 σ 在同一公式位置比较。数值库也可能采用不同定义，阅读 API 参数时必须看该库版本的文档，不能仅凭参数名猜公式。

### 3.6 阻尼在数学和物理上分别是什么意思？

数学上，λ 越大，过大的关节速度会被扣更多分。求解器会更谨慎，通常让关节速度变小，但 TCP 也会更跟不上目标。实际调节时没有适用于所有机械臂的固定最佳值：先把任务单位和权重定清楚，再记录最小奇异值、关节速度峰值、TCP 误差和求解耗时。若近奇异时速度过大，可增大阻尼或采用随奇异程度变化的阻尼；若误差长期很大，则检查阻尼是否过强、目标是否可达，以及限制是否互相冲突。

物理上它**不是**给电机真的接了一只阻尼器，也不是直接加了一个与关节速度相反的力矩。它是软件优化里的一个偏好项。叫“阻尼”是因为它抑制了数值求解中突然变大的动作，效果类似让动作温和一些。

阻尼属于软偏好：求解器尽量不要动作太大；它不是硬保证“关节速度一定不超过某个数”。

## 4. 用具体数字看奇异值与阻尼

下面矩阵是为了算得清楚的无量纲教学例子，不是 P2 手臂的测量雅可比：

\[
J=\begin{bmatrix}1&0\\0&0.01\end{bmatrix},
\qquad
\mathbf v^*=\begin{bmatrix}0\\1\end{bmatrix}.
\]

第二个方向很弱：关节速度的第二分量要乘 (0.01) 才变成 TCP 的第二方向速度。

### 不加阻尼

为了让 TCP 第二方向速度达到 1：

\[
0.01\dot q_2=1
\quad\Longrightarrow\quad
\dot q_2=100.
\]

于是 `q_dot=[0,100]`。这是数学上精确跟踪，但关节速度极大，实际机器人通常做不到，也可能危险。

### 加 λ=0.1 的阻尼

普通逆在某个奇异方向上的速度放大系数是 `1/σ`。阻尼后的放大系数变成：

\[
g(\sigma)=\frac{\sigma}{\sigma^2+\lambda^2}.
\]

代入第二方向 σ=0.01、λ=0.1：

\[
g=\frac{0.01}{0.01^2+0.1^2}
=\frac{0.01}{0.0001+0.01}
\approx0.990099.
\]

目标第二方向速度为 1，所以关节第二分量约为 (0.990099)，而不是 100。把它乘回雅可比：

\[
v_{TCP,2}=0.01\times0.990099\approx0.009901.
\]

对照着读：

- **目标 TCP 速度**：1；
- **求出的关节速度**：约 0.9901；
- **实际预测 TCP 速度**：约 0.0099；
- **没跟上的速度差**：约 `1 - 0.0099 = 0.9901`。

阻尼作出的选择是：“这个方向太弱，若硬追目标会要求关节转到 100；我宁可明显少跟一点，也不输出那么大的关节速度。”这不是说末端已经达到 0.9901；0.9901 是关节速度，末端只得到约 0.0099。

| 弱方向 σ | 不阻尼 `1/σ` | λ=0.1 时 `σ/(σ²+λ²)` |
|---:|---:|---:|
| 1 | 1 | 约 0.990 |
| 0.1 | 10 | 5 |
| 0.01 | 100 | 约 0.990 |
| 0.001 | 1000 | 约 0.100 |
| 0 | 普通除法无定义；伪逆系数为 0 | 0 |

σ 变小时，不阻尼增益一直变大；有阻尼增益不会无限增大，而是最终下降到 0。代价是困难方向的 TCP 速度也会变小，目标误差会留下来。这个留下的差称为任务残差。

以上“持续变大”指 σ>0 的倒数分支；在 σ=0 点，伪逆定义取零。阻尼函数在 σ=λ 处达到最大 1/(2λ)，因此其随 σ 的变化不是简单单调递减；大 σ 近似 1/σ，小 σ 近似 σ/λ²。这个数学界也不是驱动器指定的硬速度上限：目标大小、任务尺度和多个方向的合成仍决定最终速度。

## 5. QP 是什么？为什么叫“二次规划”？

QP 是二次规划（Quadratic Programming）。对这个词先拆成两部分：

- **规划**：求解器在许多候选关节速度中挑一组。
- **二次**：评分里有平方项。例如误差平方 `e^2`、速度平方 `q_dot^2`。

“二次”可以直接从一项误差平方看出来。假设某个任务误差是 `J q_dot - b`，它的平方为：

\[
\|J\dot q-b\|^2=(J\dot q-b)^{\mathsf T}(J\dot q-b)
=\dot q^{\mathsf T}J^{\mathsf T}J\dot q-2b^{\mathsf T}J\dot q+b^{\mathsf T}b.
\]

要选的量是 `q_dot`。展开以后，最高次是 `q_dot` 的平方，所以是二次目标。最后一项 `bᵀb` 不含 `q_dot`，对比较候选动作来说是固定分数，可以不影响最优解。

一个常见标准形式是：

\[
\min_{\mathbf z}\;\frac12\mathbf z^{\mathsf T}H\mathbf z+\mathbf f^{\mathsf T}\mathbf z
\qquad\text{subject to }A\mathbf z\le\mathbf c.
\]

对微分 IK，可以让决策量 `q_dot` 就是所有关节的速度。平方任务误差展开后是 `q_dot` 的二次函数；关节速度上限、一步后的角度范围等则能写成线性不等式。若目标函数和限制符合 QP 的形式，OSQP 这类求解器可以寻找最低评分且满足限制的速度。

可以把它想成：**先规定哪些候选动作合法，再在合法动作里挑一组最合适的。**

一个一维小例子（先忽略阻尼）：假设 TCP 速度约等于 `2 × q_dot`，目标 TCP 速度为 1。若没有限制，精确达到目标需要 `q_dot=0.5`。如果电机规定本周期速度不能超过 0.4，QP 不会把 0.5 先算出来再假装它合法，而会在允许范围内选最合适的 `q_dot=0.4`。此时 TCP 速度约为 `2×0.4=0.8`，还差 0.2。它选择“遵守速度上限，接受一点任务误差”。这是硬约束起作用的样子。

### 多个任务意见不一致时怎么办？

例如 TCP 希望向前，姿势任务希望肘部保持当前位置，阻尼希望关节速度不要太大。它们可能不能同时完美满足。求解器根据各任务权重折中：权重高的任务误差更不愿意留下，权重低的任务可以让步。

常见的教学目标函数可写成：

\[
\min_{\dot{\mathbf q}}
\sum_i\|W_i(J_i\dot{\mathbf q}-\mathbf b_i)\|^2
+\lambda^2\|\dot{\mathbf q}\|^2,
\]

再另外加限制。每个 i 是一个任务；这个教学模型只选择了总目标末尾一个全局正则。具体库还可以加入第 3.2 节的任务 LM 项，因此不能用这个简化公式否认软件的逐任务正则。

这只是帮助理解求解目标的原理式，不保证与某个 Mink 版本的内部矩阵逐项相同。求解器库负责构造并求解，项目调用决定交给它哪些任务和限制。

### 两个关节、两个偏好：把多任务目标函数算一遍

下面的数字是专门为手算编的，不是 P2 机械臂测得的雅可比，也不是项目真实关节命令。为了只练矩阵计算，本例把任务量归一化，不赋予它真实的米、弧度或速度单位；真实任务的不同单位需要通过任务尺度和权重妥善处理。我们假设这一小步要决定两个关节各改多少：

\[
\Delta\mathbf q=\begin{bmatrix}\Delta q_1\\\Delta q_2\end{bmatrix}.
\]

任务一希望 TCP 完成两个方向的运动：

\[
J_1=\begin{bmatrix}2&1\\1&2\end{bmatrix},
\qquad
\mathbf b_1=\begin{bmatrix}0.3\\0.3\end{bmatrix}.
\]

这句话的意思是：若关节小步是 \(\Delta\mathbf q\)，任务一预测出的末端变化是 \(J_1\Delta\mathbf q\)；它希望这个变化接近 \(\mathbf b_1\)。

同时，姿态偏好任务希望这一步不要无故改变关节：

\[
J_2=I,\qquad \mathbf b_2=\begin{bmatrix}0\\0\end{bmatrix}.
\]

把姿态任务权重设为 \(0.2\)，阻尼参数设为 \(\lambda=0.1\)。本例目标函数是：

\[
\min_{\Delta\mathbf q}
\underbrace{\|J_1\Delta\mathbf q-\mathbf b_1\|^2}_{\text{TCP任务误差}}
+\underbrace{\|0.2(J_2\Delta\mathbf q-\mathbf b_2)\|^2}_{\text{姿态偏好}}
+\underbrace{0.1^2\|\Delta\mathbf q\|^2}_{\text{一次全局阻尼}}.
\]

#### 第一步：把每项改写成矩阵

最小二乘的标准结果是：\(\|Jx-b\|^2\) 对应正规方程中的 \(J^{\mathsf T}J\) 和 \(J^{\mathsf T}b\)。所以本例满足：

\[
\left(J_1^{\mathsf T}J_1+0.2^2I+0.1^2I\right)\Delta\mathbf q
=J_1^{\mathsf T}\mathbf b_1.
\]

这里权重 \(0.2\) 在范数里面，平方后对矩阵的贡献是 \(0.2^2=0.04\)；阻尼也按本章约定写成 \(\lambda^2=0.01\)。姿态任务和阻尼虽然都让动作变小，但它们来源不同：姿态任务是一个有明确目标的任务，阻尼是对整组关节小步的一次全局惩罚。

#### 第二步：逐项乘出来

\[
J_1^{\mathsf T}J_1=
\begin{bmatrix}5&4\\4&5\end{bmatrix},
\qquad
J_1^{\mathsf T}\mathbf b_1=
\begin{bmatrix}0.9\\0.9\end{bmatrix}.
\]

因此：

\[
\begin{bmatrix}5.05&4\\4&5.05\end{bmatrix}
\begin{bmatrix}\Delta q_1\\\Delta q_2\end{bmatrix}
=\begin{bmatrix}0.9\\0.9\end{bmatrix}.
\]

左右关节在本例里的条件完全对称，所以解也满足 \(\Delta q_1=\Delta q_2=a\)。代入第一行：

\[
(5.05+4)a=0.9
\quad\Longrightarrow\quad
a=\frac{0.9}{9.05}\approx0.09945.
\]

所以：

\[
\Delta\mathbf q\approx\begin{bmatrix}0.09945\\0.09945\end{bmatrix}.
\]

若没有姿态偏好和阻尼，TCP 任务单独求解会得到 \([0.1,0.1]^{\mathsf T}\)，刚好达到目标。本例加入两个“小动作偏好”后，结果稍微缩小。代回 TCP 任务：

\[
J_1\Delta\mathbf q
=\begin{bmatrix}3(0.09945)\\3(0.09945)\end{bmatrix}
\approx\begin{bmatrix}0.29834\\0.29834\end{bmatrix}.
\]

目标是 \([0.3,0.3]^{\mathsf T}\)，所以每个分量约差 \(0.00166\)。求解器接受这点末端误差，以换取姿态变化和关节小步更小。

#### 这个算例说明什么？

1. TCP 任务和姿态偏好使用**同一组** \(\Delta\mathbf q\)，求解器一次决定两个关节怎样配合。
2. 姿态权重越高，越不愿意偏离姿态目标；阻尼越大，越不愿意产生大的关节小步。
3. 本例没有加入 \(G\Delta\mathbf q\le h\) 这样的硬限制，所以它只演示加权最小二乘和阻尼，**没有演示关节限位、速度上限或避碰保证**。
4. 数值 \(J_1\)、任务单位和权重全是教学设定，不能拿来声称是 P2 实际机械臂的雅可比、任务权重或输出。

## 6. 阻尼、硬限制、限幅：三者不能互相冒充

以某个关节当前角度 `q`、速度 `q_dot`、周期 `Δt` 为例。

### 6.1 速度硬限制

如果关节速度上限是 `q_dot_max`，可以直接要求：

\[
-\dot q_{max}\le\dot q\le\dot q_{max}.
\]

这是一条硬边界；合格解必须在范围内。

### 6.2 位置硬限制

预估下一步关节角约为 `q + q_dot × Δt`。若机械关节允许范围是 `[q_min, q_max]`，可以要求：

\[
q_{min}\le q+\dot q\Delta t\le q_{max}.
\]

整理后就得到对 `q_dot` 的上下界。这样可以在本步就避免继续向限位外推。

### 6.3 碰撞限制

求解器也可以接收与碰撞距离有关的限制。由于真实碰撞几何通常是非线性的，逐步 IK 常会在当前姿势附近把碰撞边界近似成可处理的限制，并在下一轮重新计算。是否安全取决于几何模型、近似误差、更新频率和实际配置；仅仅使用 QP 这个名字不会自动带来避障。

### 6.4 和阻尼对比

- **阻尼**：动作大要多扣分，但在数学上允许求解器仍选较大速度。
- **速度/位置限制**：超过边界的候选动作直接不允许。
- **求解后剪裁（clip）**：先算一个解，再把数字截小；截后任务效果会改变，而且一般不等于“在所有约束内重新找最优解”。

因此，“加了阻尼”不能说成“电机速度已被限制”；“每个关节最后 clip 了”也不等于做了约束 QP。

## 7. Δt：速度怎样变成一次命令？

Δt 是**这一次关节目标更新代表多长时间**。它把关节速度换成这一步的关节角增量：

\[
\Delta q=\dot q\Delta t.
\]

若配置周期为 `Δt = 1/200 s = 0.005 s`，可把它理解成每一步按 5 ms 计算一次。例子中 `q_dot = 0.2 rad/s`，所以本步角度增量是：

\[
0.2\text{ rad/s}\times0.005\text{ s}=0.001\text{ rad}.
\]

**配置 5 ms 不等于已经测得程序实测每 5 ms 准时完成。**要证明实际周期，要记录循环时间、最慢耗时、抖动、求解耗时和掉帧。也要区分 IK 的 Δt、MuJoCo 物理仿真的积分步长、VR 数据到达间隔、电机驱动内部伺服周期；它们可能不同。

- Δt 太大：每次跨得远，局部雅可比的近似可能不够准确，也更容易越过目标或限制。
- Δt 太小：每一步更细，但单位时间要计算更多次，系统和求解器负担会增加。
- 应根据机器人速度、模型误差、求解时间和反馈频率选取，并实测闭环表现；不能只说“越小越好”。

周期变短会改变每步增量，但**不会自动降低求解器算出的速度**。速度 `q_dot` 由目标、雅可比、任务权重、阻尼和限制共同决定。

## 8. P2 里的实现事实与教学公式的边界

现有 P2 分析记录显示，相关求解器配置 `dt=1/200 s`，FrameTask 设置 `lm_damping=0.05`，并用 OSQP 后端求解；得到的速度经过 Mink 配置积分，再形成关节目标。具体对象、调用顺序和 MuJoCo 与 Mink 分工见 [MuJoCo、Mink 任务与雅可比章节](02_MuJoCoMink任务约束与求解.md)。

这里要谨慎读参数：lm_damping=0.05 是该 API 的任务配置值。当前上游的定义已在第 3.2 节核验，历史环境版本仍未锁定；不能断言它等于本章简化公式的 λ=0.05，更不能直接代进教学表格得出实际关节速度。教学统一写 +λ²||z||²；库的全局 d 直接加在 Hessian 对角线上，二者参数命名和系数不能靠名字混用。

该调用没有显式传入速度或碰撞限制列表；Mink 某些版本可能对配置范围有默认处理，但本项目没有锁定足以确认默认行为的版本。因此目前只能说“代码这里没有显式列出这些限制”，不能由此声称所有速度、位置和碰撞均已得到可靠约束。部署实机前要确认版本、限制对象、求解失败处理和驱动器保护。

另有一段 `Dynamics.GetNullSpace` 分析代码带有 `use_stable_svd=false` 分支，实际公式走 `Jᵀ(JJᵀ)⁻¹`。这和 Mink 的 FrameTask 求解不是同一个实现。该普通逆写法要求相应矩阵满秩；不能因为文件里存在 SVD 分支，就说实际运行启用了稳定 SVD。

异常时返回当前关节配置属于“这次不更新目标”。若下游位置控制器继续使能，它可能仍然保持当前位置出力；这不等于发了零命令，也不等于电机断电。安全停止还要看命令超时、驱动器模式、故障状态和明确的停止逻辑。

## 9. 一页串起求解过程

1. 读本周期关节角 `q`，用机器人模型算当前 TCP 和雅可比 `J(q)`。
2. 用目标与当前 TCP 得到手腕任务速度 `v_TCP*`；姿势任务可能另给一个关节偏好。
3. 求解器比较各关节速度组合：手腕误差要小，动作不要无故过大，姿势偏好尽量满足。
4. 若显式配置速度、位置和碰撞限制，候选速度还必须在这些限制允许的范围内。
5. 当前上游 Mink 内部 QP 求 Δq，API 返回 Δq/dt；项目将返回速度按 dt 积分，生成下一配置目标。教学也可直接写速度型 QP，两种变量的目标和约束尺度必须一致。
6. 仿真或执行器尝试跟踪目标；读取下一轮状态，再重新算一次。

阻尼主要处理第 3 步的“弱方向上速度可能过大”；硬限制处理第 4 步的“哪些动作根本不允许”。这是两类不同保护。

## 10. 常见误解与排查顺序

| 看到的现象 | 先检查什么 |
|---|---|
| 关节速度突然很大 | 当前雅可比的最小奇异值、任务尺度、目标速度、阻尼和速度限制 |
| 加阻尼后 TCP 跟得慢 | λ 是否过大、是否接近奇异、目标是否可达、是否触发其他限制 |
| TCP 仍向关节限位外移动 | 是否真的把位置限制交给 QP，而非只加阻尼或事后 clip |
| 求解器返回了数值，但手没到目标 | 检查任务残差、目标可达性、限制冲突和任务权重 |
| 周期配置为 5 ms，但操作有卡顿 | 记录实测循环周期、QP 耗时、VR 数据年龄、线程调度和电机通信 |
| 异常后姿势保持住了 | 核对驱动仍否使能；保持位置不等于零输出或断电 |

**English reference:** “At each step, differential inverse kinematics uses the current configuration and Jacobian to compute joint velocities. Near a singularity, an undamped inverse can amplify motion along a weak direction. Damping trades tracking accuracy for smaller, more stable joint velocities. It does not enforce hard joint or collision limits; those constraints must be configured explicitly. I also distinguish the configured IK timestep from the measured control-loop period.”

## 历次提问归纳：QP、阻尼和奇异各自解决什么

核心追问归纳如下；全量索引见 [P2 历次问题归纳与完整讲解](../05_中英文面试/05_历次问题归纳与完整讲解.md)。

- **优化器要选什么？**给定当前状态、末端任务目标、任务权重、阻尼参数和实际传入的约束，优化器求这一周期的关节速度/小步更新。它不要求人提前列出所有候选动作；目标函数与约束定义了可选解和取舍。
- **为什么目标函数是二次的？**本步冻结 J、误差、权重和正则系数，残差对决策变量是线性的，平方后形成二次目标。全局正则与每任务 LM 均可贡献到总 Hessian；下一轮重新线性化。
- **阻尼为什么能压住奇异方向？**Jacobian 的小奇异值表示某个末端方向很难由关节产生；裸伪逆会乘 (1/\sigma) 而变大。阻尼把该方向增益改成 (\sigma/(\sigma^2+\lambda^2))，减少关节暴冲，代价是该方向追踪不足。
- **权重不等于限制。**权重只表示偏好，不能替代关节速度、位置、碰撞等硬约束；只有明确构造成约束并传给求解器的条件才会被保证。
- **为什么 Δq=q̇Δt？**速度是每秒变化量，乘本控制周期才得到这一小步角度变化；dt 需使用真实/配置周期的正确单位，不能把 rad/s 直接当 rad 命令。
