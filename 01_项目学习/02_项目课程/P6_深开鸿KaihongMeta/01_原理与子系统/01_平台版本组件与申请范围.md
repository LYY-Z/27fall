# 01 平台、设备与应用：先弄清P6在解决什么

> 本章从本对话中“开始学习P6”的入口展开。后面的C++、并发、协议与安全问题是为继续学习提前补齐的知识，不把它们写成你已经逐题问过或已经实机验证过。

## 1. 从一个请求开始理解平台

假设应用希望“把地锁A升起来”。这句话里至少有三个尚未解决的问题：A到底是哪台设备；它支持什么操作；软件用什么协议告诉它升起。

如果应用直接写串口字节，它必须了解设备型号、串口号、从站地址、寄存器位置、异常码。换一台设备，应用可能就要重写。平台的作用是把共同处理留在上层，把硬件差异放到具体处理器和适配器中。

```mermaid
flowchart LR
 A[应用请求 地锁A up] --> B[找到设备和命令处理函数]
 B --> C[任务排队]
 C --> D[GroundLock处理器]
 D --> E[Modbus适配器]
 E --> F[通信服务与真实设备]
 F --> G[返回码或设备反馈]
 G --> H[状态缓存与上报]
```

这张图描述可见源码的职责。它不意味着每一阶段都检查了权限、数据年龄或机械到位；这些需要逐函数确认。

## 2. 同一台设备为什么需要四种信息

| 信息 | 具体例子 | 回答的问题 |
|---|---|---|
| 身份 | `deviceId="lock-A"` | 我正在操作谁？ |
| 能力/操作 | `up`、`down` | 对它可以提出什么请求？ |
| 状态 | 最近一次地锁状态值及来源 | 它最近报告了什么？ |
| 请求及结果 | 本次调用返回码、输出JSON | 这次请求处理到了哪一步？ |

“注册了up操作”仅说明软件有一个处理入口；不等于设备在线。“状态缓存为升起”也可能只是写命令后的软件更新；不等于机械刚刚到位。

**连续例子。**10:00:00软件给A发up，写函数返回成功；10:00:00.1缓存被改为升起；10:00:01独立轮询才读取设备。前两项与最后一项的证据来源不同。若设备卡住，写成功与到位失败可以同时发生。

## 3. 这些软件名称分别是什么

| 名称 | 初学者解释 | 在本项目中怎样使用 |
|---|---|---|
| API | 程序可以调用的函数约定 | `ExecCommand(...)`是命令入口的一种API |
| 库 | 可以被别的程序链接或导入的代码集合 | 设备框架、协议适配器等组件提供可复用实现 |
| SDK | 开发某平台所需的工具、接口、头文件和依赖集合 | 构建OpenHarmony组件可能需要对应SDK；不等于单个C++文件 |
| 框架 | 预先安排好部分流程，调用业务代码的结构 | 基类负责初始化、命令查找、线程池和上报，子类填具体设备行为 |
| 协议 | 两端对消息字段与交换方式的约定 | Modbus规定寄存器读写等消息语义 |
| OpenHarmony | 系统平台及其运行/构建生态 | 当前组件使用其命名空间、GN和系统服务依赖 |
| ROS/ROS 2 | 机器人软件通信与组件生态 | 申请材料中的运动接口来源；不凭设备框架源码就证明桥接已完整部署 |

“有API”只说明有调用入口。“有SDK”说明有开发依赖；二者都不自动说明硬件连通。M-Robots、M-DDS是申请材料描述的特定平台名称，其确切接口、传输和配置要由相应版本材料解释，不把SoftBus、MQTT或普通线程池代替成M-DDS。

## 4. 当前手里到底有什么源码

固定入口是[源码版本与文件地图](../02_源码阅读与运行/01_源码版本与文件地图.md)。本地KaiHong-learning包含设备处理器基类、地锁/园艺等插件、线程池及Modbus/Snap7等适配。

可以据此讲清：共同命令怎样分派给具体设备；任务在哪个线程执行；协议参数怎样构造；状态何时更新。当前副本尚未定位申请材料所述M-Robots/M-DDS的完整专用实现，所以它不能独立证明多机器人发现、ROS桥接与平台权限链的所有历史细节。

源码存在、源码被调用、实际运行成功、本人负责实现，是四个不同结论。记录时分别写：函数和分支；调用者与构建配置；日志/设备反馈；提交或职责记录。这样才知道哪一层还需要材料。

## 5. P6与前面项目怎样衔接

P1/P2/P3/P5/P7主要让你理解“根据状态算控制量”；P4还涉及观测和决策。P6继续问：谁提供可信状态、怎样表达设备能力、动作怎样进入设备、并发和失联如何处理。

例如同一个速度控制模块想从硬件A换到B，需要确认反馈单位、方向、更新时间、命令模式和停止语义。共同函数名只能统一调用形式，真正能复用还依赖这些语义契约。

## 6. 阅读与复习路线

先读[一次设备动作](../00_项目全貌与学习路线/03_P6一次设备动作怎样走过软件平台.md)，再依次读下一章的对象、第三章的线程、第四章的协议和第五章的执行回执。最后回到[完整源码周期](../02_源码阅读与运行/02_一个周期的调用与数据流.md)，把软件请求和独立读回画在同一条时间轴上。

**纸笔检查：**应用调用up后返回success，能否直接说地锁到位？不能；要指出success来自哪个函数，以及独立完成反馈是否存在。设备有move能力但反馈过期，能否继续移动？这是策略问题，需要具体时效与停止约定，不能仅靠能力名判断。

英文口述：*The platform provides common device operations, while handlers and adapters preserve device-specific meaning. I distinguish a software return value, an independent device readback and physical completion.*
