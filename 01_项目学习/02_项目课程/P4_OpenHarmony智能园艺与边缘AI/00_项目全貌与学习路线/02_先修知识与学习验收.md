# P4 先修知识与学习验收

## 先分清系统里的三条信息流

先读[端到端数据与执行链](03_P4端到端数据与执行链.md)，再任选一条具体事件：

1. 土壤传感器读数是否触发本地水泵；
2. 摄像头图像怎样成为带时间的检测结果；
3. 服务端或 Agent 怎样提出动作，设备怎样执行并回报状态。

这些链路可能异步运行。传感器值、识别结果、动作请求和设备回执是不同数据，不能因为“消息发出去了”就认为“水泵已经按要求动作”。

## 按主题补基础

| 主题 | 需要认识 | 先记住的因果 |
|---|---|---|
| 土壤湿度输入 | ADC 数字、标定、阈值、滞回 | ADC 是采样电压的数字值；程序要标定或映射后才称为湿度估计 |
| 本地开关控制 | 状态机、滞回、人工优先级、GPIO 电平 | 滞回要记住上一次开关状态；继电器可能低电平有效，必须核对板级定义 |
| 图像和 YOLO | 图像宽高、通道、缩放、letterbox、检测框 | 模型输入前后坐标可能变化；还原检测框时要撤销缩放和边缘填充 |
| RKNN/INT8 | 张量形状、数据类型、量化尺度与零点 | INT8 不是简单把浮点截成整数；量化/反量化参数不匹配会改变输出 |
| 视觉事件和时间 | 类别、置信度、框坐标、时间戳、去重 | “检测到了”不说明目标现在仍在；要看新鲜度、连续帧和筛选条件 |
| Agent 与工具 | 规则、状态、工具调用、超时/回退 | Agent 决策是请求；设备动作还需校验、执行、回执和状态刷新 |
| 网络和恢复 | TCP 字节流、消息边界、重连、幂等键 | TCP 不保证一次 recv 就得到一条完整消息；重试可能重复动作，需要识别重复请求 |

通用入口：[基础课程总览](../../../01_通用基础/00_基础课程总览.md)。学习图像或网络时只补当前链路需要的概念，避免先把整套 AI/通信术语背下来。

## 推荐路线

1. 画出“传感器 → 本地判定 → GPIO/水泵 → 状态回读”的独立闭环。
2. 用一个 ADC 数字走过标定、进入阈值、退出阈值和人工覆盖；明确开/关两条门槛。
3. 再画摄像头数据链：采集 → 预处理 → 推理 → 解码 → NMS/过滤 → 框坐标还原 → 事件消息。
4. 对一条视觉事件标注类别、置信度、图像时间、发送时间和接收时间，解释过期结果为何不能直接触发设备动作。
5. 最后画服务端的决策、工具调用、设备命令、执行回执和恢复状态；区分“已发送、已接收、已接受、已执行、状态已确认”。
6. 对照源码地图检查功能在哪个设备或进程中运行。源码静态路径、模型推理实测和园艺现场效果要分别举证。

## 学完后的纸笔验收

1. 用一个自选传感器值，按本章实际上下阈值说明水泵如何从关变开、何时再关；讲清阈值边界和人工命令优先级。
2. 用一张 640×480 输入图像，说明缩放、填充、检测框坐标恢复各改变了什么；不要把像素坐标说成世界坐标或植物尺寸。
3. 解释模型分数、过滤后的框和最终事件不是同一种结果，并为每一步写出形状/单位。
4. 说明网络发出动作后，怎样凭设备回执和新状态确认动作，而不是靠 HTTP/TCP 成功来推断。
5. 找一个失败点：传感器卡值、视觉帧过期、设备离线、重复请求或回执超时，并指出日志至少需要哪些时间戳和状态字段。

详细复习入口：[历次问题归纳与完整讲解](../05_中英文面试/05_历次问题归纳与完整讲解.md)。未在代码、运行日志或现场实验里证实的行为，标为设计/教学解释，不写成已部署效果。

## 复习工具：用一个事件贯穿感知、决策和执行

每次复习都选一个具体事件，例如“土壤干了”或“视觉检测到植物目标”，并把它拆成可核对的阶段：

```text
传感器/摄像头产生数据
  → 采样或取帧（记录数据时间）
  → 标定/预处理/推理与过滤
  → 本地阈值或服务端策略形成事件/动作请求
  → 权限、状态、去重和新鲜度检查
  → 网络/设备接口发送命令
  → 设备接受/执行
  → 回执与新状态确认
```

本地土壤控制与视觉/Agent链路可能是不同进程或设备，不要为了画“全系统图”而假设它们必经同一个模型。复习时给每个箭头写生产者、消费者、消息字段、时间戳和失败处理。

### P4 易混概念对照

| 容易混在一起 | 应该怎样区分 |
|---|---|
| ADC值与含水率 | ADC是数字采样；含水率要靠传感器标定曲线/映射，不能把原始整数直接叫百分比。 |
| 滞回与单阈值 | 开启和关闭使用不同门槛并记住上次状态，避免读数在阈值附近抖动；人工覆盖优先级需看实际状态机。 |
| 检测框与真实物体位置 | YOLO框位于图像像素坐标；缩放、填充后要按预处理反变换，像素不等于机器人/世界坐标。 |
| 分数与“识别正确率” | 单帧置信分数是模型输出；过滤/NMS后才是候选检测；长期准确率需有标注数据集评估。 |
| INT8与直接取整 | 量化还涉及尺度和零点；输入预处理、张量layout与模型量化参数必须一致。 |
| TCP发送成功与设备执行 | TCP只提供字节流传输；应用消息边界、设备接受、物理动作及状态确认是不同阶段。 |
| 重试与恰好执行一次 | 超时后重试可能重复动作；需要请求ID/幂等键/设备状态核对，不应把网络可靠等同于动作只发生一次。 |

### 自测题与检查要点

1. 一个ADC读数如何从数字变成“需要浇水”的决定？检查点：传感器标定、上下阈值、滞回状态、人工命令优先级和故障/无效读数策略。
2. 摄像头640×480图像进入模型后，框坐标为何可能不能直接显示？检查点：缩放比例、padding、模型输出坐标格式，反变换回原图尺寸。
3. 怎样确认视觉事件没有过期？检查点：采集时间、推理完成时间、发送/接收时间、最大允许年龄；只看接收时刻不够。
4. API返回成功是否证明泵已运行？检查点：按发送→接收→接受→执行→反馈逐级回答，并指出确认执行需要哪种状态/传感器。
5. 超时重试如何避免重复开泵？检查点：唯一请求标识、幂等处理、当前设备状态、重试窗口和超时后的查询/补偿策略。
6. 视觉模型准确性怎样报告？检查点：标注测试集、类别与阈值、Precision/Recall或适合任务的指标、置信区间/现场差异；不能从一段演示推断准确率。

### 复习记录卡

每次只追一条事件，记录：输入时间、处理时间、动作ID、消息/张量形状、阈值或置信度、执行回执、最终状态。把“源码证明的路径”“模型离线评测”“仿真”“现场试验”分栏记录。当天闭卷画链，次日解释一次失败路径，一周后从原始数据重新推到最终状态。
