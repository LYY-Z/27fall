# 01 C与C++内存指针引用

先修：[数学基础](../01_数学与物理基础/README.md)。项目：P3、P6、P7。实验：[数据结构与状态同步](../../03_代码实验/01_基础实验/03_数据结构与状态同步/README.md)。

## 1. 为什么机器人代码离不开内存

传感器把温度、电机角度等数字写进内存，控制器从同一块内存取数字。变量是给一段存储空间起名。地址表示它放在哪里；指针存地址；解引用表示到那个地址取对象。先把“地址”和“该地址的值”分开。

```cpp
double angle = 0.2;
double* p = &angle; // p 保存 angle 的地址
*p = 0.3;          // 修改这个地址上的 double
double& ref = angle;
ref = 0.4;         // ref 是 angle 的另一个名字
```

不能从p的数字大小推断角度大小。`p+1`按所指类型的大小移动，不一定只移动1字节。`double*`不是double数值，向错误类型转换再取值可能破坏内存。

## 2. 栈、堆与对象的寿命

局部自动变量通常在作用域结束时销毁。动态对象需要明确所有者；C++优先用容器或智能指针管理，避免手动new/delete配对失败。

```cpp
double* bad() {
    double local = 1.0;
    return &local; // 错：函数结束后对象已不存在
}
```

返回的地址可能看起来有数，但不再有合法对象，这叫悬空指针。正确办法可以返回值，或把结果写进调用者提供的对象。引用也会悬空，不能认为引用天然安全。

`const Feedback&`允许只读借用，通常避免复制；借用期间原对象必须有效。是否需要复制取决于对象大小、并发和接口目的。

## 3. 完整手算：电机数据缓冲区

假设`uint8_t data[4]={0x01,0x02,0x00,0x64}`。前2字节是大端无符号位置，后2字节是速度：

位置原始数=0x01×256+0x02=258；速度原始数=0×256+100=100。若标定比例0.01rad/count，位置2.58rad。顺序反了会得到0x0201=513，即5.13rad。地址没错、计算没崩溃，也能因端序解释错误而控制错误。

位移前先转成足够宽的无符号类型：`(uint16_t(data[0]) << 8) | data[1]`。长度不足4时必须拒绝读取，不能访问data[3]。

## 7. 练习与答案

1. 概念：`p`和`*p`区别？答：前者地址，后者所指对象。
2. 计算：大端[0x02,0x00]、0.001rad/count？答：512×0.001=0.512rad。
3. 代码：函数返回局部变量引用为何错？答：对象已销毁；改为返回值。
4. 结果：偶发电机角度异常一定是传感器噪声吗？答：先查越界、报文解析、寿命、并发和时间戳，不能仅滤波。

## 精读补充：把中间步骤讲清楚

### A. 回调里的变量，交给线程之后还活着吗？

函数建立局部字符串command，线程池的lambda用`[&command]`借用它。函数返回后command销毁；后台线程晚一些才访问，就在用已不存在的对象。指针非空、字符串曾有内容，都不能证明此时有效。

如果当前函数一直等待future结束，局部对象可能暂时活着；但你把等待改成“超时就return”，寿命条件随之改变。因此P6的超时优化不能只把get改成wait_for：还要决定参数复制、共享所有权、取消以及任务之后如何结束。

按值捕获会保存独立参数，能解决某类局部寿命问题，但并不自动解决被捕获的原始指针所指设备对象的寿命，也不自动使设备访问线程安全。

### B. 地址与数值怎样在脑中分开？

假设angle存0.2，p指向angle。`p=&angle`建立关系；`*p=0.5`改变angle；`p=nullptr`只改变p，angle仍0.5。若再解引用空p就错。引用ref作为angle的别名，`ref=0.7`改值，不是把ref改绑到另一个变量。

### C. 读电机报文的四个检查

先检查长度，再检查端序/有符号性，再做比例换算，最后保存同帧时间和序号。`0xFFFF`作为uint16是65535；若协议规定16位有符号补码，它对应−1。两种解释都能编译，只有协议定义能决定哪种正确。
