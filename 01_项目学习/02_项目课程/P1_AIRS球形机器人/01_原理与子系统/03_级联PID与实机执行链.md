# 03 级联 PID 与实机执行链：机器人怎样从“想前进”变成“球真的滚动”

## 0. 先分清三件不同的事

控制器同时要做三件事：

1. **保持平衡：**身体偏了，就让大球滚到身体下面支撑它；
2. **改变速度：**让机器人从静止加速，或把速度调快、调慢；
3. **到达位置：**让机器人停在指定位置，而不是只达到某个速度。

这三件事会互相影响。它们不是三台互不相干的电机，而是通过“身体倾斜—球滚动—身体位置变化”连在一起。

把球形机器人想成滑板上站着一个人：人的上身可以相对滑板倾斜；滑板需要滚到人身体的重心下方，才能继续托住人。球形机器人用三只驱动轮改变大球的位置，作用类似滑板的轮子，但其球面运动方向还要按三轮几何计算。

这里有一个容易混淆的说法：身体“向前倾”是身体相对大球/机身框架的姿态；机器人“向前走”是整机相对地面的位移。两个方向有关，但不是同一个量。

## 1. 从目标到电机的完整链

~~~mermaid
flowchart TD
    A[目标位置和目标速度] --> B[外环：比较目标与当前位置、当前速度]
    B --> C[生成有界的 Roll / Pitch 姿态参考]
    C --> D[内环：比较姿态角，并看 IMU 角速度]
    D --> E[得到虚拟控制量]
    E --> F[球面运动学分配 ik]
    F --> G[三只轮子的目标速度 v_des]
    G --> H[电机和驱动器]
    H --> I[球滚动，身体移动或恢复平衡]
    I --> J[IMU、编码器反馈和状态估计]
    J --> B
~~~

### 外环：根据“位置、速度差多少”决定身体该朝哪边倾

外环通常较慢，回答的是：“为了让机器人往目标方向移动，我现在需要什么样的身体姿态参考？”

以一个水平轴为例，可把它的意图概括成：

\[
\theta_d=
\operatorname{limit}
\left[
K_p(x_d-x)+K_v(v_d-v)
\right]
\]

- \(x_d-x\)：目标位置与当前位置的差；
- \(v_d-v\)：目标速度与当前速度的差；
- \(\theta_d\)：给身体姿态内环的倾角参考；
- limit：把倾角参考限制在允许范围内。

真实代码通过 XLoop/YLoop 和项目坐标符号实现这种关系。正负方向要看代码的坐标、安装方向和电机定义，不能单凭“向前”两个字猜一个正号。可以先记住功能：外环把“我想去哪、我现在走多快”变成“身体应该朝哪个方向倾一点”。

外环输出的是**姿态参考**，不是电机命令，也不是位置本身。它通常还会限幅，避免外环要求身体倾得太多。

### 内环：让身体跟上姿态参考，同时别冲得太快

内环运行较快，回答的是：“身体现在离姿态目标有多远？它正以多快速度转过去？”

先用最简单的比例加角速度阻尼说明：

\[
u_\theta=
K_p(\theta_d-\theta)
+
K_d(\dot{\theta}_d-\dot{\theta})
\]

若倾角参考暂时不变，\(\dot{\theta}_d=0\)，就变为：

\[
u_\theta=
K_p(\theta_d-\theta)-K_d\dot{\theta}
\]

第一项只看“还差多少角度”；第二项看“现在正以多快速度倾斜”。第二项像刹车：即使身体还没有到角度目标，只要它正快速朝目标冲去，角速度项就可能先减小甚至反转控制动作。这样控制器可以提前接住身体，不必等到它越过目标后再补救。

这只是帮助理解的理想化写法。项目中的 PID 类还带有积分、角度环绕、限幅和特定的微分分支，具体实现以源码为准。另一个要分清的符号是角速度：三轮运动学章中的 \(\boldsymbol{\omega}\) 指**大球**的角速度；这里姿态内环读取的 IMU 角速度指**机身**的角运动。它们属于不同物体，即使都用 omega 表示，也不能直接当成同一个数。

### 执行映射：虚拟控制量怎样变成三只轮的速度

姿态控制器算出的 \(u_\theta\) 等轴控制量不是三个电机的直接力矩。当前源码把姿态 PID 的输出保存在 tau_roll、tau_pitch、tau_yaw 变量中，但没有在这里用转动惯量求角加速度，也没有把角加速度积分成大球角速度。随后程序将中间量与 CoM 项合成，乘 ik 矩阵和 K_t2v 系数，直接生成三只轮子的速度命令数值。

从几何原理看，球轮逆运动学矩阵本来可以把“期望大球角速度”分配成“三个小轮的角速度”。但要把当前控制器这一行严格解释成这个物理映射，输入必须已经是单位为 rad/s 的大球目标角速度；本控制周期没有清楚展示这种中间量是怎样从姿态 PID / CoM 项中按物理量纲推导出来的。因此更准确地说：它使用球轮几何分配矩阵形成三个速度目标，但中间数值到 rad/s 的标定依据尚不能从当前源码单独证明。

电机接口最后把 v_des 当作电机轴目标角速度，单位 rad/s。它不是轮缘线速度 m/s，也不是直接发给电机的力矩。轮缘线速度在理想圆轮滚动下才可由 \(v=r\dot\phi\) 换算；球面接触方向还要考虑轮子布局。

因此应区分：

- **姿态环的虚拟控制量：**控制器希望球/身体产生什么方向的控制作用；
- **三轮目标速度 \(v_{\text{des}}\)：**分配后发送给驱动器的速度命令；
- **电机力矩：**电机实际输出的物理作用，需由驱动器和电机电流闭环产生。

本项目此处发布的主要命令是轮子目标速度，不要把它说成“控制器直接给三个轮子发布了 LQR 力矩”。球面分配的细节见[三轮球体运动学分配](02_三轮球体运动学分配.md)。

## 2. 目标速度为零时，为什么轮子还会动？

“目标速度为零”表示希望整机最后不平移，并不表示电机每一刻都必须零输出。

假设机器人正直立、传感器没有噪声、身体完全没有扰动，控制命令可能接近零。但真实系统会遇到：

- 身体稍微偏斜；
- IMU 和编码器读数有噪声；
- 大球与驱动轮或地面有微小滑动；
- 手臂改变质心；
- 电池、电机和地面带来未建模的影响。

这时，即使外环仍要求“不改变位置、不加速”，姿态内环也要让轮子短暂运动，把球移到更合适的位置。轮子短暂转动是在**纠正身体姿态**，不等于控制器打算让机器人持续向前走。

所以：

> 目标速度为零，不等于所有电机命令永远为零；它表示控制器要阻止整机持续漂移，同时允许轮子为了平衡作短暂修正。

## 3. 目标速度不为零时，机器人为什么会前进？

这是最关键的运动直觉：**身体倾斜是产生加速的短暂方式；达到目标速度后，身体可以重新接近直立，球仍继续滚动。**

以向前加速为例，把动作分成几段：

### 第一步：控制器发现“还不够快”

例如目标速度是向前 \(0.5\text{ m/s}\)，而当前速度是 \(0\)。外环看到 \(v_d-v>0\)，会生成一个向前加速所需的姿态参考。具体是正 pitch 还是负 pitch，取决于项目坐标约定；先只看身体需要朝“希望加速的方向”产生一个小倾斜。

### 第二步：身体姿态发生变化

内环推动球和机身发生相对运动，使身体朝姿态目标倾斜。为了让身体相对球向前倾，球在**身体参考系里**可能先短暂向后移；这来自驱动轮对球施力时的反作用。

这里的“球向后”是球相对机身的运动，不等于整台机器人已经向后走，也不等于后续必须一直向后滚。

### 第三步：大球向前滚，给整机向前加速

身体的质心已经偏向前方。如果大球还留在身体后面，身体会继续倒下。控制器接着让大球向前滚到质心下方，提供支撑；球与地面的滚动同时带动整机向前加速。

因此，启动阶段为了建立“身体向前倾”的相对姿态，球可能先相对机身向后调整；产生向前的整机运动时，球又要相对地面向前滚。一个描述**身体与球之间的相对运动**，一个描述**整机相对地面的移动**，参考系不同，听起来才像方向矛盾。具体电机正转/反转还要按每只轮的轴向和符号约定核对。

### 第四步：速度达到目标，倾角参考减小

当当前速度逐渐接近目标速度，速度误差 \(v_d-v\) 变小，外环不再要求那么强的向前加速，倾角参考就会减小，身体回到接近直立。

但机器人不会因此立刻停下：球可以保持向前滚动，整机以已经达到的速度继续前进。就像推自行车到一定速度后不再继续加大推力，自行车仍会因为已有速度继续向前。理想无阻力的简化情况下，身体可接近直立而球继续滚动；真实系统有滚动阻力、摩擦和外扰，控制器可能需要持续给一点补偿，所以不保证姿态参考恰好等于零。

若目标是某个固定位置，位置外环还会判断离终点多远，并在接近目标时生成减速需求；身体和球随后产生反向加速度，使机器人停下来。

把过程压缩成一句话：

\[
\text{速度误差}
\rightarrow
\text{短暂倾斜、产生加速度}
\rightarrow
\text{速度误差变小}
\rightarrow
\text{身体回正，但球继续按目标速度滚动}
\]

## 4. 角速度项为什么会在还没到角度目标时就改变动作？

假设角度正方向定义为前倾，姿态目标是 \(0.05\text{ rad}\)，身体现在是 \(0.03\text{ rad}\)，而且正以 \(0.1\text{ rad/s}\) 很快继续前倾。用教学参数 \(K_p=161\)、\(K_d=46.8\)，并假设期望角速度为零：

\[
u_\theta
=161(0.05-0.03)+46.8(0-0.1)
\]

\[
u_\theta=3.22-4.68=-1.46
\]

角度误差项 \(+3.22\) 还想让身体继续前倾；角速度项 \(-4.68\) 认为身体已经冲得太快，于是总输出变成 \(-1.46\)，提前制动。

这回答了“如果一开始没有超调怎么办”：**不必先超调。**角速度反馈会根据身体正在怎样运动，提前制动。这里的负号表示按这组教学符号约定，控制作用已经转向制动；它不应直接被解读为“某一个编号电机反转”，因为之后还要经过坐标变换、比例缩放和三轮分配。

角速度项不是“额外再套一个速度环”的同义词。它是姿态内环中用于抑制倾斜运动过快的一部分。

把它和“轮子什么时候从向后变成向前”连起来看：

1. **建立前倾：**控制器先让身体产生向前的角运动；按常见的反作用直觉，大球可能先相对机身向后调整。
2. **提前接住：**身体前倾角还没到参考值，但正向前的角速度已经很大。角速度项增大并抵消角度项；当它超过角度项，姿态环的虚拟控制量就会换方向。
3. **让球向前承接身体：**控制作用换向后，球被驱动到质心下方，并产生向前的整机加速度。姿态还在目标角度之前，控制器就能开始这一步，不用等身体先超调。
4. **保持目标速度：**当速度误差继续缩小时，外环减小加速姿态参考；角度环回到平衡附近，球继续保持所需滚动速度。

“虚拟控制量换向”不等于某一只电机一定从正转变反转。它要经过带有符号约定的球轮矩阵和驱动器字段，才能对应到各轮的实际方向。

## 5. “轮子先向后，后来向前”该怎么理解？

先问清楚“向后”说的是哪一个东西、相对谁：

1. **电机轴转向：**正转还是反转，取决于电机安装和软件符号；
2. **大球相对机身：**球在身体下面向哪边移动；
3. **机器人相对地面：**整机实际向哪边走；
4. **身体姿态：**身体相对竖直方向向哪边倾。

这四个量不能直接画等号。球形机器人通过小轮和大球之间的接触传力，身体还会因反作用相对大球倾斜。启动倾斜、加速、保持速度、刹车时，控制目的不同，轮速方向也可能改变。

用最稳妥的方法判断方向：

- 先固定图上的 \(x,y,z\) 正方向；
- 再查该轮的轴向和电机正方向；
- 用[三轮球体运动学分配](02_三轮球体运动学分配.md)把给定球角速度映射为轮速；
- 最后确认驱动器的速度符号和实际安装一致。

所以不要仅凭“身体向前倾”就断言三只电机都应向后转，也不要把“轮子转向”直接当作机器人平移方向。

## 6. 把刚才的直觉对应回项目源码

现存控制路径可概括为：

1. IMU 回调提供姿态和角速度；关节回调提供轮子和手臂状态；
2. 控制周期从轮反馈估算球角速度、局部速度和位置；
3. 当前位姿与目标位姿先变到机身方向，再求误差；
4. XLoop/YLoop 根据位置和速度误差生成 pitch/roll 参考，并做限幅；
5. 姿态环比较实际角度、目标角度和角速度，形成虚拟控制量；
6. 球体运动学矩阵把控制量分到三轮目标速度；
7. 程序设置驱动消息字段，驱动器再让电机跟踪目标速度。

几个源码细节应与“控制原理”分开记：

- 外环中的世界到机身变换只旋转水平分量；平移误差通过当前量与目标量相减得到。
- cmd_vel 回调对目标速度做平滑，并按配置的命令周期积分目标位置；控制周期再积分估计位置。若真实消息时间间隔和配置值不一致，积分会有偏差。
- 角度误差会按周期范围归一化；积分和输出都有限幅。该版本的积分截断不等于回算式抗积分饱和。
- PID 辅助类在某个微分输入为零时会改用误差差分；零也可能是合法角速度，不能把它当作“测量无效”的标志。
- 实机命令主要是轮子目标速度 \(v_{\text{des}}\)。控制器的虚拟量不是直接的电机力矩。
- 配置中的循环频率只是预设值，不等于已经测得的真实周期；闭环快慢、延迟与是否稳定需要看日志和实测。
- 姿态环、球轮映射、限幅和驱动模式要串起来看，不能只看 PID 参数推断整机结果。
- 当前 launch 默认循环频率为 \(100\text{ Hz}\)，cmd_vel 目标更新频率为 \(10\text{ Hz}\)，平滑系数为 \(0.25\)。这些是配置默认值，不是已经测到的实时频率或延迟。
- 目标 yaw 角速度会被平滑并用于目标 yaw 积分；源码里虽然保存了 yaw_angular_d_，但当前调用 YawLoop 时没有把它作为目标角速度参数传入。
- setVelocityCommand 在 mode 0 下仍把计算结果放进 v_des，同时将位置比例项设为零、位置阻尼项取轮速 Kp、t_ff 清零；mode 1 下写 v_des、v_kp 和 v_ki。launch 默认 mode 0，而构造函数默认值为 1；实际运行模式要看 launch 参数和驱动器定义。

### 6.1 把教学控制图和项目当前源码对上

前面的流程图讲控制职责；下面这些是当前源码快照中的实现细节。它们解释“这份程序现在怎么算”，不应误说成所有球形机器人的固定参数。

- 位置外环把目标与当前的位置、速度送入 XLoop/YLoop；结果是 pitch/roll 参考。当前配置的外环输出限幅约为 \(0.1\text{ rad}\)。
- 当前 XLoop 的示例配置为 \(K_p=0.06,K_d=0.3,K_i=0\)。若位置误差已稳定在 \(0.2\text{ m}\)，速度差为零，且微分历史也已稳定，倾角参考约为 \(0.06\times0.2=0.012\text{ rad}\)。
- 若误差从 \(0\) 突然变成 \(0.2\text{ m}\)，而微分项用 \(dt=0.01\text{ s}\) 做误差差分，那么差分是 \(0.2/0.01=20\text{ m/s}\)，微分项会很大，输出会被 \(0.1\text{ rad}\) 限幅截住。这说明参考平滑和历史初始化会影响瞬间输出；这个静态算例不是实际机器人响应测试。
- 角度 PID 以目标减当前形成误差；角误差会环绕到合理范围，积分误差和输出会分别限幅。其积分限幅不是回算式 anti-windup。
- 这个 PID 辅助类在当前速率输入 \(xd\ne0\) 时使用目标速率减当前速率；当 \(xd=0\) 时则改用误差差分。零可能是合法的“当前角速度为零”，因此这只是源码的分支写法，不是可靠的“传感器数据有效标志”。目标速率是第四个参数 \(txd\)，不是这里的分支条件。
- cmd_vel 回调以配置的命令周期平滑速度并积分目标位置；控制定时器按自己的周期积分估计位置。若消息实际间隔和配置周期不一致，目标积分与当前估计积分会逐渐错开。
- 姿态环的虚拟量经缩放和 ik 分配后成为轮子速度目标；某些反馈分量和前馈分量经历的缩放次数不同，限幅还会改变最终数值。具体顺序见[三轮球体运动学分配](02_三轮球体运动学分配.md)和[一个周期的调用与数据流](../02_源码阅读与运行/02_一个周期的调用与数据流.md)。
- 驱动消息的速度/阻抗模式由 launch 和 driver 配置共同决定。变量名里有 tau 或 torque，不足以证明最终发送字段是电机力矩；要检查实际写入的消息字段。
<a id="pid-ports"></a>
### 6.2 按函数参数认清每一环的输入和输出

PID 公共接口是 `controller(x, xd, tx, txd=0)`：`x` 是当前值，`xd` 是当前变化率，`tx` 是目标值，`txd` 是目标变化率。同一个类被用于不同物理量，单位要随调用改变。

| 调用 | 当前值 / 当前速率 | 目标值 / 目标速率 | 输出与消费者 |
|---|---|---|---|
| XLoop | `bx`（m）/ `vx_`（m/s） | `bx_d`（m）/ `vx_d_`（m/s） | `pitch_d_`（rad），给 PitchLoop |
| YLoop | `by`（m）/ `vy_`（m/s） | `by_d`（m）/ `vy_d_`（m/s） | 结果先取负号成为 `roll_d_`（rad），给 RollLoop |
| RollLoop / PitchLoop | 机身角度（rad）/ 滤波 IMU 对应轴角速度（rad/s） | 外环倾角参考（rad）/ 省略的第四参数为 0 | 姿态中间控制量，再乘第一次 `K_t2v_` |
| YawLoop | yaw（rad）/ 滤波 IMU z 角速度（rad/s） | `yaw_d_`（rad）/ 默认 0 | yaw 中间控制量；没有传入已缓存的 `yaw_angular_d_` |
| `wheel_controller_` | 当前周期未调用它的 PID 运算 | 当前周期未构造这一层的误差 | 取它的增益和上限，填写电机接口并限制三轮范数 |

因此当前外环是“位置误差和速度误差共同形成倾角”的一层 PID/PD，没有额外实现一条独立的“位置 PID → 速度 PID → 姿态 PID”三层链。所有主机 X/Y 和姿态计算都在同一个默认 100 Hz 定时器里执行；“外环较慢、内环较快”首先指希望实现的**闭环响应速度/带宽**，不能把它说成源码已经给外环另建了低频定时器。10 Hz 的 `cmd_freq` 是目标位置积分的时间假设。

例如外环输出按 rad 定义时，\(K_p\) 需有 rad/m、\(K_d\) 需有 rad·s/m、\(K_i\) 需有 rad/(m·s) 的对应尺度。姿态 PID 若输出单位记为尚未标定的 \(U\)，三个增益分别需要 \(U/\mathrm{rad}\)、\(U\cdot\mathrm{s}/\mathrm{rad}\)、\(U/(\mathrm{rad}\cdot\mathrm{s})\)。增益数字本身不能证明 \(U=\mathrm{N\cdot m}\)。

<a id="pid-filter-timing"></a>
### 6.3 滤波发生在收到消息和发布命令时，不能把整周期都叫滤波

当前 `initializeFilters()` 将截止频率 0.8 Hz、设计采样频率 `freq_` 传给滤波器。IMU 回调只低通角速度，姿态四元数直接复制；轮状态回调低通三轮 velocity；CoM 回调低通 x/y。定时器读取这些缓存，完成两环、前馈和分配后，先整体限幅，再在命令发布函数中低通三轮 `v_des`。`cmd_vel` 的 0.25 逐消息平滑是另一路目标处理。

源码一阶低通为 \(y_k=\beta x_k+(1-\beta)y_{k-1}\)，100 Hz 设计下 \(\beta\approx0.04786\)。常数阶跃从 0 变到 1 时，\(y_n=1-(1-\beta)^n\)：约 62 次更新才超过目标的 95%。若实际每 10 ms 更新一次，约需 0.62 s；若实际每 20 ms 更新一次而系数不变，则约需 1.24 s。这是**该递推的教学阶跃计算**，并非实机总延迟，也不是每个频率分量都延迟同样时间。

滤波使高频噪声对 D 项和轮命令的影响减小，同时使真实角运动与控制动作到得更晚。姿态角、角速度、CoM 和轮速又来自不同历史，所以不能把“读到一组平滑值”当成“读到同步的真实状态”。评估时要保存原始值、滤波值、接收时刻及使用时刻；仅看一条更光滑的曲线无法判断平衡效果。

<a id="pid-torque-integral"></a>
### 6.4 真正的力矩怎样变成角速度，时间间隔为什么不可省略

先只研究一个转轴，假设惯量固定、没有其他耦合。**合力矩** \(\tau_{\mathrm{net}}\) 造成角加速度：

\[
\dot\omega=\alpha=\frac{\tau_{\mathrm{net}}}{I_{\mathrm{eq}}},\qquad
\omega(t+\Delta t)=\omega(t)+\int_t^{t+\Delta t}\alpha(s)\,ds.
\]

若这一小段内力矩保持不变，显式欧拉近似是 \(\omega_{k+1}=\omega_k+(\tau_{\mathrm{net},k}/I_{\mathrm{eq}})\Delta t_k\)。\(\Delta t_k\) 来自相邻实际更新时刻之差；固定设计周期只是模拟或实现中的时间假设。电机力矩还需减去负载、摩擦等作用才是合力矩，完整机器人则要解耦合动力学，不能只拿某个轴的惯量独立相除。

教学例：\(I_{\mathrm{eq}}=2\ \mathrm{kg\cdot m^2}\)、合力矩 \(4\ \mathrm{N\cdot m}\)、原角速度 \(0.30\ \mathrm{rad/s}\)。则角加速度为 \(2\ \mathrm{rad/s^2}\)。经过 10 ms，角速度为 0.32 rad/s；再过 10 ms 为 0.34 rad/s。经过 5 ms 则只增加 0.01 rad/s。力矩一样，速度变化还由惯量、持续时间和原速度决定。

而当前 `0.75 * tau` 每次对相同输入给相同数，没有读取原球角速度，也没有在这段映射中用惯量与 \(\Delta t\) 积分。它是静态缩放关系，不能替代上述时间演化。若另有经验证的稳态导纳 \(\omega=\tau/b\)，常数也可能具有“速度/力矩”的物理意义，但需要阻尼模型或标定证据；本源码没有展示这一依据。

<a id="pid-double-scale"></a>
### 6.5 两个 0.75 的数值效果与单位条件

令 \(\mathbf p\) 是三个姿态 PID 的输出，\(\mathbf f\) 是 CoM 加入的补偿数值，限幅和滤波之前的源码为：

\[
\mathbf s_{\mathrm{raw}}=k\,ik\,(k\mathbf p+\mathbf f)
=0.5625\,ik\,\mathbf p+0.75\,ik\,\mathbf f,
\quad k=0.75.
\]

反馈经历两次缩放，前馈只经历后一次。在线性分配这一阶段，如果两个输入恰好各沿同一轴为 1，则它们对三轮输出的系数分别是 0.5625 和 0.75；不能把补偿也算成 0.5625。限幅触发或滤波历史不同时，最终发布值不能继续按这两个裸系数直接比较。

数值相同不说明前后两次系数承担相同的单位转换。为了做单位审计，暂把它们写成 \(k_1,k_2\)：若加法处的共同单位为 \(G\)，PID 输出为 \(U\)，由于 ik 无量纲，就必须满足

\[
[k_1]=G/U,\qquad [\mathbf f]=G,\qquad
[k_2]=(\mathrm{rad/s})/G.
\]

若把 \(\mathbf p\) 和 \(\mathbf f\) 都称为 N·m，第一系数要无量纲，第二系数才可解释为 (rad/s)/(N·m)；若把同一个 `t2v` 两次都宣称是“力矩转速度系数”，加法处就不再自然同量纲。要成立，必须另外说明 PID 的输出尺度、前馈的归一化或两处标定意义。当前 YAML 只给数值 0.75，所以文档记录**真实运算式**和**尚缺的标定证据**，不推断电机实际力矩。

## 7. 最容易记混的三组说法

| 听起来相近的量 | 实际区别 |
|---|---|
| 倾角目标 \(\theta_d\) 与前进速度目标 \(v_d\) | 倾角目标是内环参考；速度目标是外环希望实现的移动状态 |
| 目标速度为零与电机命令为零 | 零速度目标仍可能需要轮子短暂动作来维持平衡 |
| 角度误差与角速度 | 角度误差表示离目标多远；角速度表示姿态正在变化多快 |
| 球相对机身的方向与整机相对地面的方向 | 参考系不同，动作方向可能相反 |
| 虚拟控制量与电机力矩 | 虚拟量还要经过球面运动学和驱动器接口，才能成为轮速/电机动作 |

## 8. 面试时可以这样解释

> “The outer position and velocity loops generate a bounded body-tilt reference. The inner attitude loop uses both pitch error and angular rate, so it can brake the body before it overshoots. A temporary lean creates the acceleration needed to change the robot’s speed. Once the target speed is reached, the body can return close to upright while the ball keeps rolling. The controller then maps the virtual command to three wheel-speed references.”

中文意思：位置和速度外环生成有限的身体倾角参考；姿态内环同时看倾角误差与角速度，所以可以在身体冲过目标前制动。短暂倾斜产生改变速度所需的加速度；达到目标速度后，身体可以回到接近直立，而大球继续滚动。之后控制器把虚拟控制量分配为三只轮的目标速度。

## 9. 一句话复习整条链

\[
\boxed{
\text{目标位置/速度}
\rightarrow
\text{外环给身体倾角参考}
\rightarrow
\text{内环用角度和角速度稳住身体}
\rightarrow
\text{球面运动学分配到三轮}
\rightarrow
\text{电机带球滚动}
\rightarrow
\text{传感器反馈并重算}
}
\]

不要把“短暂倾身产生加速度”误解成“机器人必须一直倾着才能保持速度”；也不要把“球在身体下方滚动的方向”误解成“身体和机器人相对地面的方向”。

## 历次提问归纳：控制量不等于电机物理量

本节归纳多轮关于“输出到底是什么、怎样到轮子”的追问；完整索引见 [P1 历次问题归纳与完整讲解](../05_中英文面试/06_历次问题归纳与完整讲解.md)。

- **外环做什么？**位置/速度外环把运动误差变成机身倾角参考；倾角通过重力和接触作用帮助底盘加速或减速。它不是直接把位置误差换成电机力矩。
- **内环输出一定是力矩吗？**不能只由 `tau` 变量名判断。只有模型、标定和单位链都支持时，才可称为 N·m；若后续经过 `K_t2v`、球轮几何矩阵 `ik` 并作为速度消息发布，最终接口就不是“直接发送力矩”。
- **姿态反馈和 CoM 前馈为什么能相加？**它们只有在进入同一个控制通道、同一坐标轴、同一有效量纲/缩放后，才能作为代数项合成。代码里的缩放位置不同会让两项比例不同，因此要沿调用顺序核对，不能仅因都叫 `tau_*` 就断言单位相同。
- **球角速度怎样变成三只轮的命令？**先用接触几何映射，再看输出字段是轮角速度、RPM 还是其他接口量；整体限幅与低通滤波还会改变最终发布值。一个控制周期中的中间量不一定等于电机最后收到的数值。
- **滤波为何有代价？**平滑能压高频噪声，也会增加相位延迟；滤波位置、系数和采样周期都要一起看，不能把“做了滤波”理解为噪声完全消失。
