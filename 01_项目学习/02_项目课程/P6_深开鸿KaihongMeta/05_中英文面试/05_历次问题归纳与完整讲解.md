# P6 历次问题归纳与完整学习地图

> 本文把 P6 的设备抽象、并发、协议和动作回执问题按软件数据链重新组织；不重复粘贴面试题。原题答案见 [P6 原理、实现与验证问答](02_原理实现与验证问答.md)。
>
> **范围边界**：当前材料是设备接入/控制组件的源码快照。组件名、平台名或历史项目描述不能代替版本、构建、硬件运行和个人贡献证据。
>
> **整理口径：**P6 目前按“提前学习地图”整理。这里把项目文档和已有源码中容易误读的点归并成可复习问题，不把新补充的训练题说成用户已经问过，也不把静态推演说成实机验证。

## 1. 先分清能力、状态和动作

- **能力**：设备理论上支持什么，例如能否移动、是否支持位置反馈。
- **状态**：设备此刻是否在线、位置/温度是多少、数据何时更新。
- **动作**：软件请求设备做什么，含参数、单位、目标、期限和唯一 ID。
- **结果/回执**：任务是否排队、协议是否发送、设备是否确认、动作是否完成，是不同阶段。

统一接口让上层能以类似方式使用设备，但接口相同不代表设备能力、动作单位和安全限制相同。

## 2. C++ 抽象与资源生命周期

接口定义“能做什么”，具体适配器实现“对某设备怎样做”。若通过基类指针销毁派生对象，基类析构函数需要虚析构；RAII 让资源随对象生命周期释放；`unique_ptr` 表达独占所有权，减少谁负责 delete 的歧义。

设备对象生命周期应能说清：创建/发现 → 身份识别 → 初始化 → 注册能力 → 在线与状态更新 → 停止接收新任务 → 等待/取消在途任务 → 关闭协议资源 → 销毁对象。

## 3. 线程池、回调和共享状态

线程池把任务交给有限数量的工作线程。回调可能同时读写设备缓存，保护共享结构需要一致策略：短锁、快照、不可变消息或队列都可以；“加了锁”不自动消除锁顺序死锁，也不保证读到的不同字段来自同一个采样时刻。

`future` 保存异步任务结果，但 `.get()` 会等待；异步提交不等于端到端非阻塞。若工作线程等待自己排队的任务、持锁等待 I/O，或队列无界，系统会出现阻塞、死锁或积压。关闭时要停止接收新任务并定义在途任务的完成/取消策略。

线程优先级表达调度偏好，不单独证明期限一定满足。实际延迟需测提交、开始、完成和排队时间。

## 4. 设备发现、注册、协议适配与状态同步

发现回答“看到了什么连接”，注册回答“把哪个设备和适配器/能力放入软件名册”，初始化回答“它是否准备好通信”，状态同步回答“最近反馈的设备状态是什么”。这几步不能合成一个“设备已连接”。

协议适配器负责把统一动作翻译成某硬件的字段、单位、校验和/事务；解析回包再映射成统一状态。要核对消息长度、字节序、范围、超时、设备 ID、异常码和反馈时间。协议 ACK 通常证明数据被某层接收，不一定证明物理动作完成。

注册要幂等：重复发现同一设备不能无限创建重复实例；但注册幂等也不意味着设备动作只执行一次。

## 5. 动作策略、命令关联和幂等

一次动作建议沿链检查：请求是否合法 → 设备/能力/模式是否允许 → 参数与单位是否有效 → 创建 command ID/deadline → 排队 → 适配器发送 → 设备 ACK/状态回报 → 按 ID 关联结果 → 超时/重试/取消。

网络重试可能让同一动作再次到达。幂等是同一 ID 重复提交时系统能避免重复副作用，常通过命令记录/设备侧去重/状态比较实现；只有“去重缓存”或“收到 ACK”不足以声称 exactly-once。

## 6. 跨硬件可移植与故障恢复

统一接口的价值在隔离硬件差异；其代价是需要显式描述能力、限制、状态新鲜度和错误语义。不能把一种设备的“stop”映射成另一设备同名字段后就认为行为相同。

故障应分层定位：物理链路、协议解析、设备身份/能力、任务队列、回调/锁、动作超时、状态过期、界面显示。恢复要定义重连后是否重新发现/注册、旧动作是否作废、缓存如何重新确认，以及正在运行的动作怎样处理。

## 7. 复习时用一次命令检查整个软件栈

假设应用请求“设备 A 移动 0.2 m”：确认单位与设备能力；检查 A 是谁发现/注册的；看命令是否有 ID/deadline；跟到队列与具体适配器；看协议怎样编码；区分发送成功、设备 ACK、实际状态改变；若超时，确认重试会不会重复动作；最后检查缓存时间与网页显示是否是设备新反馈。

## 8. 本地源码中特别容易讲错的八个点

1. **Init 后 online 不等于硬件刚刚响应。**当前 BaseDeviceHandler::Init 在子类 OnInit 成功后调用 SetDeviceOnline；ReportProperty 也可能在上报前置 online。必须继续查最后一次成功通信和反馈时间。
2. **写命令后的缓存不是独立读回。**GroundLock 的 WriteLockCommand 在 Modbus 写成功后把 currentStatus 更新为控制值并上报；必须和后续寄存器读回/传感器到位分开。
3. **协议地址不是 C++ 数组下标。**代码从地址 0 请求 17 个寄存器，状态取 allData[7] 并注释为 0x0006。要查底层返回 vector 的布局和设备寄存器表。
4. **读取失败时输出参数仍可能有旧数值。**ReadLockStatus 的失败路径写回缓存，但返回非成功码；数值存在不表示它是本次测量。
5. **join 不表示队列逐项完成。**ThreadPoolManager::Shutdown 设置关闭标志并 join，worker 外层循环受关闭标志控制。静态阅读不能推出所有排队任务都拿到结果；要检查未完成 promise 和等待者的退出策略。
6. **轮询参数改变不等于立即改下一次触发时刻。**接口以秒接收、内部以毫秒保存；全局默认值和已存在 schedule、设备级 interval 与 nextRunTime 是不同字段。
7. **短任务优先不等于正在运行的轮询会被抢占。**短任务开始时可能清掉排队长任务，长任务 worker 也可能跳过尚未开始的轮询；已经在设备 I/O 中的任务不会因此自动中断。
8. **被弹出的任务与它的取消记录是两件事。**`ClearPendingLongTasks` 设置取消标志并弹出队列任务，但没有在该路径删除 `taskCancelFlags_` 项；反复清理可能留下记录，是否持续增长需观测 map 大小。
