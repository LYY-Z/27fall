# P3 术语与三种长度口述

## 使用边界

这是可练习的参考答案，不替用户确认个人职责。只有本人确实完成的动作才能用I implemented/I designed。现存团队/平台代码用the implementation；新教学用a separate learning experiment。结果数值需日志，没有则解释验证方法。

## 常用术语：先用中文讲动作，再说英文词

|中文|英文|先在脑中想成什么|
|---|---|---|
|级联控制|cascaded control|外层看角度差，内层看转速差，再产生电机动作|
|角速度反馈|angular-rate feedback|陀螺告诉控制器云台正在转多快，用来跟速和提前刹车|
|摩擦轮|friction wheel|高速转动并靠表面摩擦把弹丸带出去的轮子|
|拨弹机构|feeder mechanism|把弹丸送到发射位置的拨盘/机构|
|滑模控制|sliding-mode control|根据误差与误差变化方向切换控制作用的一种反馈方法|
|功率缓冲|power buffer|电力短时不够时减少动作强度或使用储能信息调节输出|
|任务优先级|task priority|多个工作抢CPU时谁先得到处理机会|
|失联检测|communication-loss detection|一段时间没收到设备消息后标记通信异常|

练习时先讲一个可见动作，例如“云台还差两度，但已经转得很快，所以内环先减速”，然后才说`angular-rate feedback`。项目总链见[P3白话总览](../00_项目全貌与学习路线/03_P3端到端任务与反馈链.md)。

公式读法与澄清句见[技术英语](../../../04_面试训练/01_技术英语/01_术语单位公式与矩阵读法.md)。

## 30秒：先让面试官听懂问题

This project concerns the embedded control of a RoboMaster hero robot. The system coordinates the gimbal, launcher and mecanum chassis using motor feedback, an IMU, CAN communication and FreeRTOS tasks.

中文主线：系统是什么→要解决什么→关键方法。实际速度因人而异，30秒是训练目标，需自己计时。

## 90秒：加入方法和实现边界

This project concerns the embedded control of a RoboMaster hero robot. The system coordinates the gimbal, launcher and mecanum chassis using motor feedback, an IMU, CAN communication and FreeRTOS tasks.

The gimbal uses an angle loop to generate a rate reference and a rate loop to generate a motor command. The launcher needs both stable friction-wheel speed and reliable feeder motion. Chassis commands are mapped to wheel references and adjusted using available power information.

My personal responsibility and measured performance must be stated from my own records. I distinguish the active source path from historical controller versions and from separate learning simulations.

中文主线：问题→数据链→方法理由→一个实现点→证据边界。讲到复杂术语后留一句直觉解释，不一次报完技术栈。

## 3分钟：模型、实现、验证与反思

This project concerns the embedded control of a RoboMaster hero robot. The system coordinates the gimbal, launcher and mecanum chassis using motor feedback, an IMU, CAN communication and FreeRTOS tasks.

The gimbal uses an angle loop to generate a rate reference and a rate loop to generate a motor command. The launcher needs both stable friction-wheel speed and reliable feeder motion. Chassis commands are mapped to wheel references and adjusted using available power information.

In the available snapshot, the active friction-wheel path calls sliding-mode controllers; the variable-gain PID calls are commented out. The wheel-speed PID is active. The power module solves a quadratic scaling problem, but its subsequent restoration step requires separate checking.

I would record angle error, rate error, wheel-speed recovery, feeder completion, command saturation and communication age. A configured task period is not evidence of measured timing, and team awards do not establish my individual module ownership.

My personal responsibility and measured performance must be stated from my own records. I distinguish the active source path from historical controller versions and from separate learning simulations.

中文主线：模型输入输出/假设→一个实际函数链→一个已能解释的限制→怎样量化→个人贡献。不要将教材里的“会做”变成历史“做过”。

## 在口述中插入自己的贡献

确认职责后用：“My responsibility was [specific module]. I chose [method] because [reason]. I checked it using [actual data and metric]. The main limitation was [observed limitation].”

方括号必须用本人事实替换。没有记录则说：“I can explain the design, but I do not have a verified measurement for that performance claim.”
