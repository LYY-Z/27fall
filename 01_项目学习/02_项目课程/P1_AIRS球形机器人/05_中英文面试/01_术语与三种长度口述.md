# P1 术语与三种长度口述

## 使用边界

这是可练习的参考答案，不替用户确认个人职责。只有本人确实完成的动作才能用I implemented/I designed。现存团队/平台代码用the implementation；新教学用a separate learning experiment。结果数值需日志，没有则解释验证方法。

## 常用术语：先用中文讲动作，再说英文词

|中文|英文|先在脑中想成什么|
|---|---|---|
|级联控制|cascaded control|外环先定身体该怎么倾，内环再让它稳住这个倾角|
|倾角参考|tilt reference|控制器希望机身达到的倾斜角，不是电机命令|
|球轮分配|ball-to-wheel allocation|把一个球的转动要求拆成三只驱动轮各自的转速|
|质心|center of mass|把每个部件的位置按质量加权后得到的整体平衡位置|
|重力前馈|gravity feedforward|已知手臂姿势会带来重力矩，先估算并提前抵消一部分|
|四状态模型|four-state model|用位置、速度、倾角和倾角速度描述简化后的机器人|
|积分饱和|integrator windup|电机已经顶到上限，控制器却还不断累加旧误差|
|角速度|angular velocity|机身朝某个轴转得多快，常用rad/s|
|轮速反馈|wheel-speed feedback|编码器告诉控制器轮子实际转多快|
|跌倒检测|fall detection|判断倾角是否超过允许范围，不自动等于电机已停|
|使能|enable|允许控制路径继续发动作的开关状态|
|限幅|saturation|把过大的命令压在设定上限以内|

第一次练习口述时，不要从表格背术语。先讲“手臂挪动→质心变→重力矩变→控制器提前补偿”，再用`center of mass`、`gravity feedforward`替换其中两个中文词。项目全貌见[端到端总览](../00_项目全貌与学习路线/03_P1端到端闭环、数据时序与实时性.md)。

## 90秒：加入方法和实现边界

This project concerns a ball-balancing robot with two arms. The central challenge is keeping the body balanced while controlling motion and accounting for changes in the center of mass. The available implementation uses cascaded PID feedback, ball-to-wheel allocation and a model-based gravity feedforward path.

The outer loop turns position and velocity errors into bounded roll and pitch references. The inner loop uses body attitude and angular-rate feedback to generate the command that is allocated to three wheels. I find it useful to explain this as two responsibilities: deciding where to move and maintaining balance during that movement. Arm joint states also update a URDF-based center-of-mass calculation, which supplies a gravity compensation term.

The source explains the control structure, but personal authorship, the exact deployed version and measured performance require project records. The new geometry, balance and CoM scripts are separate teaching experiments; they are not evidence of historical robot performance.

中文主线：问题→数据链→方法理由→一个实现点→证据边界。讲到复杂术语后留一句直觉解释，不一次报完技术栈。

## 3分钟：模型、实现、验证与反思

This project concerns a ball-balancing robot with two arms. The central challenge is keeping the body balanced while controlling motion and accounting for changes in the center of mass. The available implementation uses cascaded PID feedback, ball-to-wheel allocation and a model-based gravity feedforward path.

The outer loop turns position and velocity errors into bounded roll and pitch references. The inner loop uses body attitude and angular-rate feedback to generate the command that is allocated to three wheels. I find it useful to explain this as two responsibilities: deciding where to move and maintaining balance during that movement. Arm joint states also update a URDF-based center-of-mass calculation, which supplies a gravity compensation term.

In the local version, the launch file and CMake target select the C++ compensation controller. Its output is a wheel velocity command rather than a direct wheel torque command. The code applies the torque-to-velocity factor in two places, so feedback and feedforward do not have identical scaling. The CoM node publishes both position and velocity, but the controller consumes only CoM position. A separate continuous four-state model supports LQR analysis, while the deployed-control description in the material concerns PID. The arm motions should be described as fixed trajectories unless additional evidence supports a broader claim.

For validation, I would compare attitude error, position error with an external reference, command saturation and recovery after a defined disturbance. A feedforward comparison needs the same arm trajectory, initial condition and feedback gains. Timing matters as well: IMU, wheel feedback and CoM data must have comparable timestamps. Reading the current fall branch reveals a controller reset without an explicit zero command in that branch; the actual stop behavior therefore needs to be traced through the driver.

The source explains the control structure, but personal authorship, the exact deployed version and measured performance require project records. The new geometry, balance and CoM scripts are separate teaching experiments; they are not evidence of historical robot performance.

中文主线：模型输入输出/假设→一个实际函数链→一个已能解释的限制→怎样量化→个人贡献。不要将教材里的“会做”变成历史“做过”。

## 在口述中插入自己的贡献

确认职责后用：“My responsibility was [specific module]. I chose [method] because [reason]. I checked it using [actual data and metric]. The main limitation was [observed limitation].”

方括号必须用本人事实替换。没有记录则说：“I can explain the design, but I do not have a verified measurement for that performance claim.”
