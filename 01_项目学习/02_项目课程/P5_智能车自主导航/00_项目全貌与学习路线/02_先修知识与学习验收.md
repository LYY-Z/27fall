# P5 先修知识与学习验收

## 先建立一次导航的整体画面

先读[导航一趟路是怎样走出来的](03_P5导航一趟路是怎样走出来的.md)。导航不是“规划器一次输出一条线”，而是定位、全局规划、局部避障/轨迹生成、车辆控制、底盘执行和反馈持续协作。

读每一章时先问：它接收什么输入、输出什么对象、下一个模块如何使用？再核对算法在当前仓库是否被 launch/config 加载。Hybrid A*、TEB、DWA、MPC 的教学推导与当前本地配置中可确认的 Navfn/RPP 路径要分开。

## 按主题准备基础

| 主题 | 需要知道的量 | 先建立的直觉 |
|---|---|---|
| 车辆运动学 | 位置 \(x,y\)、航向 \(\psi\)、速度 \(v\)、转角 \(\delta\)、轴距 \(L\) | 汽车不能横着瞬移；转角和速度决定它能沿什么曲线走 |
| 轮速与里程计 | 轮半径、轮距、RPM、时间间隔 | 轮子转数能估计走过的距离，但打滑和半径误差会积累 |
| 坐标与 TF | map、odom、base_link、传感器坐标，时间戳 | 同一个点在不同坐标系数值不同；变换也必须对应同一时刻 |
| EKF | 状态、预测、观测、协方差 \(P\)、噪声 \(Q,R\) | 先用运动模型预测，再用传感器观测修正，并根据不确定度决定信谁多一些 |
| BFS/Dijkstra/A* | 网格、邻居、代价、父节点、启发式 | 搜索维护“从哪里来”和“当前总代价”；到终点后沿父节点回溯 |
| Hybrid A* | 连续姿态 \(x,y,\psi\)、运动基元、碰撞检测 | 节点不只是一格；每个扩展动作必须符合车辆转弯能力，并检查整车轮廓 |
| TEB/DWA | 局部障碍、速度窗口、时间间隔、轨迹代价 | TEB 优化带时间的局部轨迹；DWA 在短时可达速度中采样并打分 |
| MPC | 状态 \(s\)、输入 \(u\)、预测模型、地平线、代价和约束 | 优化器会从连续可行输入范围里求数值；不是人先列出固定十组输入让它任选 |

通用入口：[基础课程总览](../../../01_通用基础/00_基础课程总览.md)。开始前不必精通所有矩阵计算，但要知道每个矩阵代表哪种物理关系，以及维度如何对上。

## 建议的学习顺序

1. 从车体和轮子开始：转角怎样决定曲率、车辆一小步怎样更新 \(x,y,\psi\)。
2. 看反馈如何形成定位：轮速/IMU输入、坐标系与时间戳、EKF 预测和更新。
3. 先用网格例子完整走 BFS、Dijkstra、A*，记录队列/优先队列、父节点、代价和最终回溯路径。
4. 再学 Hybrid A*：节点如何离散、方向盘/前进后退等动作如何扩展、怎样碰撞检测、怎样把终点接回搜索树。
5. 学全局路线之后的局部层：TEB 与 DWA 分别输出什么、障碍怎样影响路径/速度、航向点由什么约束决定。
6. 最后学 MPC：定义预测状态和输入、给出动力学与输入边界、优化整段输入序列、只执行首个动作、下一周期重算。
7. 每个算法都标一行“当前仓库证据”：配置、插件或调用点在哪里；缺证据时写“原理/材料讨论”，不要说当前运行于机器人。

## MPC 的纸笔自检

设 \(N=3\)，状态 \(s_0\) 是当前测量值，优化器选择 \(u_0,u_1,u_2\) 三个输入。运动模型逐步产生 \(s_1,s_2,s_3\)，所以有三个动作、四个状态：首个状态已经在优化前给定。输入例如加速度和转向角速度/前轮转角，但具体选哪种由车辆模型决定；可行范围由执行器能力和安全限制给出。求解后只执行 \(u_0\)，拿新传感器状态作为下一次的 \(s_0\)。

这也解释“优化器自己选”是什么意思：人提供模型、当前状态、目标、代价权重与约束；算法计算出满足这些条件、代价较小的输入数字。权重 \(Q,R,Q_f\) 需要根据单位归一化、仿真/实验和安全限制调节，不是普适固定常数。

## 学完每章后的验收

1. **讲车辆**：说明轮子、车身和转向几何之间的关系，所有正负号对应明确坐标约定。
2. **讲估计**：写清传感器输入、预测状态、观测修正和不确定度；区分连续真实运动与离散采样数据。
3. **讲路径**：能在图上标出搜索扩展顺序、总代价、父节点和回溯结果；Hybrid A* 还要画运动基元和车体碰撞范围。
4. **讲控制**：指出局部规划器输出的是路线、带时间轨迹还是速度命令；MPC 的输入/状态/约束/实际执行动作不混淆。
5. **讲失败**：传感器时间不一致、定位漂移、无可行路径、碰撞约束漏检、MPC 无可行解或底盘响应不匹配时，说明系统如何发现。
6. **核证据**：当前配置/源码路径、教学算例、仿真和真实车测试分开叙述，并注明使用的版本。

详细复习入口：[历次问题归纳与完整推导](../05_中英文面试/05_历次问题归纳与完整推导.md)。没有运行或硬件日志支持的结果，不写成已实测性能。

## 复习工具：把规划与执行放到同一条时间线上

选一个真实场景（起点、目标、障碍物和车辆尺寸），用下面的数据链逐段解释；每段都写出输入、输出、坐标系和失败条件：

```text
传感器/轮速/IMU → TF与定位估计(x,y,航向,不确定度)
   → 全局规划（地图上的可行路线）
   → 局部规划（当前障碍与车辆能力下的短期路径/轨迹）
   → 跟踪控制（转角/角速度、加速度/速度等输入）
   → 底盘与轮胎实际运动
   → 新传感器观测，下一周期重新估计和规划
```

规划输出不能越过控制器和底盘自动变成真实运动。复习时明确回答：输出是几何路径、带时间轨迹、速度命令，还是优化器的输入序列？

### P5 易混概念对照

| 容易混在一起 | 应该怎样区分 |
|---|---|
| map、odom、base_link | 同一点在不同坐标系有不同数值；TF必须带对时间，不能把不同时间的变换硬拼。 |
| 路径与轨迹 | 路径描述几何路线；轨迹通常还带时间/速度信息；控制器最后仍需形成车辆可执行命令。 |
| BFS/Dijkstra/A* | BFS按步数扩展；Dijkstra按累计代价；A*在累计代价上加启发式估计。父节点用于终点回溯，不是猜路线。 |
| Hybrid A* | 网格/桶管理搜索，但状态包含连续位姿且扩展动作按车辆模型走弧线；离散桶不意味着车辆瞬移。 |
| TEB、DWA、MPC | TEB优化带时间的局部轨迹；DWA在短时可达速度中采样打分；MPC显式预测并优化控制输入序列。是否同用取决于系统设计，不是固定套餐。 |
| MPC输入与优化器 | 人给状态模型、目标/参考、输入边界、代价权重和初值/约束；求解器算输入数值。输入“变量”是待求数，不需要预先列出唯一动作答案。 |
| (N)动作与(N+1)状态 | 起始状态 (s_0) 已知；每个动作推进一次，故 (N) 个动作产生 (s_1...s_N)，连同 (s_0) 共 (N+1) 个状态。 |
| 仿真/规划示例与仓库运行 | 教学中讲过Hybrid A*/TEB/MPC不代表当前项目配置启动了它们；当前仓库配置与源码调用才是运行证据。 |

### 自测题与检查要点

1. 用一个小网格从起点扩展到终点，并解释终点如何沿父节点倒推。检查点：每次首次/更优到达如何记录parent，终点只在被取出或满足停止条件时结束。
2. Hybrid A*某个节点怎样扩展？检查点：选择前进/倒车及若干转角基元，按车辆曲率积分出新位姿，检查碰撞，再映射入离散桶并更新代价/父节点。
3. TEB为何需要时间间隔？检查点：同一几何点串可对应不同速度；时间间隔影响速度/加速度约束和轨迹代价。
4. MPC优化器“选动作”究竟选什么？检查点：连续变量序列 (u_0...u_{N-1})；说出输入定义、可行上下界、模型、代价和滚动执行首项。
5. Q、R、终点代价分别表达什么？检查点：状态误差、动作大小/变化代价、终端状态偏好；数值依赖单位归一化与验证，不存在通用标准值。
6. 无可行路径或MPC无可行解时，系统应如何处理？检查点：明确检测结果、停止/降级策略、重规划或安全命令，并记录原因；不能假定优化器总有解。
7. 当前仓库究竟运行哪套规划/控制？检查点：从launch/config/plugin和调用链给证据，再把课程示例单独标出。

### 复习阶梯

先画小地图并保存每次扩展与parent；再画车辆一小段弧线；接着对同一场景写出全局路径、局部输出和控制输入；最后用日志/配置确认实际系统配置。当天闭卷解释一次A*或MPC，次日重画失败案例，一周后手算一次状态预测和代价。
