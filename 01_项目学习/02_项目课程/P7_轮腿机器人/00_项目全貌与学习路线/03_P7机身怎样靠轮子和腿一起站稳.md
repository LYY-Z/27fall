# P7 白话总览：轮子怎么走，腿怎么撑，身体怎么不倒

## 1. 先想象真实机器人

机器人底下有轮子，轮子和地面接触；两侧有由多根杆组成的腿；身体和电池等较重部件在上方。轮子负责让机器人沿地面移动，腿机构改变身体高度和支撑形状。

侧面可以简化成：

          身体和质心
              ●
              │  身体倾角
          五连杆腿
              │
             轮轴 ○  → 轮子沿地面滚动

腿不是一根能伸缩的杆，而是多根固定长度的杆围成闭链。电机改变主动杆角度，整个闭链重新摆出形状，轮轴和身体之间的距离随之改变。

## 2. 为什么轮子要追着身体走

身体质心在轮轴上方，像倒着放的摆。若身体向前倾，重力会让它更往前倒。轮子往前滚到身体下面，支撑点就跟着移动，才能继续托住身体。

控制器不能只问“轮子应该转多快”，还要看身体歪了多少、正在歪多快、车体偏离目标多远。这是平衡反馈的直觉。

## 3. 课程分别教什么

- 第五课先算腿的几何：主动关节角决定两根主动杆端点，被动杆把输出点约束在圆交点。
- 第六课用 PID 示范姿态/速度反馈和变腿高控制。
- 第八课暂时把复杂腿机构简化成轮驱动倒立摆，从动能、势能和拉格朗日方程推到四状态 LQR。
- 第九课展示轮反馈参数与腿高相关的处理方式。
- 第十、十一课讲腿端虚拟力如何通过几何雅可比变成腿关节 torque 命令。

这些课程相互衔接，但目录分开，是不同的教学代码版本；不能说所有函数都同时在一个控制器里运行。

## 4. LQR 和轮反馈怎么对应

第八课教学模型状态是 \([\theta,\dot\theta,x,\dot x]\)：身体俯仰角、俯仰角速度、轮轴位置、轮轴速度；输入是一个等效驱动力矩。LQR 在设计阶段利用模型和 Q/R 计算反馈增益。

后续代码里左右轮目标是电机接口命令，按各侧状态和腿高相关系数计算。它不是直接把第八课的模型 tau 原样发到电机。轮命令的精确单位还要看轮电机库。

## 5. VMC 和腿部做什么

腿部控制先看轮轴/腿端离目标高度、目标前后位置差多少，结合腿端运动速度形成虚拟力。再按当前五连杆形状，把虚拟力换成两个主动关节的力矩命令。

可以记成：

腿端目标误差 → 腿端虚拟力 → 几何力矩映射 → 两个腿关节 torque 字段

“虚拟”表示力是控制器计算出来的目标，不是腿里装了弹簧。VMC 输出到腿关节，轮反馈输出到轮电机；二者功能不同。

## 6. 一条完整的因果链

IMU 给身体方向/转动信息；电机反馈给轮和关节状态；关节角通过五连杆模型得到腿几何；控制器比较目标与当前状态，算轮目标和腿虚拟力；腿力映射成关节 torque；命令经过通信发送，运动后的新传感器信息再进入下一轮。

阅读代码时要注意：并行 IMU 任务和主 loop 不保证在一个完全同步的瞬间；第十一课 VMC 新算出的 torque 通常到下一次 CAN_Control 才装入发送结构；静态轮电机库没有公开实现，因此目标单位需要额外核对。

## 7. 这份课程材料能证明什么

它能支持对机构几何、倒立摆模型、LQR 设计步骤、轮控制代码、VMC 力矩映射和 ESP32 CAN 调用的源码分析。它不能单独证明实机达到某频率、某种稳定性或个人完成某项工作。那些结论需要同版本硬件日志和个人贡献证据。
