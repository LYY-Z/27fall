# 麦轮运动学与轮速反馈

## 学习目标与入口

本章解决：四个轮子怎样同时实现前后、横向和转动。

相关项目：P3。先修：[基础课程总览](../../../01_通用基础/00_基础课程总览.md)。建议先读本项目全貌，再按章节编号阅读。代码入口：[教学实验与完整命令](../../../03_代码实验/02_项目实验/P3/README.md)；代码未运行核对，输出预期不能当实测。

## 0. 先用白话定位本页

麦轮的滚子允许一个方向容易滚动、另一个方向能推地，所以每只轮子都会同时受前进、横移和转弯影响。一个轮子不是“只管一个方向”。先固定车头、轮序、轮子正方向，再看每行方程如何把车体的三个运动要求合成该轮速度；之后沿反馈看电机是否跟上。

读的时候依次做三件事：说出实际物体和目标，标明每个输入/输出的含义与单位，再沿代码确认这一步真实被谁调用。教学示例帮助你理解因果关系，只有源码、日志或实验记录支持的内容才能说成项目事实。

<a id="mecanum-teaching"></a>
## 教学约定：先固定车体轴与轮序

每轮只在驱动方向约束接触速度，滚轮允许另一分量滚动。四轮目标是三自由度body速度的线性组合，不是每轮只管一个轴。

教学X型、轮序FL/FR/RL/RR、body+x前+y左：
\[
\omega_w=\frac1r
\begin{bmatrix}1&-1&-d\\1&1&d\\1&1&-d\\1&-1&d\end{bmatrix}
[v_x,v_y,\omega]^T,\quad d=a+b.
\]
位置半长a/半宽b单位m，r轮半径；旋转项dω单位m/s。


教学数值取 r=0.1 m、d=0.4 m：纯前进 [1,0,0] 得 [10,10,10,10] rad/s；纯横移 [0,1,0] 得 [-10,10,10,-10]；纯旋转 [0,0,1] 得 [-4,4,-4,4]；组合 [1,0.5,1] 得 [1,19,11,9] rad/s。该组轮号与源代码不同。

## 从通用几何到当前源码接口

前面的矩阵是一个便于学习的 X 型麦轮约定：输入 `vx, vy` 是 m/s，车体转速是 rad/s，输出轮角速度也是 rad/s。真实源码不是直接照抄那个矩阵：它用 `vx, vy, vw`、电机安装符号、轮序和 RPM 换算常数。这里从“车身想怎样动”一步步读到“电机想转多快”。

<a id="mecanum-geometry"></a>
### 1. 从刚体接触点速度到每轮滚动约束

把机器人底盘中心想成一个点。车体平移时，四个轮子都随车身一起前后/左右移动；车体旋转时，每个轮子又绕旋转中心画圆。轮子所在点的速度可以写成：

\[
\mathbf v_{wheel,i}=\mathbf v_{center}+\boldsymbol\omega\times\mathbf r_i
\]

这里 \(\mathbf r_i\) 是从车体参考中心到第 \(i\) 个轮子的距离。叉乘项只是在说“车身转动会给偏离中心的轮子额外的切向速度”。再根据麦轮滚子方向和电机正方向，把轮子处的速度投到该轮能驱动的方向上，就得到每只轮子的线速度；再除以轮周长，换成轮转速；最后乘减速比换成电机 RPM。

所以一条可读的链是：

```text
车体前后/左右平移 + 车体绕中心转动
        ↓
每个角上的轮子得到不同的接触点速度
        ↓ 按滚子方向与电机正方向组合
每个轮子的目标线速度
        ↓ 除以轮周长、乘传动比并换成每分钟转数
每个电机的目标 RPM
```

若平面旋转 \(\boldsymbol\omega=[0,0,\omega]\)、轮位置 \(\mathbf r=[r_x,r_y,0]\)，则 \(\boldsymbol\omega\times\mathbf r=[-\omega r_y,\omega r_x,0]\)，轮位置速度就是 \([v_x-\omega r_y,v_y+\omega r_x]\)。教学FL位于(a,b)，其滚动约束可写 \(r\omega_{FL}=v_{ix}-v_{iy}\)，代入得到 \(r\omega_{FL}=v_x-v_y-(a+b)\omega\)；其他三轮按滚子倾斜方向选加号/减号，形成前面的四行矩阵。

这里 `(1,-1)` 是便于写无滑动约束的系数向量，并非已经归一化的单位方向。若用单位方向 `(1,-1)/sqrt(2)` 真做投影，轮驱动速度的投影也带同一个sqrt(2)，两侧相消才得到上述公式；不能只把车体一边除sqrt(2)而轮速一边不处理。滚子自由转动意味着沿自由方向的约束弱，不是轮子只在车体某一轴工作。

<a id="mecanum-source"></a>
### 2. 本源码自己的四轮公式

`Wheat_Wheel_Solving.c` 中数组次序是 **RF、LF、RB、LB**，即右前、左前、右后、左后。代码逐行写的是：

\[
\begin{aligned}
RPM_{RF}&=(v_y-v_x+\rho_f v_w)C\\
RPM_{LF}&=(v_y+v_x+\rho_f v_w)C\\
RPM_{RB}&=(-v_y-v_x+\rho_b v_w)C\\
RPM_{LB}&=(-v_y+v_x+\rho_b v_w)C
\end{aligned}
\]

其中：

- \(v_x,v_y\) 是源码底盘平移参考；这套参数把最大平移速度按 m/s 定义。
- \(v_w\) 是转向参考；它必须和 \(\rho v_w\) 的单位匹配，才能与 m/s 的平移项相加。
- \(\rho_f,\rho_b\) 是旋转中心到前后轮的有效力臂，源码由轴距、轮距和云台偏置计算。
- \(C=\texttt{wheel\_rpm\_ratio}=60/(\text{轮周长}\times\text{M3508\_DECELE\_RATIO})\)，把轮子线速度换成电机每分钟转数。

写成矩阵就是：

\[
\begin{bmatrix}RPM_{RF}\\RPM_{LF}\\RPM_{RB}\\RPM_{LB}\end{bmatrix}
=C
\begin{bmatrix}
-1&1&\rho_f\\
1&1&\rho_f\\
-1&-1&\rho_b\\
1&-1&\rho_b
\end{bmatrix}
\begin{bmatrix}v_x\\v_y\\v_w\end{bmatrix}
\]

这张矩阵每行是一只电机，每列是一个车体运动分量。负号不是“轮子错误”，而是把车体方向、电机接线/安装方向和源码轮号一起编码进了公式。若换轮序、翻电机、改 X/O 滚子布局或换坐标正方向，符号就需要重新核对。

<a id="motor-rpm"></a>
### 3. 用源码配置做一个纯前进例子

源码给出的轮周长是 \(0.478\) m，减速比常量是 \(1/19\)。因此：

\[
C=\frac{60}{0.478\times(1/19)}\approx2384.94\quad
\frac{\text{motor RPM}}{\text{m/s}}
\]

只令 \(v_x=1\text{ m/s}\)，并令 \(v_y=v_w=0\)：

\[
[RPM_{RF},RPM_{LF},RPM_{RB},RPM_{LB}]
\approx[-2384.94,2384.94,-2384.94,2384.94]
\]

代码把结果先放进 `int16_t wheel_rpm[4]`，小数会被截去，再查最大绝对值是否超过 `M3508_MAX_RPM=8000`。因此数组里的整数约为 \([-2384,2384,-2384,2384]\)。这说明 `rpm_set` 是**电机目标 RPM**，不是车体 m/s，也不是轮子的 rad/s。

反过来看纯横移，只保留 \(v_y\)，源码的前后轮正负组合不同；只保留旋转，只保留 \(v_w\) 项。先把三个分量一次只开一个，就能用低风险方式核对轮号和符号，之后再看组合运动。

### 4. 力臂和角速度单位需要特别核对

源码参数：轴距 \(0.47\) m、轮距 \(0.412\) m、`GIMBAL_OFFSET=0`，所以：

\[
\rho_f=\rho_b=(0.47+0.412)/2=0.441\text{ m}
\]

如果 \(v_w\) 用 rad/s，那么 \(\rho v_w\) 是 m/s，量纲上成立。但源码 `CHASSIS_WZ_SET_SPEED` 有值 180，而最大旋转速度又按 3.0 配置；同时宏注释中留下过 `/ RADIAN_COEF` 的痕迹。阅读时不能只看变量名就断言 180 是 rad/s：应追查这个分支的角速度单位、是否应该有度转弧度换算，以及执行时 wheel RPM 是否被 8000 限幅。单位或换算不一致会让旋转项远大于平移项。

<a id="wheel-can-order"></a>
### 5. 统一限速、功率缩放、轮 PID 与 CAN 重排

源码的执行顺序是：

1. 按四轮公式算出四个 `int16_t wheel_rpm`；
2. 取四个数绝对值中的最大值；
3. 若最大值超过 8000，把四个整数目标乘同一比例 `8000/max`；
4. 按 RF/LF/RB/LB 写入四个 `rpm_set`；
5. 底盘主循环调用功率限制，对 `rpm_set` 再乘功率系数；
6. 每个轮子分别用速度 PID 比较 `rpm_set` 与 CAN 反馈 RPM，输出 `give_current`；
7. CAN 打包时又按驱动接口的参数次序发送。主循环传参顺序是 RF、LF、LB、RB，和轮速解算数组的后两项顺序不同，追接口时要确认这个重排是否与电机 ID 对应。

统一乘比例能保住四轮目标的相对比例；它不保证原来的速度大小，也不保证轮胎不打滑。源码还在整数转换后才做 8000 上限判断，因此非常大的非预期浮点目标应在转换前先检查范围，避免先转换时超出 `int16_t` 表示范围。

教学目标 `[100,200,-100,-200]`、轮速上限150，同乘0.75得 `[75,150,-75,-150]`；各轮单独夹到±150则得 `[100,150,-100,-150]`，比值变了，原平移/旋转组合可能随之改变。若后续速度PID某一路饱和，实际轮速仍未必按目标同比例变化，所以“命令保方向”与“地面轨迹保持”是两层证据。

### 6. 轮速闭环不是“矩阵直接控制电机”

麦轮矩阵只回答：**车体运动要求对应每只电机多大的目标转速**。它不直接产生电机力矩。接下来每只 M3508 独立执行速度 PID：

\[
e_i=RPM_{set,i}-RPM_{meas,i},\qquad
give\_current_i=PID_i(e_i)
\]

电机驱动器接收的是 `give_current` 协议整数；其物理电流、转矩还受驱动协议标度、减速器、供电和限幅影响。当前底盘 PID 配置为 \(K_p=5,K_i=0,K_d=0\)，输出最大值 20000；PID 函数没有显式用 \(dt\) 缩放积分/微分，不能把这些增益当成与任务周期无关的连续参数。

`Chassis_Wheel_Loop_Cal` 调用了 `ramp_calc`，但紧接着 PID 使用的仍是 `rpm_set`，不是 ramp 计算返回值或 ramp 状态。因此仅凭出现 `ramp_calc`，不能断言轮速目标已被斜坡平滑。

### 7. 反解四轮反馈时，为什么用最小二乘？

四只轮速里有四个测量数，但理想平面车体只有 \(v_x,v_y,v_w\) 三个未知量。矩阵是 \(4\times3\)，一般不能对它做普通方阵逆。可用伪逆从四轮反馈估计最符合整体运动的三维车体速度：

\[
\hat{\mathbf v}_{body}=A^+\mathbf{RPM}_{wheel}
\]

若一只轮打滑、编码器噪声或四轮数据不同步，四个数可能无法同时满足同一刚体运动方程，最小二乘给的是“整体最接近”的解，不会自动识别哪只轮坏了。打滑检测需要看各轮残差、IMU/外部定位以及时间戳，不能只看伪逆结果。

> **源码事实与通用教材的边界：**附件中的 FL/FR/RL/RR 矩阵可以用来学投影，但不能直接替换本项目的 RF/LF/RB/LB 方程。项目面试先说清本源码行序、符号、输入单位和目标 RPM，再讲通用麦轮原理。
