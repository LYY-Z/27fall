# 06 一个接口能否复用：单位、故障、恢复与性能

本章把P6与前面控制项目连接起来。相同函数签名只是调用形式；是否可靠复用，要核对值的物理含义和失败行为。参考[完整源码周期](../02_源码阅读与运行/02_一个周期的调用与数据流.md)。

## 1. 一个速度数值为什么不能直接发给所有硬件

教学上层请求0.3m/s。某轮式设备接收轮角速度，半径0.06m：

\[
\omega=v/r=0.3/0.06=5\ \mathrm{rad/s}.
\]

若另一个驱动接收RPM，还要转换：

\[
\mathrm{RPM}=\omega\frac{60}{2\pi}\approx47.75.
\]

若反馈位于减速器前，轮轴速度还要按减速比转换。这个例子解释接口设计，不是当前地锁组件的真实运动接口。地锁up/down又是离散操作，不能拿上面的速度数字调用。

上层统一单位、方向和参考系后，适配器才能做明确转换。否则同一个value=1，可能分别意味着1rad/s、1RPM、一次开关或某个协议整数。

## 2. 复用需要一份可说明的设备合同

| 合同项 | 应写清的内容 |
|---|---|
| 能力 | 支持读取什么、执行什么；不支持时如何返回 |
| 输入 | 单位、范围、方向、模式、目标是绝对还是相对 |
| 反馈 | 测量来源、序号、时间、有效性、精度 |
| 成功 | 表示接受、发送、ACK还是到位 |
| 停止 | 零速、保持、断使能或制动；响应时间 |
| 故障/恢复 | 超时、重连、旧命令、旧缓存与人工覆盖 |

验证复用时，比较上层剩余的硬件特定分支，和多适配器是否满足同一语义。共享一个execute函数名，不足以证明同一控制算法可以无修改跨设备使用。

## 3. 本地SmartFarm连接管理提供什么学习例子

EnsureConnectionForKey从通道表取得或建立Snap7适配器和连接级mutex。连接级锁使同一连接的操作协调；全局表锁用于管理表本身，不能长期持它进行慢I/O，否则其他设备也会被拖慢。

StartConnectionMonitor用标志限制重复启动；停止监测需要停止条件、通知和join。重连成功说明连接重新建立，未必说明缓存已经更新或某个旧动作完成。

外部SDK、系统服务和GN依赖必须匹配。普通标准库教学代码能够解释接口，不代表原OpenHarmony整平台已在桌面环境构建成功。

## 4. “设备不动”按阶段排查

```text
请求是否创建且参数合法？
  ↓
设备ID/能力/命令是否匹配？
  ↓
任务是否开始，是否在等锁？
  ↓
协议地址、值和通道是否正确？
  ↓
设备是否回ACK，有无异常码？
  ↓
有无独立状态改变/到位证据？
```

这条顺序能区分业务拒绝、排队积压、适配错误、通信错误与机械故障。某一层日志写success，不能省略后面层的检查。

**当前地锁的特别问题：**Reading失败时ReadLockStatus可输出旧缓存；ListeningTask当前又没有在该错误分支return，因此最终上报成功可能掩盖读取失败。排查必须保留read_ret、report_ret和poll_ret三层，而非只看online。详见[协议与状态同步](04_协议适配发现注册与状态同步.md)。

## 5. 重连后为什么不能重发全部积压

假设断线前排了10条move请求，设备重连时这些请求已过时。依次重放可能让设备执行早已不需要的动作。

恢复应先确认身份、模式和最新反馈；再判断每项请求是否过期、是否仍有意义、是否允许重试，以及以前是否可能执行过。对不能确认的结果，保留UNKNOWN并用查询或安全处理，不把重连事件直接当任务完成。

恢复策略是工程设计建议，必须与当前已实现路径分开。对可见源码，只按实际重连、缓存和返回码流程说明。

## 6. 端到端效率怎样算

教学把顺序阶段定义为：等待可用反馈100ms，解析5ms，排队40ms，协议写30ms，独立读回20ms。若这些阶段依次发生且不重叠，总195ms。100ms截止期就不满足，即使协议写只要30ms。

如果某些阶段并行，不能把所有耗时盲目相加；应记录同一请求开始和最终完成时间。平均延迟也可能掩盖偶发长等待，所以要看分位数、最大观测值、超期次数，以及观测窗口。

控制频率高，不代表反馈频率高；命令吞吐高，也不代表机械动作响应快。P6的线程池调度、P3的RTOS任务和P1/P2的控制定时器，属于不同执行环境，不能套用同一个周期保证。

## 7. 一份能定位原因的记录

| 字段 | 为什么需要 |
|---|---|
| deviceId、operation、actionId | 把同一动作在不同层的记录串起来 |
| submit/start/end | 分开排队与工作耗时 |
| source_time、receive_time、last_success_read | 区分新采样、延迟和旧缓存 |
| input_unit、wire_value、adapter | 发现单位、协议或设备选择错误 |
| read_ret、write_ret、report_ret、final_ret | 保留不同阶段的错误 |
| command_stage、desired/reported | 避免把目标状态当设备状态 |
| queue_depth、dropped_poll_count | 判断任务积压或轮询被跳过 |

这些是建议日志字段，不代表原源码已记录全部。用已存在日志可以确认到哪一步，就只报告到哪一步。
